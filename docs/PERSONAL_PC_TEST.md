# 개인 PC 제한 시험 안내서 — ChanceBlog Desktop 0.1.0-preview.1

**개인 PC 제한 시험용, 미서명 Package — 공개 배포용이 아닙니다**

**이 시험지는 어느 Package 용인가요?** 초안 저장·백업·복원 화면이 **들어 있는 정식 시험용 Package** 용입니다(저장·백업·복원이 아직 없는 시험 빌드는 개인 PC 로 보내지 않습니다). 받은 압축 파일의 이름에 `TESTBUILD` 가 들어 있거나 `PACKAGE_INFO.md` 맨 위에 '이 빌드는 시험 빌드' 라고 적혀 있거나 화면 `정보` 에 '시험 빌드' 안내가 보이면 **이 시험지로 시험하지 말고** 그 사실만 알려 주세요. 정식 시험용 Package 에서는 저장·백업·복원이 **모두 있어야** 하므로 그 단계에서 **'해당 없음'을 쓸 수 없습니다** — 못 찾았으면 '실패(기능 없음)'으로 적습니다. 화면 글자가 이 문서와 다르면 문서가 낡은 것일 수 있으니 같은 뜻의 단추를 고르고 다른 점을 적어 주세요.

이 문서는 운영자(비개발자)가 **개인 PC 에서 직접** 해 보는 시험 순서입니다. 회사 PC 에서는 하지 않습니다(회사 PC 는 관리자 권한이라 '일반 사용자' 시험이 되지 않습니다). 모두 하면 한 시간쯤 걸립니다.
결정 근거는 운영자 2026-11-11 결정 7항(개인 PC 필수 시험)·8항(Package 정보)·9항(Package Gate)이고, 개발자용 설명은 [`PACKAGE.md`](PACKAGE.md) 에 있습니다.

- 각 칸의 **`[ ]`** 는 체크 칸입니다. 하고 나서 `[x]` 로 바꿔 적어 두세요(7단계의 표에 옮겨 적습니다).
- **"이렇게 보이면 통과"** 문장과 다르면 **실패**입니다. 멈추지 말고 그때 화면에 무엇이 보였는지만 적고 다음 칸으로 가세요(아래 '멈추고 바로 알릴 일' 은 예외).

- '해당 없음'은 `(선택)` 이라고 적힌 칸을 하지 않았을 때만 씁니다.
- 시험하다 설정을 바꾸거나 무언가를 설치하라는 창이 뜨면 **누르지 말고** 창 이름을 적으세요.

**멈추고 바로 알릴 일**: ① 앱을 열거나 쓰는 중에 관리자 권한(UAC — 암호를 넣거나 예/아니요를 고르라는 창)을 묻는 창이 뜸(6단계에서 시험용 계정을 만들 때와 8단계에서 지울 때 Windows 설정이 관리자 암호를 묻는 것은 해당하지 않습니다 — 6단계 준비를 보세요) ② 앱이 키·비밀번호·계정을 달라고 함 ③ 앱이 브라우저를 열었는데 네이버 글쓰기 주소가 아닌 곳임 ④ 화면에 키처럼 보이는 긴 글자가 그대로 보임.

## 0단계. 준비 — 압축 파일이 온전한지

받을 것: **압축 파일** `ChanceBlogDesktop-0.1.0-preview.1-win64.zip` 과 같은 곳에 있는 **`SHA256SUMS`**, **`PACKAGE_INFO.md`** 세 파일(받는 곳은 AI 가 알려 드린 곳입니다). 세 파일을 한 폴더에 둡니다. **압축 파일 이름에 `TESTBUILD` 가 들어 있으면 시험 빌드이니 여기서 멈추고 알려 주세요.**

압축 파일은 GitHub 가 **수동 빌드**로 만들어 `Artifacts` 로 올려 둡니다. GitHub 에 로그인한 브라우저에서 하세요. 화면 글자는 GitHub 가 바꿀 수 있으니 같은 뜻의 단추를 고르세요. 이 칸은 7단계 표에 줄이 없고, 받은 압축 파일의 이름만 7단계에서 함께 적습니다.

- [ ] 이 저장소의 `Actions` 탭 → 왼쪽 목록에서 `Package — 개인 PC 제한 시험용 빌드(수동)` 를 엽니다. 실행 목록은 위가 가장 새것입니다. 새로 만들어야 하면(받을 실행이 없거나 아래의 14일이 지났을 때) 오른쪽의 `Run workflow` → 초록색 `Run workflow` 를 한 번 누릅니다(`Branch: main` 그대로, 입력 칸은 없습니다). 끝날 때까지 기다립니다(제한 시간은 30분입니다).
- [ ] **초록 체크** 표시가 붙은 실행을 열어 맨 아래로 내리면 `Artifacts` 아래에 `ChanceBlogDesktop-preview` 가 있습니다. 눌러서 내려받습니다(파일 이름은 `ChanceBlogDesktop-preview.zip`).

### 0-1. 계정이 표준 사용자인지 확인

- [ ] Windows `설정` → `계정` → `내 정보` 에서 이름 아래에 **`관리자`** 라는 글자가 **없어야** 표준 사용자입니다. 있으면 관리자 계정이니 표준 사용자 계정을 하나 만들거나 다른 계정으로 로그인해서 이 단계부터 다시 합니다(계정을 만드는 일에는 관리자 암호가 필요합니다 — 6단계 준비의 안내와 같습니다).
- 다른 방법: 시작 버튼 → `cmd` → 열린 검은 창에 `net localgroup Administrators` 입력 → 나온 목록에 내 계정 이름이 **없으면** 표준 사용자입니다.
- **이렇게 보이면 통과**: 이 시험을 하는 계정이 표준 사용자(관리자 아님).

### 0-2. 악성코드 검사

- [ ] 압축 파일을 마우스 오른쪽 단추로 누르고 `Microsoft Defender로 검사`(또는 쓰는 보안 프로그램의 검사)를 고릅니다. `PACKAGE_INFO.md` 의 6번(Malware 검사 결과)에 '검사 안 함'이라고 적혀 있으면 그 빈칸을 여기서 채우는 것이고, 이미 '위협이 발견되지 않았어요'라고 적혀 있어도 개인 PC 에서 한 번 더 확인합니다.
- **이렇게 보이면 통과**: '위협이 없습니다'. 위협이 나오면 **압축을 풀지 말고** 이름만 적어 알려 주세요.

### 0-3. SHA-256 확인

- [ ] 압축 파일이 있는 폴더를 파일 탐색기로 엽니다. 주소 표시줄을 한 번 누르고 `powershell` 이라고 쓴 뒤 Enter 를 누르면 그 폴더에서 PowerShell 창이 열립니다(관리자 권한으로 열지 않습니다).
- [ ] 아래 한 줄을 붙여 넣고 Enter:

```text
Get-FileHash .\ChanceBlogDesktop-0.1.0-preview.1-win64.zip -Algorithm SHA256
```

- [ ] `SHA256SUMS` 를 메모장으로 열어 첫 줄 앞의 64글자와 위 결과의 `Hash` 칸을 비교합니다(영문 대문자·소문자 차이는 같은 값입니다).
- **이렇게 보이면 통과**: 64글자가 **한 글자도 다르지 않고** 같습니다. 다르면 압축 파일이 바뀌었거나 덜 받아진 것이니 풀지 말고 알려 주세요.

## 1단계. 표준 사용자 계정에서 압축 풀기·실행

### 1-1. 압축 풀기

- [ ] 내 계정 폴더(`C:\Users\내이름`) **바로 아래**에 `ChanceBlogTest` 라는 새 폴더를 만듭니다.
- [ ] 압축 파일을 마우스 오른쪽 단추로 → `모두 압축 풀기` → 위치를 위 `ChanceBlogTest` 로 정하고 `압축 풀기`.
- **하지 말 것**: `AppData` 폴더 안·`Program Files` 안·OneDrive 로 동기화되는 폴더(문서·바탕 화면이 그럴 수 있음)에는 풀지 않습니다. 이 앱의 데이터 폴더(`ChanceblogDesktop`)와 비슷한 이름의 폴더에도 풀지 않습니다. 폴더 경로가 길면(`C:\` 부터 100글자 넘게) 풀리다 멈출 수 있습니다.
- **이렇게 보이면 통과**: `ChanceBlogTest\ChanceBlogDesktop-0.1.0-preview.1` 안에 `ChanceBlogDesktop.exe`·`_internal`·`vendor`·`LICENSES` 폴더와 `VERSION`·`PACKAGE_INFO.md` 파일이 있습니다. 풀린 폴더 경로를 7단계 표에 적어 둡니다(**설치 폴더 위치**).

### 1-2. 실행 — 관리자 권한을 묻지 않아야 합니다

- [ ] `ChanceBlogDesktop.exe` 를 두 번 누릅니다.
- **창이 뜨면 이렇게 하세요**:
  - **파란색 'Windows의 PC 보호' 창**(SmartScreen)이 뜨면 `추가 정보` → `실행` 을 누릅니다. 이 서명 없는 Package 에서는 나올 수 있는 일입니다. **떴다는 사실을 7단계 표에 적습니다.**
  - **방패 그림과 함께 '이 앱이 디바이스를 변경하도록 허용하시겠어요?'(관리자 권한) 창**이 뜨면 **실패**입니다 — `아니요` 를 누르고 멈춰서 알려 주세요.
  - '스마트 앱 컨트롤이 앱을 차단했습니다' 라는 창이 뜨면 **이 PC 에서는 실행할 수 없는 것**입니다 — 설정을 바꾸지 말고 이 사실만 적어 알려 주세요(맨 아래 '막혔을 때' 참고).
- **이렇게 보이면 통과**: `ChanceBlog Desktop` 창이 열리고 왼쪽에 `홈`·`주제 후보`·`초안 작성`·`Seed 관리`·`블로그 관리`·`설정` 메뉴가 보입니다. **관리자 권한 요구 창은 한 번도 안 떴습니다.**

### 1-3. 버전·미서명 표시

- [ ] 왼쪽 메뉴의 `설정` → `연결 관리` 카드의 마지막 줄 `정보`(처음에는 접혀 있습니다 — 그 바로 아래에 `백업·복원` 카드가 이어집니다)를 눌러 펼칩니다.
- **이렇게 보이면 통과**: `버전  v0.1.0-preview.1 · 커밋 ` 다음에 7글자가 보이고, 그 아래에 **`개인 PC 제한 시험용, 미서명 Package`** 한 줄이 보입니다(그 줄 끝에 `시험 빌드 — 개인 PC 로 보내지 않는 빌드예요` 가 이어져 있으면 시험 빌드이니 멈추고 알려 주세요). (그 7글자는 `PACKAGE_INFO.md` 2번의 커밋 앞 7글자와 같아야 합니다.)

### 1-4. 이미 열려 있을 때 한 번 더 열어 보기 — 창이 하나만 떠야 합니다

앱을 **두 번 열어도 창이 하나만 뜨는 것이 맞습니다**(같은 데이터를 두 창이 동시에 고치지 않게 하려는 장치입니다). 1-2 에서 연 `ChanceBlog Desktop` 창을 **닫지 말고 그대로 둔 채** 해 보세요.

- [ ] 1-2 에서 연 것과 **같은** `ChanceBlogDesktop.exe` 를 한 번 더 두 번 누릅니다.
- [ ] 몇 초 기다리면서 `ChanceBlog Desktop` 창이 몇 개 떠 있는지 봅니다(작업 표시줄의 단추도 같이 봅니다).
- **이렇게 보이면 통과**: **새 창이 뜨지 않고**, 열려 있던 창이 앞으로 오거나(작업 표시줄 단추가 깜박일 수도 있습니다) `이미 열려 있거나 열리는 중이에요` 라는 안내 상자 **하나만** 뜹니다. 안내 상자는 `확인` 을 누르면 닫히고, 열려 있던 창을 그대로 계속 쓰면 됩니다.
- **실패**: `ChanceBlog Desktop` 창이 두 개 뜨면 실패입니다 — 새로 뜬 창은 건드리지 말고 닫은 뒤, 창이 두 개였다는 사실만 7단계 표의 1-4 줄에 적어 주세요.
- 첫 번째 창이 아직 뜨는 중에 두 번 눌렀다면 새 창 없이 잠시 뒤 첫 창이 앞으로 옵니다. 안내 상자가 계속 뜨는데 열려 있는 창이 보이지 않으면 작업 관리자(`Ctrl`+`Shift`+`Esc`)에서 `ChanceBlog Desktop` 을 찾아 끝낸 뒤 다시 열고, 그 사실을 1-4 줄에 적어 주세요.

## 2단계. 프로필·Seed·후보·초안 만들기 (시험용 값만)

- [ ] **블로그 등록**: 왼쪽 `블로그 관리` → 왼쪽(창이 좁으면 위쪽)에 늘어선 카드들 중 **`네이버 A`**(`블로그를 등록해 보세요`·`비어 있음`·`눌러서 이름과 블로그 ID 를 넣어요.` 라고 적힌 카드)를 누릅니다 → `네이버 A 등록` 입력 칸이 열립니다 → `표시 이름` 에 `시험 블로그 A`, `블로그 ID 또는 주소` 에 `testblog-a` (진짜 블로그가 아니어도 됩니다 — 공백 없이) → 아래쪽 `저장`.
  **통과**: '저장했어요.' 안내가 보이고 `네이버 A` 카드가 `등록됨` 으로 바뀌며 `시험 블로그 A` 이름이 보입니다.
- [ ] **Seed 등록**: 왼쪽 `Seed 관리` → `새 Seed 등록` → 칸을 채웁니다 — `Seed 낱말` 에 `시험용 키워드`, `대분류`·`중분류` 에 `시험`, `중요도` 는 `일반`, `대상 유형` 은 아무거나 하나(예: `제품`), `소속` 은 `네이버 A` → `승인 전으로 등록`. 이어서 목록에 생긴 Seed 를 눌러 열고 `승인하기` 를 누릅니다.
  **통과**: '승인했어요. 이제 후보 생성에 쓰여요.' 안내가 보입니다.
- [ ] **후보 만들기**: 왼쪽 `주제 후보` → `후보 만들기` → 확인 창에서 `만들기`.
  **통과**: 목록에 후보가 하나 이상 생깁니다. ('아직 후보를 만들 수 없어요' 가 나오면 그 이유 글을 적습니다 — 보통 Seed 가 승인 전이거나 `네이버 A` 가 등록되지 않은 경우입니다.)
- [ ] **초안 만들기**: 후보 하나를 눌러 오른쪽에 열리는 상세 창(창이 좁으면 오른쪽에서 밀려 나오는 서랍) **맨 아래에 붙어 있는** `이 주제로 만들기` 를 누릅니다.
  **통과**: `초안 작성` 화면에 제목과 본문이 생깁니다(AI 가 아니라 규칙으로 만든 글입니다).
- [ ] **글자 하나 고치기**: 제목 맨 끝에 `!` 한 글자를 더해 둡니다(다시 열었을 때 '고친 글'인지 알아보려고).
- [ ] **저장**: `저장` 단추(또는 Ctrl+S)를 누릅니다.
  **통과**: '저장됨'(또는 같은 뜻) 표시가 보입니다. **저장 단추가 화면에 없으면 '실패(기능 없음)'** 으로 적고 3단계의 초안 부분은 건너뜁니다(정식 시험용 Package 에는 저장이 있어야 합니다).
- (선택) **복사**: `제목 복사` 를 누른 뒤 메모장을 열어 붙여 넣기(Ctrl+V). **통과**: 방금 고친 제목이 그대로 붙습니다. 복사 전에 확인 창이 뜨면 읽고 `복사` 를 누릅니다.
- (선택) **네이버 글쓰기 열기**: `네이버 글쓰기 열기` 단추 → 브라우저에서 네이버 블로그 글쓰기 주소가 열립니다. **앱은 주소만 열고 로그인·입력·발행은 하지 않습니다.** 단추가 꺼져 있으면 이유 글을 적습니다.

## 3단계. 저장하고 껐다 켜기

- [ ] 앱 창을 닫습니다(오른쪽 위 X). '저장하지 않은 내용이 있어요' 창(단추 `저장`·`저장 안 하고 닫기`·`계속 고치기`)이 뜨면 **저장하지 않은 것**이 있다는 뜻입니다 — `계속 고치기` 를 누르고 저장한 뒤 다시 닫습니다(그 창의 `저장` 을 눌러도 저장하고 닫힙니다). 2단계에서 저장해 두었다면 이 창은 뜨지 않습니다.
- [ ] 같은 폴더의 `ChanceBlogDesktop.exe` 를 다시 엽니다.
- **이렇게 보이면 통과**:
  - [ ] `블로그 관리` 의 `네이버 A` 카드에 `시험 블로그 A` 가 `등록됨` 으로 그대로 있습니다.
  - [ ] `Seed 관리` 에 시험용 키워드가 그대로 있고 승인된 상태입니다.
  - [ ] `주제 후보` 에 후보가 그대로 있습니다.
  - [ ] 저장한 초안이 `저장한 초안` 목록(또는 `초안 작성` 화면의 같은 자리)에 있고, 열면 **제목 맨 끝의 `!` 까지 그대로**입니다.
- [ ] **데이터 폴더 위치 확인**: 키보드 `Windows` 키 + `R` → `%LOCALAPPDATA%` 입력 → Enter → 열린 폴더 안에 `ChanceblogDesktop` 폴더가 있습니다. 그 전체 경로를 7단계 표에 적습니다(**데이터 폴더 위치**). 안에 `chanceblog.db`·`topic_engine` 같은 이름이 보이면 정상입니다.

## 4단계. 백업과 복원

- [ ] 왼쪽 `설정` → 화면을 아래로 내려 `연결 관리` 카드 밑의 **`백업·복원` 카드**(맨 아래에는 `내 글 문체 참고값 보기` 카드가 따로 있고 `백업·복원` 은 그 바로 위입니다) → 카드 오른쪽 위의 `지금 백업`.
  **통과**: '백업을 만들었어요' 안내와 함께 목록에 새 줄이 생기고, 그 줄에 **`Credential 제외됨`**(키·토큰은 백업에 안 들어 있다는 뜻의 글)이 보입니다. 상태가 '완료'(일부만이거나 실패면 그 글을 적습니다).
- [ ] **일부러 한 글자 고치기**: `블로그 관리` 에서 `네이버 A` 카드를 눌러 `표시 이름` 을 `시험 블로그 A` 에서 `시험 블로그 AA` 로 한 글자 더하고 `저장`.
- [ ] 다시 `설정` → `백업·복원` → 방금 만든 백업 줄의 `복원` → 확인 창('이 백업으로 복원할까요?')에서 **무엇이 바뀌는지 읽고** `복원하기` 를 누릅니다.
  **통과**: '복원을 마쳤어요' 안내가 나오고(복원하기 직전 데이터를 '복원 직전 사본' 으로 남겨 뒀다는 글이 이어집니다), `블로그 관리` 의 이름이 **`시험 블로그 A`**(한 글자 없는 처음 모양)로 돌아와 있습니다. 필요하면 앱을 닫았다 다시 엽니다.
- [ ] 백업은 같은 PC 에 만들어지는 사본이라 PC 가 고장 나면 같이 사라집니다. 안내 글(USB 같은 곳에 직접 복사해 두라는 글)이 보이는지만 확인합니다.
- **백업·복원 기능이 화면에 없으면 '실패(기능 없음)'** 으로 적습니다(정식 시험용 Package 에는 있어야 합니다).

## 5단계. 키(Credential) 등록 — 가짜 글자로

- [ ] 왼쪽 `설정` → `AI 보조` 줄을 눌러 펼칩니다(처음에는 접혀 있습니다) → `AI 보조(선택)` 카드의 `키 등록` 단추. **설정 화면 위쪽에 이미 펼쳐져 있는 `NAVER API HUB 검색어 트렌드` 카드에도 `키 등록` 단추가 있습니다 — 그것이 아닙니다.** 꼭 `AI 보조(선택)` 카드의 것을 누릅니다.
- [ ] 열린 `키 등록` 창의 `별칭` 칸에 `시험`(키는 적지 않습니다), `API 키` 칸에는 **가짜 글자 `TEST-KEY-NOT-REAL`** 을 그대로 붙여 넣습니다(17글자 — 입력한 글은 점으로만 보입니다). '너무 짧습니다'가 나오면 `TEST-KEY-NOT-REAL-TEST-KEY-NOT-REAL` 로 길게 합니다. → `다음` → 확인 화면을 읽고(약관 확인 칸이 있으면 체크) `저장`.
- **이렇게 보이면 통과**:
  - [ ] 카드의 `저장된 키` 줄에 방금 넣은 별칭(`시험`)과 등록 상태·시각만 보입니다(`등록됨` 같은 글).
  - [ ] **키의 끝 글자·앞 글자·`****` 같은 일부 글자가 어디에도 보이지 않습니다**(`REAL` 이나 `TEST` 가 보이면 실패).
- [ ] (선택) Windows `자격 증명 관리자` → `Windows 자격 증명` → `일반 자격 증명` 에 `ChanceBlogDesktop:` 로 시작하는 줄이 하나 있습니다.
- **키는 아직 지우지 마세요.** 6단계에서 다른 계정이 이 키를 못 보는지 확인한 뒤 **6-4 에서** 지웁니다(키가 남아 있어야 6-2 의 확인이 의미가 있습니다).

## 6단계. 다른 일반 Windows 계정에서 — 첫 계정의 데이터·키에 못 닿는지

**준비**: 표준 사용자 계정이 **하나 더** 필요합니다(관리자 계정이면 안 됩니다 — 시험이 틀어집니다). 없으면 `설정` → `계정` → `다른 사용자` → `계정 추가` 로 만듭니다(시험용 로컬 계정, 시험이 끝나면 8단계에서 지웁니다). Windows 11 은 '계정 추가' 에서 마이크로소프트 계정 로그인을 권합니다 — 그때 `이 사람의 로그인 정보가 없습니다` → `Microsoft 계정이 없는 사용자 추가` 를 골라 이름·비밀번호만 넣는 **로컬 계정**으로 만드세요(새 계정은 기본이 표준 사용자입니다).

**계정을 만들거나 지우는 일에는 관리자 권한(암호)이 필요합니다**: 이 시험을 하는 계정은 표준 사용자(0-1)라서, 위의 `계정 추가` 와 8단계의 계정 제거를 하면 Windows 가 **관리자 계정의 이름과 암호**를 넣으라는 창을 띄웁니다. 그 창은 Windows 설정이 띄운 것이라 **앱 때문에 생긴 문제가 아닙니다**('멈추고 바로 알릴 일' ① 은 앱을 열거나 쓰는 중에 뜬 창만 가리킵니다). 개인 PC 의 관리자 계정(PC 를 처음 설정할 때 만든 계정 등)의 암호를 아는 사람이 직접 넣으세요 — **암호는 Windows 의 그 창에만** 넣고 이 시험지·보고·사진·AI 대화창 어디에도 적지 않습니다.

**관리자 암호를 모르거나 관리자 계정이 없으면**: 계정을 만들지 말고 6-1·6-2·6-3 을 모두 **`실패(권한 없음)`** 으로 적고 그 세 칸만 건너뜁니다(7단계 표에 그대로 적습니다 — 앱의 문제가 아니라 시험을 못 한 것을 알리는 표시입니다). 6-4 의 키 지우기는 첫 계정에서 그대로 합니다(가짜 키를 남겨 두지 않으려고).

**압축 파일 옮기기**: 첫 계정에서 압축 파일을 `C:\Users\Public\Documents`(모든 계정이 볼 수 있는 폴더)에 복사해 둡니다. 첫 계정 폴더에 풀어 둔 앱은 다른 계정이 열 수 없습니다.

**두 번째 계정으로 로그인한 뒤**(첫 계정은 로그아웃하거나 사용자 전환):

- [ ] **6-1. 첫 계정의 데이터 폴더 열기 시도**: 파일 탐색기 주소 표시줄에 `C:\Users\첫계정이름\AppData\Local\ChanceblogDesktop` 을 쓰고 Enter(첫계정이름 자리에 첫 계정의 폴더 이름).
  **이렇게 보이면 통과**: **'액세스 거부'**(또는 '이 폴더에 액세스할 권한이 없습니다')가 나오고 폴더 안이 **열리지 않습니다.**
  **`계속` 단추가 보여도 누르지 마세요** — 눌러서 권한을 주면 그 폴더의 접근 권한이 바뀌어 버립니다. 그냥 닫으세요. (폴더가 열려 버리면 **실패**이니 그 사실을 알려 주세요.)
- [ ] **6-2. 첫 계정의 키에 접근 못 하는지**: 시작 버튼 → `cmd` → 검은 창에 `cmdkey /list` 입력 → Enter. (첫 계정에는 5단계의 가짜 키가 아직 남아 있습니다.)
  **통과**: 목록의 `대상:` 줄 가운데 **`ChanceBlogDesktop:` 이 들어 있는 줄**(보통 `대상: LegacyGeneric:target=ChanceBlogDesktop:…` 꼴로 보입니다)이 **하나도 없습니다.**
- [ ] **6-3. 자기 계정의 빈 데이터로 시작하는지**: 두 번째 계정에서 `C:\Users\Public\Documents` 의 압축 파일을 **두 번째 계정의 폴더**(`C:\Users\둘째계정이름\ChanceBlogTest`)에 풀고 `ChanceBlogDesktop.exe` 를 실행합니다(1단계와 같은 방법, SmartScreen 창이 뜨면 같은 순서로).
  **통과**: 첫 계정에서 만든 `시험 블로그 A`·Seed·후보·초안·백업이 **하나도 보이지 않는** 빈 상태입니다. `설정` 의 키도 모두 키 없음입니다.
- [ ] 이 계정에서도 관리자 권한을 묻는 창은 안 떠야 합니다.
- [ ] **6-4. 첫 계정으로 돌아와 키 지우기**: 두 번째 계정의 앱을 닫고 첫 계정으로 로그인합니다(관리자 암호가 없어 6-1·6-2·6-3 을 건너뛰었다면 이미 첫 계정입니다) → 앱을 열어 `설정` → `AI 보조` → `AI 보조(선택)` 카드의 `삭제` → 확인.
  **통과**: `저장된 키` 줄이 처음처럼 `연결 안 됨 — 키 없이도 쓸 수 있어요`(미등록 상태)로 돌아오고, (선택) 자격 증명 관리자의 그 줄도 사라집니다.
