# 개인 PC 시험 안내서 — ChanceBlog Desktop 1.0 (초안)

**초안입니다 — 설치 도구·업데이트 방식·일부 화면 글자가 아직 정해지지 않아 〔확인 필요〕 라고 적은 곳은 그것이 정해진 뒤에 채웁니다.** 공개 배포 전에 운영자가 개인 PC 에서 직접 해 보는 순서의 **뼈대**이고, 지금의 시험지 [`PERSONAL_PC_TEST.md`](PERSONAL_PC_TEST.md)(0.1.0-preview.1 용)는 고치지 않았습니다. 정식으로 바꿀 때 이 초안이 그 자리를 대신하고, 그때 문서를 못박는 시험도 새 시험지에 맞춰 함께 바꿉니다([`V1_RELEASE_CHECKLIST.md`](V1_RELEASE_CHECKLIST.md) D10).

**이 시험지는 어느 빌드용인가요?** 릴리스를 올리기 전의 **후보 빌드**(예: `0.9.x` 후보와 그 다음 후보 — 번호 규칙은 〔확인 필요〕) 용입니다. 받은 파일 이름이나 화면 `정보` 에 **시험 빌드**라고 적혀 있으면 이 시험지로 시험하지 말고 그 사실만 알려 주세요. 화면 글자가 이 문서와 다르면 문서가 낡은 것일 수 있으니 같은 뜻의 단추를 고르고 다른 점을 적어 주세요.

이 문서는 운영자(비개발자)가 **개인 PC 에서 직접** 해 보는 시험 순서입니다. 회사 PC 에서는 하지 않습니다(회사 PC 는 관리자 권한이라 '일반 사용자' 시험이 되지 않습니다). 모두 하면 **세 시간쯤**(추정 — 두 번에 나눠 해도 됩니다) 걸립니다. 근거는 앱 v1.0 의 완료 기준(설치형·휴대용 모두 실행, 업데이트 전 백업과 실패 시 복구, Pages 시험 글, Blogger 초안, 로그·보고서에 키 없음)입니다.

## 읽고 시작해 주세요

- **진짜 키·비밀번호·토큰은 앱의 어느 칸에도 넣지 않습니다.** 키 칸에는 3단계에서 알려 드리는 **가짜 글자**만 넣습니다. 진짜 로그인이 필요한 곳은 **0단계의 릴리스 화면(GitHub — 브라우저에서 운영자 본인 계정으로)과 9단계(GitHub)·10단계(Google)뿐**이고, 그곳의 비밀번호는 **그 회사의 로그인 창에만** 넣습니다(앱·이 시험지·보고·사진·AI 대화창 어디에도 적지 않습니다).
- **9단계와 10단계는 운영자가 번호 있는 요청에서 승인한 뒤에만** 합니다(실제 서비스에 글이 올라가는 일이라서 — 승인이 없으면 그 두 단계는 건너뛰고 보고 표에 `승인 전` 이라고 적습니다).
- 각 칸의 **`[ ]`** 는 체크 칸입니다. 하고 나서 `[x]` 로 바꿔 적어 두세요(11단계의 표에 옮겨 적습니다).
- **"이렇게 보이면 통과"** 문장과 다르면 **실패**입니다. 멈추지 말고 그때 화면에 무엇이 보였는지만 적고 다음 칸으로 가세요(아래 '멈추고 바로 알릴 일' 은 예외).
- '해당 없음'은 `(선택)` 이라고 적힌 칸을 하지 않았을 때만 씁니다.
- 시험하다 설정을 바꾸거나 무언가를 더 설치하라는 창이 뜨면 **누르지 말고** 창 이름을 적으세요.

**멈추고 바로 알릴 일**: ① 앱을 설치하거나 열거나 쓰는 중에 관리자 권한(UAC — 암호를 넣거나 예/아니요를 고르라는 창)을 묻는 창이 뜸(8단계와 12단계에서 시험용 계정을 만들거나 지울 때 Windows 설정이 관리자 암호를 묻는 것은 해당하지 않습니다) ② 앱이 키·비밀번호·계정을 **앱 안의 칸에** 달라고 함 ③ 앱이 브라우저를 열었는데 안내와 다른 곳임 ④ 화면에 키처럼 보이는 긴 글자가 그대로 보임 ⑤ 업데이트나 되돌리기를 하다 **내 글이 사라진 것처럼 보임**(그 자리에서 멈추고 아무것도 더 누르지 마세요 — 올리기 전에 만든 백업이 있습니다) ⑥ 0-5 에서 이 계정에 진짜로 쓰는 데이터·키가 **이미 있음**(이 계정에서는 시험을 이어 가지 말고 알려 주세요).

## 0단계. 준비 — 받은 파일이 온전한지

받을 것(GitHub 의 릴리스 화면 — 로그인한 브라우저에서 엽니다. 아직 공개하지 않은 초안 릴리스는 운영자 계정에만 보입니다 〔확인 필요〕 — 의 `Assets` 에서 받고, 이름은 화면에 적힌 그대로이며 정해진 이름은 〔확인 필요〕): ① **설치 파일** 둘 — **이전 판(n-1)** 과 **새 판(n)** ② **휴대용 압축 파일**(새 판) ③ **`SHA256SUMS`**(각 파일의 지문 목록). 모두 한 폴더에 둡니다. **이름에 `TESTBUILD` 가 들어 있으면 시험 빌드이니 여기서 멈추고 알려 주세요.**

- [ ] **0-1. 계정이 표준 사용자인지**: Windows `설정` → `계정` → `내 정보` 에서 이름 아래에 `관리자` 라는 글자가 **없어야** 표준 사용자입니다. 있으면 다른 표준 사용자 계정으로 로그인해서 이 단계부터 다시 합니다.
- [ ] **0-2. 악성코드 검사**: 받은 파일을 마우스 오른쪽 단추로 누르고 `Microsoft Defender로 검사`(또는 쓰는 보안 프로그램의 검사)를 고릅니다. **통과**: '위협이 없습니다'. 위협이 나오면 **열지 말고** 이름만 적어 알려 주세요.
- [ ] **0-3. 지문(SHA-256) 확인**: 파일이 있는 폴더를 탐색기로 열고 주소 표시줄을 한 번 누른 뒤 `powershell` 이라고 쓰고 Enter 를 누릅니다(관리자 권한으로 열지 않습니다). 아래 한 줄을 파일마다 이름만 바꿔 붙여 넣고 Enter:

```text
Get-FileHash .\받은파일이름 -Algorithm SHA256
```

  `SHA256SUMS` 를 메모장으로 열어 그 파일 줄 앞의 64글자와 위 결과의 `Hash` 칸을 비교합니다(대문자·소문자 차이는 같은 값입니다). **통과**: 64글자가 **한 글자도 다르지 않고** 같습니다. 다르면 풀거나 설치하지 말고 알려 주세요.
- [ ] **0-4. 지금 PC 상태 적어 두기**(읽기만 하고 바꾸지 않습니다): Windows 버전(`설정` → `시스템` → `정보`)·화면 배율(`설정` → `시스템` → `디스플레이`)·스마트 앱 컨트롤 상태(`Windows 보안` → `앱 및 브라우저 컨트롤`).
- [ ] **0-5. 이 계정에 진짜 데이터·키가 이미 있는지 먼저 확인**(읽기만 하고 바꾸지 않습니다 — 2–8단계가 이 계정의 데이터 폴더에 시험 데이터를 섞고 12단계는 지우는 단계라서 **1단계 전에** 봅니다): ① 키보드 `Windows` 키 + `R` → `%LOCALAPPDATA%` → Enter → 열린 폴더 안에 `ChanceblogDesktop` 폴더가 **이미 있는지** 봅니다. ② `자격 증명 관리자` → `Windows 자격 증명` → `일반 자격 증명` 에 `ChanceBlogDesktop:` 로 시작하는 줄이 **이미 있는지** 봅니다(6-6 과 같은 곳입니다). **통과**: 둘 다 없습니다 — 깨끗한 계정이니 1단계로 갑니다. **하나라도 있으면 이 계정에서는 시험을 이어 가지 말고**(앱을 진짜로 써 온 계정일 수 있습니다) 그 사실을 알려 주세요 — 8단계처럼 만든 **시험 전용 표준 계정**에서 하거나 `ChanceblogDesktop` 폴더를 통째로 다른 곳에 복사해 둔 뒤 하면 됩니다. 이 계정의 폴더와 자격 증명 줄은 **지우지 않습니다**.

## 1단계. 이전 판(n-1)을 표준 사용자 계정에서 설치하고 열기

업데이트 시험(4단계)을 하려면 **이전 판을 먼저** 설치해야 합니다. 설치 파일을 두 번 누르는 것부터 시작합니다.

- [ ] **1-1. 설치**: 이전 판 설치 파일을 두 번 누릅니다. **창이 뜨면 이렇게 하세요**: 파란색 'Windows의 PC 보호' 창(SmartScreen)이 뜨면 `추가 정보` → `실행` 을 누릅니다(서명 없는 프로그램에서는 나올 수 있는 일이니 **떴다는 사실을 보고 표에 적습니다**). 방패 그림과 함께 '이 앱이 디바이스를 변경하도록 허용하시겠어요?'(관리자 권한) 창이 뜨면 **실패**입니다 — `아니요` 를 누르고 멈춰서 알려 주세요. '스마트 앱 컨트롤이 앱을 차단했습니다' 가 뜨면 이 PC 에서는 실행할 수 없는 것이니 설정을 바꾸지 말고 그 사실만 알려 주세요. 설치 창의 글자·단추 이름은 〔확인 필요: 설치 도구가 정해진 뒤〕.
- **이렇게 보이면 통과**: 관리자 권한을 묻지 않고 설치가 끝납니다. 설치된 위치(보통 내 계정의 사용자 폴더 아래 — 〔확인 필요〕)를 보고 표에 적습니다.
- [ ] **1-2. 열기**: 시작 메뉴(또는 바탕 화면 바로가기 — 〔확인 필요: 어디에 생기는지〕)에서 앱을 엽니다. **통과**: `ChanceBlog Desktop` 창이 열리고 왼쪽에 `홈`·`주제 후보`·`초안 작성`·`Seed 관리`·`블로그 관리`·`설정` 메뉴가 보입니다(글 흐름 화면이 더 생겼다면 그 메뉴도 보입니다 — 〔확인 필요: 화면 범위〕). **관리자 권한 요구 창은 한 번도 안 떴습니다.**
- [ ] **1-3. 버전·설치 방식 표시**: 왼쪽 `설정` → `연결 관리` 카드의 마지막 줄 `정보` 를 눌러 펼칩니다. **통과**: 이전 판의 버전이 보이고(예: `버전 v0.9.x`), 설치형이라는 표시가 있다면 그 글을 보고 표에 적습니다 〔확인 필요: 화면 글〕.
- [ ] **1-4. 한 번 더 열어 보기**: 열려 있는 창을 닫지 말고 같은 앱을 한 번 더 엽니다. **통과**: **새 창이 뜨지 않고** 열려 있던 창이 앞으로 오거나(작업 표시줄 단추가 깜박일 수 있습니다) `이미 열려 있거나 열리는 중이에요` 안내 상자 **하나만** 뜹니다. 창이 두 개 뜨면 실패입니다 — 새 창은 건드리지 말고 닫은 뒤 그 사실을 적어 주세요.

## 2단계. 블로그·Seed·후보·초안 만들고 저장하기 (시험용 값만)

앞으로 업데이트·되돌리기·제거에서 **내 데이터가 그대로 남는지** 보려고 이전 판에 데이터를 만들어 둡니다. 진짜 블로그가 아니어도 됩니다.

- [ ] **블로그 등록**: 왼쪽 `블로그 관리` → `네이버 블로그` 카드 → `표시 이름` 에 `시험 블로그 A`, `블로그 ID 또는 주소` 에 `testblog-a` → `저장`. **통과**: '저장했어요.' 안내가 보이고 카드가 `등록됨` 으로 바뀝니다.
- [ ] **Seed 등록·승인**: `Seed 관리` → `새 Seed 등록` → `Seed 낱말` 에 `시험용 키워드`, `대분류`·`중분류` 에 `시험`, `중요도` 는 `일반`, `대상 유형` 은 하나, `소속` 은 `네이버 블로그 1` → `승인 전으로 등록` → 목록에서 눌러 열고 `승인하기`. **통과**: '승인했어요. 이제 후보 생성에 쓰여요.'
- [ ] **후보·초안**: `주제 후보` → `후보 만들기` → 확인 창 `만들기` → 후보를 눌러 오른쪽 상세 창 맨 아래의 `이 주제로 만들기`. **통과**: `초안 작성` 화면에 제목과 본문이 생깁니다.
- [ ] **고쳐서 저장**: 제목 맨 끝에 `!` 한 글자를 더하고 `저장`. **통과**: '저장됨' 표시.
- [ ] **껐다 켜기**: 창을 닫고(저장하지 않은 내용이 있다는 창이 뜨면 `계속 고치기` 로 저장한 뒤 다시 닫습니다) 앱을 다시 엽니다. **통과**: `블로그 관리`·`Seed 관리`·`주제 후보`·`저장한 초안` 이 그대로이고 초안의 제목 끝에 `!` 까지 그대로입니다.
- [ ] **데이터 폴더 위치**: 키보드 `Windows` 키 + `R` → `%LOCALAPPDATA%` → Enter → 열린 폴더 안의 `ChanceblogDesktop` 폴더 경로를 보고 표에 적습니다(**설치·제거·업데이트와 상관없이 이 폴더에 데이터가 있어야 합니다**).
- (선택) 글 흐름 화면(가져오기·미리보기·검토·승인·내보내기·발행 기록)이 있다면 초안 하나로 처음부터 내보내기까지 한 번 해 봅니다 — 〔확인 필요: 화면이 만들어지면 단계를 여기에 쓴다〕.

## 3단계. 백업과 복원, 가짜 키

- [ ] **백업**: 왼쪽 `설정` → 아래로 내려 `백업·복원` 카드 → `지금 백업`. **통과**: '백업을 만들었어요' 안내와 함께 목록에 새 줄이 생기고 그 줄에 **`Credential 제외됨`** 이 보입니다. **이 백업을 4단계 업데이트의 '올리기 전 백업' 으로 둡니다(지우지 마세요).**
- [ ] **일부러 고치고 복원**: `블로그 관리` 에서 `표시 이름` 을 `시험 블로그 AA` 로 한 글자 더하고 `저장` → `설정` → `백업·복원` → 방금 백업의 `복원` → 확인 창을 읽고 `복원하기`. **통과**: '복원을 마쳤어요' 안내가 나오고 이름이 `시험 블로그 A` 로 돌아옵니다.
- [ ] **가짜 키 등록**: `설정` → `AI 보조` 줄을 펼쳐 `AI 보조(선택)` 카드의 `키 등록`(위쪽 `NAVER API HUB 검색어 트렌드` 카드의 것이 아닙니다) → `별칭` 에 `시험`, `API 키` 에 **가짜 글자 `TEST-KEY-NOT-REAL`** 을 붙여 넣기(너무 짧다고 하면 `TEST-KEY-NOT-REAL-TEST-KEY-NOT-REAL`) → `다음` → `저장`. **통과**: `저장된 키` 줄에 별칭 `시험` 과 등록 상태만 보이고 **키의 앞·끝 글자는 어디에도 보이지 않습니다.**
- [ ] **가짜 키 지우기**: 같은 카드의 `삭제` → 확인. **통과**: `저장된 키` 줄이 `연결 안 됨 — 키 없이도 쓸 수 있어요` 로 돌아옵니다.

## 4단계. 업데이트 — 이전 판(n-1)에서 새 판(n)으로

앱 안의 업데이트는 **사용자가 단추를 눌렀을 때만** 확인하는 것이 기본입니다(시작할 때 몰래 확인하지 않습니다 — 방식은 〔확인 필요: 확인 B〕). 이 단계에서 **업데이트 전 백업**과 **데이터 보존**을 봅니다.

- [ ] **4-1. 업데이트 확인**: 앱에서 업데이트를 확인하는 단추(〔확인 필요: 위치와 이름 — 설정 화면의 카드일 것으로 봅니다〕)를 누릅니다. **통과**: 새 판이 있다는 안내와 새 버전 번호가 보입니다. 새 판이 없다고 나오면 0단계에서 받은 새 판이 맞는지 확인하고 알려 주세요.
- [ ] **4-2. 적용 전 확인**: 적용하기 전에 앱이 **무엇을 할지 알려 주는지**(백업을 먼저 만든다는 말·다시 시작한다는 말)를 읽습니다. 알려 주는 글을 보고 표에 적습니다 〔확인 필요: 화면 글〕.
- [ ] **4-3. 적용**: 안내대로 업데이트를 시작합니다. **통과**: 앱이 닫혔다가 다시 열리고(또는 안내대로 다시 열고) **관리자 권한 요구 창이 한 번도 안 뜹니다.**
- [ ] **4-4. 새 판 확인**: `설정` → `연결 관리` → `정보`. **통과**: 새 판의 버전이 보입니다.
- [ ] **4-5. 내 데이터가 그대로인지**: `블로그 관리`(`시험 블로그 A`)·`Seed 관리`·`주제 후보`·`저장한 초안`(제목 끝의 `!` 까지)이 2단계에서 만든 그대로입니다. **통과**: 하나도 사라지거나 바뀌지 않았습니다.
- [ ] **4-6. 업데이트 전 백업이 남았는지**: `설정` → `백업·복원` 목록에 3단계의 백업과 **업데이트 직전에 앱이 만든 백업**(〔확인 필요: 이름·표시〕)이 있고 `Credential 제외됨` 이 보입니다. **통과**: 둘 다 있습니다.
- **참고**: 서명이 틀린 업데이트·바뀐 파일·디스크가 가득 찬 경우 같은 **실패 시험은 개발 쪽 시험이 합니다**(운영자 PC 에서 만들 방법이 없습니다) — 이 단계는 정상 흐름만 봅니다.

## 5단계. 되돌리기(롤백)

업데이트가 잘못됐을 때 **내 글이 안전하게 돌아오는지**를 봅니다. 두 가지를 해 봅니다.

- [ ] **5-1. 앱이 스스로 되돌리는 경우**(개발 쪽이 **일부러 실패하게 만든 시험용 새 판**을 따로 줄 때만 — 없으면 `해당 없음` 이 아니라 `시험용 판 없음` 으로 적습니다 〔확인 필요: 시험용 판을 만들지〕): 그 판으로 업데이트합니다. **통과**: 업데이트가 끝난 뒤 앱이 **이전 판으로 되돌아와** 열리고 안내 글이 나오며(〔확인 필요: 화면 글〕) 2단계 데이터가 그대로입니다.
- [ ] **5-2. 사람이 직접 되돌리는 경우**(백업 복원): ① 이 단계 전에 **4단계의 '올리기 전 백업'** 이 목록에 있는지 봅니다. ② 이전 판을 다시 설치합니다(방법은 〔확인 필요: 되돌리는 설치 방법 — 설치 도구가 정해져야 적습니다〕). ③ 이전 판을 열면 **'더 새로운 버전의 프로그램이 만든 …라 열지 않았어요'** 와 같은 뜻의 안내가 나올 수 있습니다(화면 글은 〔확인 필요〕) — 이것은 정상입니다(낮은 버전은 높은 버전의 데이터를 열지 않아 데이터를 지킵니다). ④ 안내가 나오면 `설정` → `백업·복원` 에서 **4단계의 '올리기 전 백업'** 을 복원합니다. **통과**: 복원 뒤 이전 판에서 2단계 데이터가 그대로 보입니다. 안내 없이 바로 열렸다면 그대로 데이터를 확인합니다.
- [ ] **5-3. 다시 업데이트**: 되돌린 뒤 새 판으로 한 번 더 업데이트합니다. **통과**: 4단계와 같이 됩니다.

## 6단계. 제거 — 설치한 앱 지우기

- [ ] **6-1. 제거 방법 찾기**: Windows `설정` → `앱` → `설치된 앱` 에서 ChanceBlog Desktop 을 찾습니다(〔확인 필요: 앱 이름〕). **통과**: 목록에 있고 `제거` 가 보입니다. 제거 중에 관리자 암호를 묻는 창이 뜨면 **실패**입니다.
- [ ] **6-2. 제거**: `제거` 를 누르고 안내를 따릅니다. **통과**: 끝났다는 안내가 나옵니다(제거 도구의 글은 〔확인 필요〕).
- [ ] **6-3. 앱이 사라졌는지**: 시작 메뉴의 항목·바탕 화면 바로가기·설치했던 폴더(1-1 에서 적은 곳)를 봅니다. **통과**: 앱 항목이 모두 사라졌고 설치 폴더가 비었거나 없습니다. 남은 것이 있으면 이름을 적습니다.
- [ ] **6-4. 내 데이터가 남았는지**: `Windows` 키 + `R` → `%LOCALAPPDATA%` → `ChanceblogDesktop` 폴더가 **그대로 있고** 안의 `chanceblog.db`·`backups` 등이 있습니다(데이터를 지우는지는 확인 C 에서 정합니다 — 추천은 **기본 보존**). 〔확인 필요: 제거 도구가 데이터를 묻는지〕. **통과**: 폴더가 남아 있습니다.
- [ ] **6-5. 다시 설치하면 데이터가 그대로**: 새 판 설치 파일로 다시 설치하고 열어 2단계 데이터를 봅니다. **통과**: 블로그·Seed·후보·초안이 그대로입니다.
- [ ] **6-6. 자격 증명 항목**: `자격 증명 관리자` → `Windows 자격 증명` → `일반 자격 증명` 에 `ChanceBlogDesktop:` 로 시작하는 줄이 제거 뒤에도 남는지(3단계에서 가짜 키를 지웠으니 없는 것이 정상입니다). 남은 줄이 있으면 이름을 적고 **지우지 말고** 알려 주세요.

## 7단계. 휴대용(압축 폴더) — 설치 없이 열기

- [ ] **7-1. 압축 풀기**: 내 계정 폴더 **바로 아래**에 `ChanceBlogTest` 폴더를 만들고 휴대용 압축 파일을 `모두 압축 풀기` 로 그 폴더에 풉니다. **하지 말 것**: `AppData` 안·`Program Files` 안·OneDrive 로 동기화되는 폴더에는 풀지 않습니다. 경로가 길면(`C:\` 부터 100글자 넘게) 풀리다 멈출 수 있습니다. **통과**: 폴더 안에 `ChanceBlogDesktop.exe` 와 몇 개의 폴더가 보입니다.
- [ ] **7-2. 실행**: `ChanceBlogDesktop.exe` 를 두 번 누릅니다(SmartScreen 창은 1-1 과 같은 순서). **통과**: 창이 열리고 관리자 권한을 묻지 않습니다.
- [ ] **7-3. 버전·표시**: `설정` → `연결 관리` → `정보`. **통과**: 새 판의 버전이 보이고 휴대용 표시가 있다면 그 글을 적습니다 〔확인 필요: 화면 글〕.
- [ ] **7-4. 설치형과 데이터 폴더가 같은지**(추천 결정: 휴대용도 같은 `%LOCALAPPDATA%\ChanceblogDesktop` 를 씁니다 — 〔확인 필요: 확인 C〕): 6단계에서 다시 설치한 앱의 데이터(`시험 블로그 A` 등)가 휴대용에서도 보이는지 봅니다. **통과**: 같은 데이터가 보입니다(다르게 결정되면 그 결정대로 적습니다).
- [ ] **7-5. 설치형을 열어 둔 채 휴대용 열기**: 설치형 앱을 연 채 휴대용도 엽니다. **통과**: 같은 데이터를 두 창이 동시에 고치지 않도록 새 창이 뜨지 않고 `이미 열려 있거나 열리는 중이에요` 안내(또는 열려 있는 창이 앞으로)가 나옵니다 — 휴대용이 다른 데이터 폴더를 쓰도록 결정됐다면 두 창이 열려도 정상입니다. 어느 쪽이었는지 적습니다.
- [ ] **7-6. 지우기**: 앱을 닫고 `ChanceBlogTest` 폴더를 지웁니다. **통과**: 지운 뒤에도 다른 곳에 남은 것이 없습니다(시작 메뉴·레지스트리 항목이 만들어지지 않는 것이 휴대용입니다).

## 8단계. 다른 일반 Windows 계정에서 — 첫 계정의 데이터·키에 못 닿는지

**준비**: 표준 사용자 계정이 **하나 더** 필요합니다(관리자 계정이면 안 됩니다). 없으면 `설정` → `계정` → `다른 사용자` → `계정 추가` 로 로컬 계정을 만듭니다('Microsoft 계정이 없는 사용자 추가' 를 고르세요). **계정을 만들거나 지우는 일에는 관리자 암호가 필요합니다** — 그 창은 Windows 설정이 띄운 것이라 **앱 때문에 생긴 문제가 아닙니다.** 암호는 Windows 의 그 창에만 넣고 이 시험지·보고·사진·AI 대화창 어디에도 적지 않습니다. 관리자 암호를 모르면 8-1·8-2·8-3 을 `실패(권한 없음)` 으로 적고 건너뜁니다. 압축 파일(또는 설치 파일)은 첫 계정에서 `C:\Users\Public\Documents` 에 복사해 두면 둘째 계정이 쓸 수 있습니다. 먼저 **첫 계정에 가짜 키를 한 번 더 등록**해 둡니다(3단계와 같은 방법 — 지우지 않고 둡니다).

- [ ] **8-3. 자기 데이터로 시작하는지**: 둘째 계정에서 앱을 설치(또는 휴대용으로 열기)해 엽니다. **통과**: 첫 계정에서 만든 블로그·Seed·후보·초안·백업이 **하나도 보이지 않는 빈 상태**입니다.
- [ ] **8-4. 첫 계정으로 돌아와 가짜 키 지우기**: `설정` → `AI 보조` → `삭제` → 확인. **통과**: `저장된 키` 줄이 `연결 안 됨 — 키 없이도 쓸 수 있어요` 로 돌아옵니다.

## 9단계. Pages 시험 글 — 가지에 올리고 병합해 공개 확인 (운영자가 승인한 뒤에만)

**먼저 알아 둘 것**: 이 단계는 **진짜 GitHub 저장소를 바꿉니다.** 승인된 방식(〔확인 필요: 시험 글 방식 — 확인 D〕)으로만 합니다. 앱은 `main` 에 **직접 올리지 않고 별도의 가지에만** 올리며, 그 가지를 합치는 것은 **운영자가 GitHub 화면에서 직접** 합니다(앱은 비교 화면 주소를 알려 주기만 하고 열지 않습니다 — 〔확인 필요〕). 시험 글은 **제목에 `시험` 을 넣은 글 한 개**만 만듭니다.

- [ ] **9-1. 연결**: 앱의 GitHub Pages 연결(〔확인 필요: 위치와 이름〕)에 시험에 쓸 `chanceblog` 폴더(승인된 저장소의 내 PC 사본)를 연결합니다. **통과**: 연결됐다는 안내가 나옵니다. PC 에 GitHub 로그인(Git 로그인)이 없으면 안내가 나오고, 로그인은 **GitHub 의 로그인 창에서만** 합니다.
- [ ] **9-2. 시험 글 만들기·검토·승인**: 제목에 `시험` 이 들어간 글 하나를 만들어 미리보기를 읽고 승인합니다(〔확인 필요: 화면의 단추 이름〕). **통과**: 승인됨 상태가 됩니다.
- [ ] **9-3. 가지로 올리기**: 올리기 단추를 누릅니다(앱이 **무엇을 올리는지 먼저 보여 주고 확인을 받는지** 봅니다). **통과**: 올렸다는 안내와 함께 **'병합 대기'** 같은 상태가 보입니다(〔확인 필요: 상태 이름〕). **아직 공개 주소에는 글이 없어야 합니다.**
- [ ] **9-4. `main` 에 직접 올라가지 않았는지**: GitHub 저장소 화면에서 `main` 의 최근 변경에 시험 글이 **없고**, 별도의 가지가 새로 생긴 것을 봅니다. **통과**: `main` 은 그대로이고 새 가지만 있습니다. 시험 글이 `main` 에 바로 올라가 있으면 **실패 — 바로 알려 주세요.**
- [ ] **9-5. 병합**: 앱이 알려 준 비교 화면(또는 GitHub 의 가지 목록)에서 변경이 **시험 글 하나뿐인지** 읽고 운영자가 직접 병합합니다.
- [ ] **9-6. 공개 확인**: 잠시 뒤 앱의 공개 확인 단추(〔확인 필요〕)를 누릅니다. **통과**: '공개됨' 상태가 되고 앱이 알려 준 주소에서 시험 글이 열립니다.
- [ ] **9-7. 시험 글 정리**: 시험 글을 어떻게 지우는지는 승인된 방식을 따릅니다(〔확인 필요: 확인 D〕). **통과**: 정리한 뒤 공개 주소에서 글이 더는 열리지 않습니다.
- [ ] **9-8. 연결 끊기**: 앱의 연결 해제(〔확인 필요〕)를 눌러 봅니다. **통과**: 끊긴 뒤 올리기 단추가 쓸 수 없는 상태가 되고 내 글은 그대로입니다.

## 10단계. Blogger 초안 — 초안으로만 저장 (운영자가 승인한 뒤에만)

**먼저 알아 둘 것**: 시험용 Blogger 블로그 하나에만 합니다. 앱은 **초안으로만** 저장하고 **공개하지 않습니다**(공개는 운영자가 Blogger 에서 직접 합니다). 구글 로그인은 **브라우저에 뜬 구글의 창에서만** 하고 앱의 칸에는 비밀번호를 넣지 않습니다. OAuth 로그인 준비(운영자가 구글 클라우드에서 만든 '데스크톱 앱' 로그인 정보 — 영문·한글 블로그마다)는 시험 전에 끝나 있어야 합니다(〔확인 필요: 준비 방법을 BLOGGER 갈래가 안내〕).

- [ ] **10-1. 연결**: 앱의 Blogger 연결(〔확인 필요: 위치와 이름〕)을 시작합니다. **통과**: 브라우저가 열리고 구글의 로그인·동의 창이 나옵니다. **동의 창에 적힌 권한 이름을 그대로 읽어** 11단계 표의 10-1 '동의 창에 적힌 권한' 칸에 옮겨 적습니다(〔확인 필요: Blogger 가 실제로 요구하는 권한 이름 — 이 문서를 쓰면서 확인하지 못했습니다. 글 쓰기만 따로 허락하는 권한이 있는지도 모릅니다〕). 앱이 미리 안내한 권한(〔확인 필요: BLOGGER 갈래가 정한 권한〕)과 다르거나 계정 전체·삭제처럼 더 넓어 보이면 **누르지 말고** 알려 주세요.
- [ ] **10-2. 로그인 마치기**: 로그인·동의를 마칩니다. **통과**: 앱으로 돌아와 '연결됨' 같은 상태가 보입니다. 앱이 **비밀번호나 키를 앱 안의 칸에 달라고 하면 실패**입니다.
- [ ] **10-3. 시험 글을 초안으로 저장**: 제목에 `시험` 이 들어간 글 하나를 만들어 승인한 뒤 Blogger 로 보냅니다(〔확인 필요: 단추 이름〕). **통과**: '초안으로 저장했어요' 같은 안내가 나옵니다.
- [ ] **10-4. Blogger 화면에서 확인**: 구글 Blogger 의 시험 블로그 화면에서 **초안** 목록에 그 글이 있고 **공개되지 않았는지**(블로그 첫 화면에 글이 보이지 않는지) 봅니다. **통과**: 초안으로만 있습니다. 공개돼 있으면 **실패 — 바로 알려 주세요.**
- [ ] **10-5. 연결 끊기**: 앱의 연결 해제를 누릅니다. **통과**: 연결이 끊기고 다시 올리려면 로그인을 새로 해야 합니다. 구글 계정의 `보안` → `타사 앱 액세스` 목록에서 앱이 사라졌는지도 봅니다(〔확인 필요: 화면 이름〕).
- [ ] **10-6. 로그·진단에 키가 없는지**: `설정` → `연결 관리` → `정보` 의 `진단 정보 복사` 로 복사한 글을 메모장에 붙여 넣어 훑어봅니다. **통과**: 키·토큰처럼 보이는 긴 글자가 없습니다. 있으면 **붙여 넣은 글은 올리지 말고** 알려 주세요.

## 12단계. 시험이 끝난 뒤 지우기

- [ ] **앱**: 설치한 앱은 6단계처럼 제거합니다(두 계정 모두). 휴대용 폴더(`ChanceBlogTest`)와 `C:\Users\Public\Documents` 에 복사해 둔 파일도 지웁니다.
- [ ] **데이터 폴더**: `Windows` 키 + `R` → `%LOCALAPPDATA%` → `ChanceblogDesktop` 폴더를 지웁니다(두 계정 모두 — 시험 데이터와 백업이 들어 있습니다). **이 앱을 시험이 아니라 진짜로 쓰는 중이라면(진짜 블로그·Seed·초안이 들어 있다면) 지우지 마세요.** 0-5 에서 이미 있던 폴더도 마찬가지입니다.
- [ ] **자격 증명 관리자 항목**: 3단계와 8-4 에서 가짜 키를 이미 지웠으니 `ChanceBlogDesktop:` 로 시작하는 줄은 남아 있지 않은 것이 정상입니다(6-6 과 같습니다). 남은 줄이 있으면 **지우지 말고** 줄 이름과 0-5 때 적어 둔 것을 함께 알려 주세요 — 진짜 키가 든 줄일 수 있고, 지우면 되돌리려고 키를 다시 넣어야 합니다. 0-5 에서 그런 줄이 하나도 없던 계정이고 시험 중에 생긴 가짜 키라는 것이 분명할 때만 `제거` 합니다.
- [ ] **9·10단계 흔적**: 시험 글·가지·구글의 앱 연결이 정리됐는지 한 번 더 봅니다(위 9-7·10-5).
- [ ] 8단계 때문에 **시험용 계정을 새로 만들었다면** `설정` → `계정` → `다른 사용자` 에서 그 계정을 제거합니다(그 계정의 파일이 모두 지워집니다 — 이때도 관리자 암호를 묻는 창은 앱 때문이 아닙니다). 암호를 모르면 **지우지 말고 그대로 두고** 보고에 '시험용 계정이 남아 있다' 고 적어 주세요.

## 막혔을 때 — 자주 막히는 곳

1. **설치 파일이 안 열림·SmartScreen 에 `실행` 이 없음**: `추가 정보` 라는 작은 글씨를 먼저 눌러야 `실행` 이 나옵니다. `추가 정보` 도 없이 막히면 스마트 앱 컨트롤 차단이니 설정을 바꾸지 말고 알려 주세요.
2. **`Get-FileHash` 가 '인식할 수 없다'고 함**: 줄을 직접 치지 말고 한 줄을 그대로 복사해 붙여 넣으세요. 파일이 있는 폴더에서 PowerShell 을 연 것인지 확인하세요(0-3).
3. **압축이 안 풀리거나 풀다 멈춤**: 경로가 길거나 `AppData`·OneDrive 폴더 안입니다 → `C:\Users\내이름\ChanceBlogTest` 에 다시 풉니다.
4. **업데이트 확인 단추가 안 보이거나 새 판이 없다고 나옴**: 0단계에서 받은 새 판의 번호가 이전 판보다 높은지 확인하고 알려 주세요(화면 글은 〔확인 필요〕).
5. **업데이트나 되돌리기 중에 앱이 멈춘 것 같음**: 5분 기다린 뒤에도 그대로면 **끄지 말고** 화면 글을 그대로 적어 알려 주세요(작업 관리자로 끄는 것은 마지막 수단입니다). 내 글이 사라진 것처럼 보이면 위 '멈추고 바로 알릴 일' ⑤ 입니다.
6. **9·10단계 로그인 창이 안 뜸**: 브라우저가 팝업을 막았는지 확인하세요. 비밀번호를 앱 안에 입력하라는 곳이 있다면 입력하지 말고 알려 주세요.
7. **단추 이름이 다르거나 기능이 없음**: 이름이 다르면 같은 뜻의 단추를 고릅니다. 이 문서가 부르는 기능이 정말 없으면 `실패(기능 없음)` 으로 적고 계속합니다 — 아직 만들어지기 전의 후보 빌드일 수 있으니 알려 주세요.
