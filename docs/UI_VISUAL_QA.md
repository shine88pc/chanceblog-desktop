# 화면 시각 검수 — 검증 환경·사진·점검 결과 (PySide6, 창을 띄우지 않음)

> 화면 배율은 **지원 제한이 아니라 검증 범위**다([`UI_DESIGN_SPEC.md`](UI_DESIGN_SPEC.md) §6). 검수는 `scripts/ui_capture.py` 가 **창을 화면에 띄우지 않고**(`QT_QPA_PLATFORM=offscreen`) 사진을 찍고 같은 환경에서 글자 잘림·누르는 칸·가로 스크롤을 점검한다(홈·상태 화면과 설정 화면 — P4a). **이 PC 는 원격 화면(1912×914, 100%)이고 윈도 배율 같은 시스템 설정은 바꾸지 않는다** — 그래서 배율 사진은 Qt 자체의 High DPI 경로를 시험하는 환경 변수(`QT_SCALE_FACTOR`)와 창 크기 지정으로 만든 **'배율 흉내'** 이고, 실제 윈도 125·150% 렌더·한글 입력기·화면 읽기 프로그램·개인 PC 확인은 운영자 PC 검증으로 남는다(§6). **UI-C0 부터는 앱 화면 사진과 따로, 공통 부품 모음(`--gallery` — 개발용)도 같은 방식으로 찍고 점검한다(§7).**

## 1. 검증 환경

| 구분 | 화면 크기/배율 | 창의 논리 크기 | 만든 방법 | 사진(아래 §2) |
|---|---|---|---|---|
| **필수** | 1366×768 / 100% | 1366×768 | 배율 변수 없음 | 홈·여섯 상태 |
| **필수** | 1920×1080 / 100% | 1920×1080 | 배율 변수 없음 | 홈 |
| **필수** | 1920×1080 / **125%**(배율 흉내) | 1536×864 | `QT_SCALE_FACTOR=1.25` | 홈·서랍·대화상자·툴팁·토스트 |
| 조건부 | 1920×1080 / **150%**(배율 흉내) | 1280×720 | `QT_SCALE_FACTOR=1.5` | 홈(핵심 기능을 쓸 수 있는지만) |
| 참고 | 1180×720 / 100%(UI-C1d 의 최소 폭 — 두 추천 구역이 위아래로 서는 폭) | 1180×720 | 배율 변수 없음 | 홈 |

**UI-C0 의 부품 모음은 위 네 환경에 1366×768 / 125%(논리 1093×614, `QT_SCALE_FACTOR=1.25`)를 더한 다섯 환경에서 찍는다(§7).** 배율 변수는 프로세스를 시작할 때 정해야 하므로 환경마다 자식 프로세스로 돌린다(앱 코드에는 배율 값이 없고 시험이 그것을 확인한다). 사진의 물리 크기는 화면 크기와 같다(125% 에서 논리 1536×864 → 1920×1080). 화면 없는 환경은 운영체제 글꼴을 몰라서 사진·점검 도구만 윈도가 알려 준 시스템 글꼴(`SystemParametersInfo` 의 메시지 글꼴 — 이 PC 는 '맑은 고딕')을 대신 건넨다 — 앱 코드는 늘 `QFontDatabase.systemFont()` 를 쓴다(창을 만들지 않고 진짜 윈도 플랫폼 플러그인으로 읽어 본 이 PC 의 값: 일반 `GeneralFont`=맑은 고딕 9pt·고정폭 `FixedFont`=Courier New 9pt, 화면 1600×900·배율 1.0 — 점검 도구의 대체 글꼴과 같다). 툴팁은 별도의 작은 창이라 창 사진에 안 찍히므로 배지 바로 아래의 실제 자리에 겹쳐 그린다(화면 없는 환경의 가짜 화면 800×800 이 툴팁을 구석으로 밀어내기 때문).

## 2. 사진 (`docs/images/ui/`, 폭 1000px 로 줄임 — 원본은 `scripts/ui_capture.py` 로 다시 만든다)

**UI-C0 에서 이 사진들(홈 계열과 설정 12장)을 새 토큰으로 다시 찍었다 — 의도적인 갱신이다.** 홈·설정의 구조·글·배치는 그대로이고, 사진에서 달라 보이는 곳은 토큰 값(색·글자 크기·모서리)으로 설명되는 곳뿐이다(목록은 §7). 아래 §3·§5-2 의 숫자와 관찰은 UI-C0 이전 값에서 본 것이라, 구조에 관한 내용은 그대로 맞지만 색·글자 크기는 새 사진을 기준으로 읽는다.

**UI-C1d 에서 홈 계열 13장을 새 홈으로 다시 찍었고 새 사진 3장을 더했다 — 의도적인 변화다(§11).** 설정 12장과 부품 모음 5장은 새 코드로 다시 찍어 기존과 픽셀까지 같아 올리지 않았다. 아래 §3 의 숫자와 관찰 중 옛 홈의 요약 카드·칩·추천 행·오른쪽 패널에 관한 것은 UI-C1d 이전의 모습이다.

| 읽는 중 | 줄 모양 자리 표시 3줄 + `연결 상태를 읽고 있어요…`, 새로 읽기 아이콘이 흐리다(꺼짐), 취소 단추 없음(의도) |

| 오류(진단 정보 펼침) | 위험 색 아이콘·제목·한 줄 원인·`다시 시도`, 펼친 진단 정보는 `code`·`time` 두 줄뿐. **고친 것**: 예시 오류 문장이 제목과 거의 같은 말이라(`연결 설정을 읽지 못했어요.` / `연결 설정 파일을 읽지 못했어요.`) 원인과 안심 문장(`파일은 고치거나 지우지 않았어요.`)으로 바꿨다 |
| 일부만·오프라인 | 위에 노랑 안내 띠(일부만은 둘, 오프라인은 하나) — 띠 아래 용도 카드는 그대로 — 어긋남 없음 |
| 실제 어댑터(모두 펼침) | 예시 표시·`예시` 꼬리표가 없고 사용량은 실제 값(`오늘 0 / 100회 · 이번 달 0 / 27,000회` + 작은 글 `서비스 콘솔 월 한도 30,000회 · 실패한 호출도 세어요`), `연결됨` 이 어디에도 없으며 키를 넣은 용도는 `연결 확인 필요`·넣지 않은 용도는 `연결 안 됨`, 키 항목이 없는 검색광고 카드는 보이지 않고(D-99) 묶음 머리 요약은 `준비 중 1 · 연결 확인 필요 1`. 서비스의 고정 멈춤 문구(`…사용할 수 없습니다`)는 한도에 닿았을 때만 나오므로 처음 모습에서는 보이지 않는다. **남은 관찰**: 멈춘 사유 한 줄(`인증 상태가 확실하지 않습니다 — 연결 시험에 성공한 기록이 있어야 새 호출을 합니다`)은 서비스가 주는 존댓말 문장이라 화면의 `~해요` 말투와 다르다 — 서비스의 고정 문구를 그대로 쓰라는 규칙(D-35)이라 바꾸지 않았다 |
| 125%·150% | 글자 잘림·겹침 없음, 접이식 머리의 칩이 오른쪽 끝에 붙어 있고 150% 에서는 설명 문장이 한 줄 더 줄바꿈된다 — 어긋남 없음 |
| 1920×1080/100% | 본문이 최대 폭(1280+여백)에서 가운데 정렬되고 두 열 카드가 넓게 놓인다(홈과 같은 규칙) — 어긋남 없음 |

**시험**(PySide6 가 있으면 모두 돈다, 없으면 Qt 시험만 건너뜀): 새 순수 시험 `test_ui_settings` 76개(P4a 63 + 수정 1차 13)·새 Qt 시험 `test_ui_qt_settings` 42개(P4a 41 + 수정 1차 1)·바뀐 `test_topic_protect_ui` 34개(홈·자리표시 지문 시험 포함). 3.12+PySide6 `test_ui_qt_settings` 42 / 기존 `test_ui_qt` 80 · `test_ui_qt_images` 10 · `test_ui_qt_scale` 1 은 모두 OK 이고, 진짜 3.10(PySide6 없음)에서 순수 시험 251개가 OK 이며 Qt 시험은 건너뛴다(42개).
**변이**(규칙을 일부러 어겨 시험이 잡는지): 73곳 — 뷰모델 28·어댑터 13·가짜 공급자 2·상태 6·문구 3·토큰 1·화면 표 2·Qt 18 — 처음에 1곳(호출 코드가 있는 용도의 모르는 상태를 '연결됨' 으로 읽는 것)이 살아남아 그 경우의 시험을 더했고 다시 돌려 73곳 모두 잡았다. 수정 1차에서는 독립 점검이 찾은 살아남은 변이 7곳(직전 커밋의 시험으로는 통과하던 것)을 포함해 35곳을 더 돌렸고 새 시험으로 모두 잡았다.

## 6. 운영자 PC 확인으로 남는 것 (설치 마무리 체크리스트에 있음)

- 실제 윈도 **125%·150%** 화면에서 홈·상태·서랍·대화상자·툴팁의 렌더(글자 흐림·잘림·단추 높이) — 위 사진은 Qt 의 High DPI 경로를 흉내 낸 것이다.
- **한글 입력기(IME)** 로 입력 칸에 글을 쓸 때의 조합·커서(이 묶음의 입력 부품은 시험에서 영문 입력만 확인).
- **화면 읽기 프로그램**(Narrator 등)이 접근 이름·토스트(알림 이벤트)를 읽는지.
- 시스템 글꼴이 의도대로 잡히는지(한국어 윈도는 '맑은 고딕'이 기대값), 윈도 **'텍스트 크기'**·고대비 모드(이 묶음은 텍스트 크기 설정을 반영하지 않는다).
- 모니터를 옮길 때(배율이 다른 두 화면) 아이콘·글자 선명도.
- 설정 화면이 **실제 키 보관소(윈도 자격 증명 관리자)** 를 읽는 모습 — 이 묶음의 시험·사진은 프로그램 안의 가짜 보관소만 썼다(보관소에는 '있나' 만 묻고 값은 꺼내지 않는다).
- 설치된 환경의 **이미지 형식 플러그인**(`qjpeg`·`qwebp`)과 `QImageReader.supportedImageFormats()` ([`UI_IMAGES.md`](UI_IMAGES.md) §4).
- 새 홈(UI-C1d)의 **카드 그림자**(KPI·구역·연결 한 줄)의 선명도와 그리는 속도, 실제 창의 첫 화면(제목 줄·작업 표시줄이 빼는 높이), 화면 읽기 프로그램이 추천 줄·구역 이름을 읽는 모습(§11).
- 주제 후보 화면(P4d, §10-6): 125·150% 에서 **카드 격자·고정 상세 창**의 렌더(카드 그림자·점수 링·칩), 검색 칸의 **한글 입력기(IME) 조합**(시험은 입력기 확정 이벤트로 흉내 냈다), 화면 읽기 프로그램이 카드(한 줄 이름)·점수 구성·확인창을 읽는 모습, 그리고 **실제 사용자 폴더에서 후보를 한 번 만들어 보기**(승인한 Seed 가 있을 때 `후보 만들기` → `만들기` — `topic_engine/topic_engine.db` 하나만 생기고 설정 파일·사본이 새로 생기지 않는지).

## 10-4. P4c 블로그 관리 폼의 주제 설정 구역 — 사진·점검·기존 기능 영향·시험 (2026-11-07)
