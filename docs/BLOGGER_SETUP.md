# Blogger 초안 저장 — 운영자 설정과 실기 시험 안내

앱 v1.0 의 'Blogger 초안 저장'(BLOGGER 갈래, 결정 D-770에서 D-780, 운영자 확인 038 ③)을 **켜기 전에 운영자가 준비할 일**과 **켠 뒤의 실기 시험 순서**를 한곳에 모은 안내다. 보안 쪽 규칙과 위협 표는 [`SECURITY.md`](SECURITY.md) 맨 끝의 'Blogger 초안 저장' 절, 결정의 이유는 [`DECISIONS.md`](DECISIONS.md) 의 D-770에서 D-779 에 있다.

## 1. 지금 상태

- 구현과 이 PC 안의 가짜 서버 시험은 끝났다. **스위치(소스 상수)는 모두 꺼져 있어서** 지금 빌드는 Blogger 로 아무것도 보내지 않는다 — 출하 표도 비어 있다.
- 앱은 **초안만** 저장한다. 공개는 사람이 Blogger 의 초안 목록에서 직접 한다. 앱은 공개된 글을 고치거나 지우지 않는다.
- 켜는 일은 두 단계이고 단계마다 따로 번호 있는 확인을 받는다.

| 단계 | 켜는 스위치(소스 상수) | 열리는 일 |
|---|---|---|
| 1 | `BLOGGER_OAUTH_INPUT` · `NET_BLOGGER_OAUTH` | 클라이언트 ID·시크릿 입력, 로그인, 연결 확인, 연결 해제 |
| 2 | `EXTERNAL_WRITE` · `NET_BLOGGER_DRAFT` | 글 한 편을 Blogger 에 **초안으로** 저장 |

## 2. 구글 클라우드에서 할 일(한 번 — 운영자)

비밀(클라이언트 ID·시크릿)은 **앱의 입력 칸에만** 붙여 넣는다. 채팅·이슈·파일·저장소에는 쓰지 않는다. 구글 화면의 JSON 은 받을 필요가 없다(받았다면 저장소 밖에 두고 쓴 뒤 지운다).

| # | 할 일 | 설명 |
|---|---|---|
| 1 | 프로젝트 | 구글 클라우드 프로젝트를 쓴다. 클라우드 자동 발행이 쓰는 프로젝트와 같아도 되지만 **클라이언트는 따로 만든다**(할당량은 프로젝트 단위로 같이 쓸 수 있다 — 실기 확인 필요) |
| 2 | Blogger API 사용 설정 | 프로젝트마다 한 번. 꺼져 있으면 앱이 `BLOGGER_API_NOT_ENABLED` 로 알린다 |
| 3 | 동의 화면을 **프로덕션**으로 | 사용자 유형 '외부' 에 게시 상태가 테스트이면 로그인이 **7일 뒤 만료**된다. 프로덕션 + 미확인 앱은 '확인되지 않은 앱' 경고가 나온다 — 혼자 쓰므로 '고급'에서 이동해 진행한다. Blogger 범위가 민감 범위인지(새 사용자 수 제한이 걸리는지)는 동의 화면의 범위 표시에서 확인한다(실기 확인 필요) |
| 4 | 클라이언트 둘 | 사용자 인증 정보에서 OAuth 클라이언트 ID 를 만든다. 애플리케이션 유형은 **데스크톱 앱**이고 이름은 예를 들어 '데스크톱 앱 영문'·'데스크톱 앱 한글' 이다. **클라우드 자동 발행이 쓰는 클라이언트와 다른 것**이어야 한다(취소·100개 한도·할당량이 서로 영향을 주지 않게) |
| 5 | 값 옮기기 | 클라이언트 ID 와 시크릿을 앱 입력 칸에만 붙여 넣는다(아래 3절) |
| 6 | 로그인 | 앱의 '로그인' 으로 브라우저를 열어 **그 블로그의 구글 계정**으로 로그인하고 허용한다 — 영문·한글 계정이 다를 수 있다 |
| 7 | 블로그 번호 | 블로그 관리의 해당 슬롯 'Blogger 블로그 번호' 칸에 숫자를 넣는다(Blogger 대시보드 주소의 숫자 — 위치 확인 필요). 주소는 받지 않는다 |
| 8 | 연결 확인 | 앱이 보여 주는 블로그 이름·주소가 맞는지 사람이 확인한다 — 영문·한글이 뒤바뀌는 사고를 막는 단계다 |

## 3. 앱에서 하는 순서(1단계가 켜진 뒤)

항목 이름은 **`영문` 또는 `한글` 둘 중 하나**다(블로그 하나에 하나). 두 블로그는 서로 다른 블로그라서 한쪽이 막혀도 다른 쪽으로 넘기지 않는다. 명령줄 예시는 `python -m chanceblog_desktop` 뒤에 붙인다(화면의 설정 카드는 화면 갈래가 만든다).

1. **클라이언트 정보 넣기**: `keys add blogger --name 영문 --stdin` — 표준 입력으로 JSON 한 줄에 두 칸(`client_id`·`client_secret` — 칸 이름은 `keys purposes` 에 보인다)을 주거나, 터미널에서 칸마다 숨김 입력으로 넣는다. 갱신용 인증 값은 입력하지 않는다 — 로그인이 받아 자격 증명 관리자에만 보관한다. 상태는 '로그인 필요' 가 된다.
2. **로그인**: `blogger login 영문` — 안내에 나온 주소를 브라우저로 열어 로그인하고 허용한다(3분 안에). 안전을 위해 이 화면은 주소의 `client_id=` 값을 가려서 보여 주므로, 가려진 자리(`[가림: 주소 인자]`)에 1번에서 넣은 클라이언트 ID 를 붙여 넣어 연다. 허용하면 브라우저가 이 PC 안의 임시 창구로 돌아오고 앱이 로그인을 마친다.
3. **연결 확인**: `blogger check 영문` — 블로그 이름·주소·번호를 보여 준다. 맞는 블로그면 같은 명령에 `--yes` 를 붙여 '연결됨' 으로 적는다.
4. **초안 저장(2단계가 켜진 뒤)**: 먼저 글을 승인한다(검토 흐름). 그다음 `blogger save-draft 글번호 영문 --yes` — Blogger 에 **초안으로** 저장하고 글 상태가 '초안 저장됨' 이 된다. `--tags a,b,c` 로 라벨을 줄 수 있다(10개·각 40자까지). 원고를 고쳐 다시 승인한 뒤 저장하면 앱은 이전에 보내다 멈춘 옛 초안을 이어받지 않고 새 초안을 만든다 — Blogger 의 초안 목록에 이전 판이 남아 있으면 필요 없는 쪽을 직접 지운다(앱은 지우지 않는다).
5. **연결 해제**: `blogger disconnect 영문 --yes` — 구글에 로그인 값을 **먼저** 취소하고 성공하면 이 PC 의 갱신용 값을 지운다(클라이언트 정보는 남는다). 오프라인이면 아무것도 지우지 않고 알린다. 그래도 이 PC 의 값만 지우려면 `--this-pc-only --understand-not-revoked` 를 함께 준다 — 구글에 로그인 값이 남으니 구글 계정의 보안 설정에서 앱 접근을 직접 지운다.
6. **상태 보기**: `blogger status` — 읽기만 한다(접속 없음).

이 PC 의 사진 파일이 든 글은 Blogger 초안으로 보낼 수 없다(`BLOGGER_IMAGE_UNSUPPORTED`) — 사진은 이 PC 를 떠나지 않는다. 인터넷 주소의 사진만 허용 호스트 표 안에서 들어간다.

## 4. 실기 시험(켠 뒤 — 운영자)

시험 글도 **발행 전 검사를 그대로 통과**해야 한다(최소 분량 한글 1000자·영문 1500자 포함). 결과는 `PERSONAL_PC_TEST.md` 의 단계 표 형식으로 적는다.

| 단계 | 무엇 | 확인할 것 | 기록 |
|---|---|---|---|
| R1 | 입력 → 로그인 → 연결 확인 | 브라우저가 열리고 허용한 뒤 앱으로 돌아온다 · 블로그 이름·주소가 맞다 · 윈도 방화벽이 루프백 듣기에 질문하는지 | 결과표 한 줄 |
| R2 | 연결 해제 → 구글 계정의 '연결된 앱' 목록에서 사라졌는지 → 다시 로그인 | 취소가 먹었다 — **같은 클라이언트의 다른 토큰에 영향이 있는지도 관찰**(다른 클라이언트라 클라우드 자동 발행은 영향이 없어야 한다) · 로그인한 채 다시 로그인했다면 끝나자마자 `blogger check` 로 새 로그인 값이 살아 있는지 본다(옛 값 취소가 새 값까지 무효로 만드는지) | 결과표 |
| R3 | 시험 글 한 건(제목 '[시험]')을 초안으로 저장 | **Blogger 초안함에 있고 공개되지 않았다** · 라벨·본문이 맞다 · 사진은 인터넷 주소의 것만 | 결과표 + 화면 사진 |
| R4 | 같은 글로 '초안 저장' 한 번 더 | 앱이 이어받거나 안내한다 — 초안이 둘이 되지 않는다(원고를 고치지 않은 같은 글일 때 — 고쳤다면 새 초안이 하나 더 생기는 것이 맞다) | 결과표 |
| R5 | 시험 초안을 운영자가 Blogger 에서 지움 | 앱은 지우지 않는다 | |

## 5. 켜는 변경(개발자 — 단계마다 번호를 받은 뒤에만)

AI 는 켜는 상수를 병합하지 않는다. 승인된 단계의 변경은 다음 모양이다.

1. `src/chanceblog_desktop/capabilities.py` 에서 그 단계의 상수를 글자 그대로 `True` 로 바꾼다(한 줄씩).
2. `packaging/pkgcommon.py` 의 `SHIPPED_OPEN_SWITCHES` 에 같은 이름을 더한다 — 묶음 점검(`--selftest`)은 켜진 상수의 집합이 이 표와 **정확히 같을 때만** 통과한다.
3. '모두 꺼져 있음' 을 못박은 시험(출하 상수 시험·Blogger 켜기 준비 시험·키 화면의 닫힌 모양 시험)을 같은 변경에서 열린 모양으로 고친다 — 약해지지 않게 단계마다 어떤 스위치 조합이 통과하는지 정확히 적는다.
4. 켠 뒤에는 위 4절의 실기 시험을 하고, 어긋난 가정은 한 줄 상수로 고친다(콜백 경로 `/callback` 은 `net/loopback.py` 의 `CALLBACK_PATH`, 앱이 스스로 두는 한도 하루 30회·1분 6회는 `service/connections.py` 의 `BLOGGER_DAY_LIMIT`·`BLOGGER_MINUTE_LIMIT`).

## 6. 문제가 생기면

| 보이는 오류 | 뜻 | 하실 일 |
|---|---|---|
| `BLOGGER_NOT_CONNECTED` | 로그인이 안 돼 있다 | `blogger login` 부터 |
| `BLOGGER_LOGIN_FAILED` | 허용하지 않았거나 3분이 지났거나 범위가 다르다 | 허용까지 누르고 다시 로그인 |
| `BLOGGER_AUTH_EXPIRED` | 갱신이 거절됐다(동의 화면이 테스트 상태면 7일 뒤 만료) | 다시 로그인하고 동의 화면을 프로덕션으로 |
| `BLOGGER_API_NOT_ENABLED` | 그 프로젝트에서 Blogger API 가 꺼져 있다 | 구글 클라우드에서 사용 설정(켠 뒤 몇 분 걸릴 수 있다) |
| `BLOGGER_PERMISSION_DENIED` | 이 계정으로는 그 블로그에 쓸 수 없다 | 맞는 계정으로 로그인했는지·블로그 번호가 맞는지 확인 |
| `BLOGGER_NOT_DRAFT` | 초안으로 저장했는데 Blogger 가 초안이 아니라고 답했다 | **바로** Blogger 에서 그 글이 공개돼 있으면 초안으로 되돌리거나 지운다(앱은 하지 않는다) |
| `BLOGGER_DRAFT_UNKNOWN` | 저장됐는지 알 수 없다 | Blogger 의 초안 목록에서 같은 제목이 있는지 먼저 본다 — 없을 때만 다시 저장 |
| `BLOGGER_IMAGE_UNSUPPORTED` | 이 PC 의 사진이 든 글이다 | 인터넷 주소의 사진으로 바꾸거나 뺀 뒤 다시 승인 |

전체 오류 문구는 [`TROUBLESHOOTING.md`](TROUBLESHOOTING.md) 의 Blogger 표에 있다.

## 7. 아직 확인하지 못한 것(실기에서 확인 — 가짜 서버 시험의 가정일 뿐이다)

Blogger 의 실제 할당량 숫자 · 제목과 라벨의 실제 길이 상한(앱 한도는 제목 200자·라벨 10개 각 40자로 더 엄격하다) · Blogger 범위가 민감 범위인지 · 콜백 경로 `/callback` 을 구글이 받아들이는지 · 초안 찾기 질의의 `status` 값 대소문자 · `access_type=offline`·`prompt=consent` 로 갱신 토큰이 오는지 · `client_secret` 을 항상 보내도 되는지 · `view=ADMIN` 이 받아들여지는지 · 저장 응답에 `status` 가 들어 있는지 · 취소가 같은 클라이언트의 다른 토큰에 미치는 영향 · 윈도 방화벽의 루프백 듣기 질문. 어긋나는 것이 나오면 멈추고 번호 있는 확인 요청으로 알린다.
