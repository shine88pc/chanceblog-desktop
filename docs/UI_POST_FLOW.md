**상태 규칙은 이미 서비스에 있다**(`content/status.py` 의 `FLOWS`·`content/model.py` 의 `transition`): 승인은 현재 원고의 판으로 만든 렌더링에만 줄 수 있고, 원고를 고치면 검토·승인이 풀리며, 올라간 상태는 되돌리지 않는다. 화면은 이 규칙을 **새로 만들지 않고** 서비스 함수만 부른다 —
그래서 1a 는 서비스·글 저장 형식·오류 코드를 바꾸지 않는다(0줄).

**조사에서 찾은 빈틈 둘** (1b 로 넘긴다, 보고서에도 적는다): ① 네이버 검토·복사에는 설정 파일(`settings.json`)의 네이버 프로필이 필요한데, 화면(블로그 관리)이 저장하는 곳은 `topic_engine/channel_profiles.json` 이라 서로 다르다 — 화면만 쓰는 사용자는 네이버 프로필을 만들 길이 없다.
② 화면에서 글을 고치는 길(`edit_project`)이 없어서, 검토에서 걸린 글은 파일을 고쳐 새 글로 다시 가져와야 한다.

## 2. 화면의 최소 구성

### 2-1. 메뉴·이름·화면 안 구성

- **메뉴**: `글 검토`(열쇠 `posts`, 아이콘 `check_circle`)를 사이드바 **핵심 작업** 묶음의 맨 끝(홈·주제 후보·초안 작성 다음)에 둔다 — 후보를 고르고(주제 후보) 초안을 만들고(초안 작성) 그 글을 가져와 검토한다는 순서다.
  `SCREEN_BUILDERS` 와 `NAV` 에 한 줄씩 더하고 시험이 같은 열쇠·같은 순서인지 지킨다(기존 메뉴 목록을 못박은 시험 열세 파일은 의도적으로 갱신 — D-633).
- **화면 안은 두 모습**이고 같은 화면에서 바뀐다(서랍·고정 상세 창은 쓰지 않는다 — 어떤 창 폭에서도 같은 길이다):
  1. **목록** — 머리(제목·설명·`글 가져오기`(주요 단추 하나)·`다시 읽기`) + 글 카드들(제목·판 번호·고친 때·플랫폼별 상태 글). 카드를 누르면 상세.
  2. **상세** — `목록으로` + 글 이름과 정보 한 줄 / **미리보기 카드**(글을 안전하게 그린 모습) / **내보내기 전 검토 카드**(플랫폼 고르기 → 그 플랫폼의 상태·단추·검토 결과).
- **창 안 대화상자 둘** (앱 틀의 `Dialog` 에 얹는다 — 별도 창 없음): `글 가져오기`(2-4 절), `GitHub Pages 검토 값`(분야·언어·대표 이미지 주소 …). 승인은 **확인창**이 먼저다(3-5 절).
- **눌러서 가는 미완성 화면은 없다.** 네이버 복사·발행 기록·Pages 올리기 단추는 1a 에 만들지 않는다(1b·1c). 화면에는 '다음 단계에서 열려요' 같은 거짓 단추도 없다 — 안내 글만 있다.

### 2-2. 층 나누기와 서비스 연결 한 곳

```text
View(ui/qt/post_screen·post_parts·post_flow)  →  PostsController(ui/core/posts_view.py: 뷰모델·눌림 규칙)  →  PostsProvider(ui/core/posts.py)  ┬ FakePostsProvider(메모리 예시)
        ▲ 시그널(작업 스레드 → 화면 스레드)             post_rules.py(순수 규칙) · post_text.py(문구)            JobRunner(ui/core/jobs.py)      └ ServicePostsProvider(ui/posts_adapter.py → service/ — 서비스를 읽고 전이하는 곳은 여기 한 곳)
```

- `ui/core/` 는 PySide6 도 `service` 도 가져오지 않는다(기존 소스 시험이 지킨다). 화면 층이 서비스를 부르는 곳은 **`ui/posts_adapter.py` 한 곳**이고(D-97), 부르는 서비스 함수는 정확히 아홉이다(5절 표). 시험이 어댑터 소스를 `ast` 로 읽어 서비스에서 가져오는 이름·별칭의 속성·컨텍스트 호출까지 허용 목록과 정확히 같은지 견주고(`from ..service.x import y` 같은 우회도 걸린다 — D-639), 화면 층과 어댑터에 Qt 의 파일 쓰기 도구가 없음도 이름으로 못박는다.
- 글 속 건강 효과 단정 판정(`topics.safety`)과 비밀 모양 검사(`security.scan`)는 서비스가 아니라 기존 순수 모듈이라 `ui/core/post_rules.py` 가 부르고, 가짜 공급자와 실제 어댑터가 **같은 함수**를 쓴다(가짜가 실제와 다르게 굴지 않게).
- 무거운 계산(미리보기 만들기·건강 판정·비밀 모양 검사)은 모두 **작업 스레드**(공급자) 안에서 한다. 화면 스레드는 만들어 둔 값을 그리기만 한다.

### 2-3. 상태 그림

글 한 편의 **플랫폼별** 상태(서비스의 `FLOWS` 그대로)와 화면에서 누르는 것:

```text
시작 전 / 글 만듦 ──[검토 시작]──▶ 검토 중 ──[승인하기 + 확인창]──▶ 승인됨(Pages) · 복사 준비됨(네이버)
   ▲                                │  ▲                                  │
   │                                │  └────[다시 검토]──────────────────┤(다시 검토하면 승인이 풀려요)
   └──── 원고를 고침(명령줄 edit) ◀──┴──────────────[승인 취소]────────────┘ → 검토 중
승인됨 이후(올림·공개됨·복사함·직접 발행함·실패)는 1a 화면이 바꾸지 않는다 — 글자로만 보이고 단추가 없다(1b·1c).
```

화면 쪽 상태(컨트롤러): 목록 여섯 상태(2-5 절) × 상세(`open`) × 검토 결과(`review`: 없음 · 읽는 중 · 받음 · 낡음) × 쓰기 작업(`posts-write` 하나).

### 2-4. 가져오기 대화 · Pages 검토 값 대화

- 가져오기와 Pages 값은 **창 안 대화상자**이고 입력 칸의 글은 칸에만 있다(컨트롤러는 '입력이 있나' 만 안다). 대화를 어느 길로든 닫으면 칸을 비우고 되돌리기 기록까지 지운다.
- **가져오기**: 입력이 있을 때 닫으면 **확인 줄**이 먼저다(`그래도 닫기` · `계속 쓰기` — 처음 포커스는 안전한 쪽). 확인 줄이 떠 있을 때 `취소` 를 또 눌러도 닫히지 않는다(`그래도 닫기` 를 눌러야 닫힌다). 가져오는 중에는 닫지 않는다.
- **앱을 닫을 때**(X·Alt+F4) 가져오기 대화에 입력이 있으면 같은 대화 안의 확인 줄이 먼저다 — `그래도 닫기` 를 누르면 앱도 닫힌다. 이 '앱 닫기를 기다림' 표시는 컨트롤러(`import_quit`)에 있고 확인 줄이 거두어지는 모든 길(`계속 쓰기`·계속 입력·`취소`·닫힘·새 가져오기)에서 함께 내려간다. 가져오는 중에는 확인 줄을 띄우지 않고 닫지도 않는다(끝난 뒤 다시 닫는다).
- **파일에서 읽기**: 본문 칸에 이미 쓴 글이 있으면 파일의 글로 **한 번의 편집으로** 바뀌고 안내 줄이 `Ctrl+Z 로 되돌릴 수 있어요` 를 알린다(되돌리기 기록을 지우지 않는다).
- **Pages 값 대화**: 닫을 때 칸의 값(분야·언어·대표 이미지 주소·태그·한 줄 설명 — 글 본문이 아니다)을 컨트롤러가 **이 앱을 연 동안만** 기억해 다시 열 때 채워 준다(파일에 쓰지 않는다 — 그래서 확인 줄은 두지 않는다). **키·토큰 모양이 든 값은 기억하지 않는다**(거절된 글이 다시 채워지지 않게 — 저장 검사기가 아는 여섯 유형뿐 아니라 가리기 엔진이 가리는 모든 모양이 그렇다, D-641). 서비스가 값을 거절해도(키 모양 포함) 대화는 열려 있고 이유만 보인다.

### 2-5. 목록의 여섯 상태 (D-95 의 틀)

| 상태 | 언제 | 화면 |
|---|---|---|
| 읽는 중 | 목록을 읽는 동안 | 줄 모양 자리 표시 + `글 목록을 읽고 있어요…`(취소 단추 없음 — 읽기는 이 PC 의 파일뿐) |
| 정상 | 글이 하나 이상 | 글 카드들(고친 때가 늦은 것부터) |
| 빈 | 글이 하나도 없거나 글 저장소 파일이 아직 없음 | `아직 가져온 글이 없어요` + `글 가져오기` |
| 오류 | 글 저장소를 읽지 못함(파일 깨짐·더 새로운 버전 등) | 쉬운 말 + `다시 시도` + 접힌 진단 정보(오류 코드·시각뿐) |
| 일부만 | 어떤 글은 읽을 수 없음(깨진 행) | 위쪽 안내 띠 `읽지 못한 글이 N개 있어요` + 나머지 글은 그대로 |
| 오프라인 | 예시 데이터에서만(실제 읽기는 네트워크를 쓰지 않으므로 만들지 않는다) | 안내 띠 `오프라인 상태예요. 이 PC 에 저장해 둔 글만 보여 드려요.` |

상세는 같은 틀의 축소판이다: 읽는 중 · 정상 · 오류(`목록으로` 와 `다시 시도`) · 글이 그 사이 사라짐(안내를 띄우고 목록으로).

## 3. 1a 화면 사양

### 3-1. 글 목록

글 카드 하나: 제목(비밀 모양을 가린 뒤 줄임) · `판 N · 고친 때` · **상태 글 세 줄 이하**(`GitHub Pages: 검토 중` 처럼 플랫폼 이름과 상태 이름 — 시작 전 플랫폼은 적지 않고 모두 시작 전이면 `아직 어디에도 내보내지 않았어요`) · 열기 단추(카드 전체가 눌린다 — 키보드는 Tab·Enter).
상태 이름은 서비스의 한국어 표(`STATUS_KO`)와 **같은 글자**를 문구표에 두고 시험이 견준다(화면 층은 서비스를 가져오지 않으므로 같은 글자를 두 곳에 두되 어긋나면 빨개진다 — D-95 ④).

### 3-2. 가져오기 대화

- 종류 고르기 둘: `Markdown 글`(기본) · `기존 HTML 글`(붙여 넣기만 — HTML 파일 읽기는 서비스가 .txt·.md 만 읽으므로 지금은 없다). 칸: 제목(필수), 본문(붙여 넣기 칸 — 평문뿐). 단추: `파일에서 읽기`(Markdown 일 때만), `가져오기`(주요), `취소`.
- `파일에서 읽기` → 파일 고르기(위치만) → **작업 스레드**에서 서비스의 안전한 읽기(`own_posts`)로 읽고 → 본문 칸에 채운다(제목 칸이 비어 있으면 파일 이름에서 확장자를 뗀 것). CP949 로 읽었으면 '글자가 깨져 보이면 UTF-8 로 저장해 다시 골라 주세요' 를 보인다. 거절은 서비스의 고정 문장 그대로.
- `가져오기` 는 제목·본문이 모두 있을 때만 켜진다. 누르면 작업 스레드에서 서비스가 검사한다(NUL·크기·제목의 위험한 글·**비밀 모양**) → 글 저장소에 한 트랜잭션으로 저장 → 대화가 닫히고 그 글의 상세가 열린다. **실패하면 입력은 그대로** 두고 이유를 대화 안에 쉬운 말로 보인다(비밀 모양이면 위치와 유형만 — 글은 되풀이하지 않는다).
- 비밀·키 값은 화면 어디에도 내지 않는다(D-93). 가져온 글에 키 모양이 있으면 저장하지 않으므로 목록에도 없다.

### 3-3. 미리보기 (글 속 HTML·스크립트를 실행하지 않는다)

- 서비스의 안전 변환 `markdown_blocks`(허용 태그 `p·h2–h4·ul·ol·li·strong·b·em·i·br·blockquote` 만 남기는 정화 한 번 더 거침)로 블록을 나눈 뒤 `html_to_text` 로 **글자만** 뽑아 블록 종류(소제목·문단·목록·인용)별로 일반 글 부품으로 그린다. 앱 전체에서 서식 글(HTML)로 읽히는 길이 닫혀 있으므로(소스 시험 `test_source_rules_ui_text`) 미리보기도 Qt 의 서식 글 위젯을 쓰지 않는다 — 글 속의 `<script>` 는 **글자 그대로** 보이고 실행되지 않는다.
- 그리기 전에 모든 글을 **가린 뒤에 줄인다**(`display_text` — 키·토큰 모양은 가려진 글로 나간다). 블록 하나가 3,000자를 넘으면 그 블록은 줄이고, 블록은 앞 80개·합쳐 20,000자까지만 보이며 나머지는 `미리보기는 앞부분만 보여요(전체 N문단 중 M문단)` 한 줄로 알린다(아주 긴 글에도 화면이 느려지지 않게).
- **개인 키 블록(PEM·PGP)은 머리부터 꼬리까지 한 덩어리로 가린다**(D-640). 블록은 빈 줄마다 나뉘고 실제 PGP 키는 머리 줄 뒤에 빈 줄이 있어, 블록마다 따로 가리면 본문 줄이 그대로 나간다. 그래서 머리(`BEGIN … PRIVATE KEY`)가 열린 블록부터 가장 가까운 꼬리(`END … PRIVATE KEY`)가 든 블록까지(사이에 빈 줄·소제목·목록·인용이 끼어도)를 한 글로 이어 붙여 가린다. 꼬리가 없으면 머리 뒤 글 전부가 가려진다(의심스러우면 내보내지 않는다). 묶인 덩어리는 한 블록으로 세고 글자 수는 글 그대로다. **조건과 한계**: 머리·꼬리가 무엇인지는 앱이 정규식으로 따라 하지 않고 **가리기 엔진에 묻는다**(눈에 안 보이는 글자로 쪼갠 머리·길이 한도 없는 라벨도 엔진이 가리는 대로 가린다 — 엔진은 개인 키 꼬리만 꼬리로 본다). 변환 전에 원문도 줄마다 엔진에 물어 개인 키 블록이 덮은 줄을 먼저 가리고 (변환기가 버리거나 흉내 내는 머리·꼬리 때문에 어긋나지 않게 — 꼬리는 원문과 변환된 글 둘 다 닫혔을 때만 닫는다), 변환기가 만드는 머리는 변환 뒤의 묶기가 맡는다. 앱의 저장 길도 눈에 안 보이는 글자로 쪼갠 머리나 긴 라벨의 머리는 받을 수 있어서(저장 검사기가 그것을 못 알아본다) 이 가리기가 마지막 방어선이다. 엔진 자체가 못 알아보는 머리(전각 글자·동형 문자로 쓴 머리)는 가리지 못한다. 15만 자가 넘는 한 줄은 엔진에 물을 수 없어 머리 낱말이 있으면 열린 것으로 본다(더 많이 가리는 쪽). 승인은 이 가리기와 상관없이 서비스의 승인 관문이 막는다.
- 정보 한 줄: 글자 수 · 문단 수 · 이미지 N장(자리만 — 이미지는 그리지 않는다) · 출처 N개.
- 이미지·링크는 그리지도 열지도 않는다(링크는 글자만).

### 3-4. 검토 카드

플랫폼 고르기(칩 셋: `GitHub Pages`·`네이버 A`·`네이버 B` — 칩 글자에 지금 상태가 같이 있다) 아래에 고른 플랫폼 한 곳의 판이 있다. **주요 단추는 늘 하나**: 아직 이 앱을 연 뒤에 검토하지 않았으면 `검토 시작`(이미 검토 중·승인됨이면 `다시 검토`), 검토 결과를 받았고 승인할 수 있으면 `승인하기`.

검토 결과(`검토 시작` 이 돌려준 것)는 세 층이고 각 층은 **글자 배지**(`통과`·`막힘`·`확인 필요`)와 사유 줄을 가진다(색만으로 말하지 않는다):

1. **발행 전 검사** — 서비스의 관문(`service/gate.py` 의 `run_gates`: 파일 모양·키 모양 문자열·HTML 태그·템플릿 표기·위험한 주소·머리말 값·본문 분량(한글 1000자·영문 1500자)·보이지 않는 글자·이 PC 의 폴더 경로·핵심 코드의 잔여물 검사) 결과. 사유의 `[코드]` 마다 **쉬운 한 문장**과 '어떻게 고치나' 를 문구표에 둔다(모르는 코드는 일반 문장 + 접힌 자세히에 코드). 네이버는 패키지의 **경고**(프로필 옵션·글 길이 …)와 **두 블로그 유사도**(제목·첫 문단·본문·이미지·태그 — 많이 비슷하면 `막힘`)를 보인다.
2. **건강 효과 단정** — 글을 문장 단위로 기존 판정기(`topics.safety`, 초안 화면의 복사 관문과 **같은 함수**)에 한 번씩 건다. `일반 생활정보`·`건강 정보 확인 필요(표시만)`·`근거 확인 필요`·`의료·효과 단정 위험`(막힘) 네 단계 중 가장 높은 단계와, 막힘 단계 문장의 **앞부분**(비밀 모양은 가림)을 보인다.
3. **비밀 모양** — 저장 때와 같은 검사기(`security.scan`)로 제목·본문·출처·이미지 이름과 설명(저장 때 훑는 칸과 같다)을 한 번 더 훑어 **위치(줄)와 유형만** 보인다(글·길이 힌트 없음). 하나라도 있으면 `막힘`. (건강 효과 단정 판정은 제목과 본문에만 건다 — Pages 한 줄 설명·태그에는 아직 걸지 않는다. 1b 의 몫으로 이월.)

`막힘` 이 하나라도 있으면 승인 단추는 꺼지고 이유 한 줄이 단추 옆에 있다(`막힌 항목이 있어 승인할 수 없어요`). 검토 결과는 서비스가 **글 저장소에 저장한 렌더링**(현재 판)의 것이다.

### 3-5. 승인과 되돌리기 — 승인은 게시가 아니다

- `승인하기` 가 **켜지는 조건**(전부, 컨트롤러 한 곳 `can_approve`): ① 이 앱을 연 뒤 **이 글·이 플랫폼·이 판**의 검토 결과를 받았다(`review_for` 가 지금 글 번호·판·플랫폼과 같다) ② 그 플랫폼의 상태가 '검토 중' ③ 검토 결과에 `막힘` 이 없다(검사·건강 효과 단정·비밀 모양·네이버 유사도) ④ 쓰기 작업이 돌고 있지 않다 ⑤ 복원이 돌고 있지 않다. 어느 하나라도 빠지면 꺼진 채 이유가 보인다.
- 누르면 **확인창**이 먼저다(처음 포커스는 취소 — Enter 를 잘못 눌러도 승인되지 않는다). 확인창 글: `이 글을 승인할까요?` + 플랫폼·판 + **`승인은 '이대로 내보내도 좋다' 는 내 표시일 뿐이에요. 승인해도 이 앱은 글을 어디에도 올리지 않아요(이 버전에서는 외부로 올리는 기능이 꺼져 있어요). 승인은 언제든 취소할 수 있어요.`** 확인창을 보이지 않고 승인을 시작하는 길은 없다(컨트롤러가 `unconfirmed` 로 거절).
- 서비스가 승인 순간에 **관문을 다시 검사**한다(fail closed — 걸리면 승인하지 않고 쉬운 말로 알림). 그 사이 글이 바뀌었으면(`판` 이 다름·상태가 풀림) 승인하지 않고 '글이 바뀌었어요. 다시 검토해 주세요' 를 보인다.
- `승인 취소` — 승인됨·복사 준비됨 → 검토 중으로(서비스의 `revoke_approval`). 되돌릴 수 있는 일이라 확인창은 없다. 올라간 글·복사를 마친 글은 서비스가 거절하고, 화면은 그 상태에 단추를 아예 만들지 않는다.
- 새 오류 코드는 만들지 않는다 — 서비스 오류는 **종류**(검사 걸림·글 바뀜·글 없음·저장소 문제·입력 값·비밀 모양·기타)로만 나눠 고정 문장으로 알리고, 오류 코드는 접힌 진단 정보에만 있다.

## 5. 외부 쓰기·네트워크·하위 프로세스 0 증명 계획

1a 는 `capabilities.py`·`service/external.py`·`tests/test_source_rules_outgoing.py`·`tests/test_external_write_*.py` 를 **건드리지 않는다**. 이 시험들이 그대로 초록이어야 하고, 빨개지면 설계가 틀린 것이다.

| 증명 | 방법 |
|---|---|
| 어댑터가 부르는 서비스 함수는 이것뿐 | `ui/posts_adapter.py` 소스를 AST 로 훑어 서비스 호출을 모아 **정확한 목록과 같음**을 못박는다 — 읽기: `projects.list_projects`·`projects.show_project`·`own_posts.read_own_files`·`own_posts.check_pasted_text`, 쓰기: `projects.new_project`·`projects.import_html`·`review.request_review`·`review.grant_approval`·`review.revoke_approval`. `pages_flow`·`naver_flow`·`gitrepo`·`external`·`capabilities`·`issue_naver_package`·`record_naver_published` 는 가져오지도 않는다. 호출뿐 아니라 **서비스에서 가져오는 이름(`from ..service.x import y`·`as` 별칭·꾸러미째·별표 포함)·서비스 모듈 별칭의 속성·컨텍스트(`ctx`)의 속성 사슬**도 허용 목록과 정확히 같아야 하고 `getattr` 같은 동적 접근이 없다. 컨텍스트는 `ctx = self._context(...)` 한 모양으로만 만들고 컨텍스트의 이름(`git`·`backend`·`keystore`·`store` …)은 허용된 두 사슬 밖에서 쓰지 못한다(별칭·즉석 사슬·매개변수 이름·`sys.modules` 우회 포함, D-639 — 합성 소스로 검사 자체를 시험한다) |
| 화면 층에 쓰기·접속이 없다 | `ui/core/post*.py`·`ui/qt/post*.py` 소스에 파일 쓰기·`open`·`socket`·`subprocess`·`urllib`·웹 접속 모듈이 없음을 훑는다(기존 `SourceRulesTest` 와 같은 방식, 새 파일이 자동으로 범위에 든다). Qt 의 파일 도구(`QFile` 쓰기 열기 모드·`QSaveFile`·`QTextStream`·`QDir.mkpath`·`QSettings` 등)도 이름으로 막는다(D-639) |
| 실제 서비스로 끝까지 돌려도 데이터 폴더 밖이 안 바뀐다 | 임시 데이터 폴더에서 가져오기 → 검토 → 승인 → 승인 취소를 돌리고 폴더 트리 스냅샷을 견준다(새로 생기는 파일은 글 저장소·잠금 파일뿐). `ctx.git` 이 기본 거절 실행기 그대로라 어떤 git 호출도 일어나지 않음(호출 기록 0). **한계**: 시험의 가짜 뒷받침(`ctx.backend`)은 공개 주소 계산에서 OS 임시 폴더를 쓰는 실제 코드(`publish/deploy.py`)를 돌리지 않으므로, '연결한 저장소가 있을 때의 임시 폴더' 는 시험이 아니라 서비스 코드를 읽어 확인한 사실이다(1절) |
| 읽기는 읽기만 | 목록·상세·미리보기·파일 읽기 뒤 데이터 폴더의 모든 파일이 **한 바이트도** 안 바뀐다(수정 시각 포함) — 읽기 전용 컨텍스트(`ctx.reading_only()`) |
| 소켓·하위 프로세스가 불리면 실패 | 시험 안에서 `socket.socket.connect`·`subprocess.Popen` 을 불리면 바로 실패하는 훅으로 바꾸고 위 전 과정을 돌린다(기존 외부 쓰기 0 시험의 방식) |
| 허용 목록 시험은 그대로 | `test_source_rules_outgoing`·`test_source_rules_output`·`test_source_rules_ui_text`·`test_external_write_zero`·`test_external_write_gate`·`test_capabilities*` 를 고치지 않고 통과 |
| 발행 정지 변수·병합·`workflow_dispatch` 0 | 앱은 `PIPELINE_PAUSE` 를 읽지도 쓰지도 않는다(화면 소스에 그 낱말이 없음을 훑는다) |

**이 표의 소스 규칙 시험은 시험 코드이지 실행 때의 방어가 아니다**(독립 검증 S·Q 2차 — D-639). '정확히 같음'은 이름·가져오기·속성·호출 모양 기준이다. 못 잡는 모양이 남는다: Qt 쓰기를 `getattr(QtCore, 'QFi' + 'le')`·`vars(QtCore)[...]` 같은 이름 조립으로 만들거나(숫자 모드 `.open(2)`) 위젯 `grab().save(...)`·`QImage.save`·`Path(...).open('w')`·`io.open`·`os.open`·`tempfile`·`sqlite3.connect`·`pickle.dump`·`QTextDocumentWriter`·`QPdfWriter` 로 파일을 쓰는 길(이름 목록에 없다), 화면 층(어댑터 밖)에서 `sys.modules[...]` 로 서비스 모듈을 꺼내는 길. 앱 전체 규칙 `test_source_rules_outgoing` 이 맡는 부분이 있고 나머지는 다음 안전 갈래에서 코드로 좁힌다. **실제 방어는 시험이 아니다**: 기본 컨텍스트의 git 실행기는 거절 실행기, 기본 백엔드는 `LocalOnlyBackend`, `capabilities.py` 의 스위치(`EXTERNAL_WRITE`·`BLOGGER_OAUTH_INPUT`·`LOCAL_OCR`)는 모두 꺼져 있고 서비스가 승인 순간에 글을 다시 검사한다. 1b 에서 고치기·지우기가 붙을 때 이 표의 '못박는다' 를 그대로 믿지 말고 이 방어를 본다.

## 6. 접근성·확대·한글 입력

- **접근 이름**: 새 단추·카드·칩·입력 칸·확인 줄 모두 접근 이름이 있고(아이콘만 있는 단추는 접근 이름 + 툴팁), 상태는 색만이 아니라 늘 글자가 함께 있다(배지·사유 줄). 처음 포커스는 안전한 쪽, Esc 로 대화상자·확인창을 닫는다, 열려 있는 동안 Tab 은 그 안에서만 돈다.
- **키보드**: 모든 눌리는 것은 Tab·Enter·Space 로 쓸 수 있고 포커스 링이 보인다. 카드 목록은 Tab 정거장이 카드마다 하나이다. 화면을 다시 그린 뒤에는 누른 곳의 `focus_key` 로 포커스를 되돌린다.
- **확대·창 크기**: 누르는 칸 36px 이상, 고정 폭·높이 없음, 가로 스크롤 없음. 오프스크린 시험이 필수 창 크기 여섯(1366×768 · 125% 논리 1093×614 · 1536×864 · 150% 논리 1280×720 · 1920×1080 · 최소 900×560)에서 가로 스크롤·글자 잘림·단추가 창 안에 있는지 잰다. **실제 윈도 125·150% 렌더·한글 입력기·화면 읽기 프로그램은 운영자 PC 확인으로 남는다**(이 묶음에서 확인하지 못한다).
- **한글 입력**: 본문·제목 칸은 평문 입력이고(서식·그림 붙이기 없음) Tab 은 다음 칸으로 간다. 입력 중에는 화면 전체를 다시 그리지 않고 입력 칸이 있는 대화상자는 별도 위젯이라 한글 조합 중에 칸이 사라지지 않는다. 입력기가 확정한 글도 읽기 전용·꺼진 칸은 받지 않는다(기존 `PasteBox` 와 같은 규칙).
- **긴 글**: 미리보기는 앞부분만 그리고(3-3), 목록은 글이 수백 개여도 한 번에 앞 50개만 그리고 `더 보기` 로 늘린다.

### 8-3. 네이버 복사 패키지 화면 사양

**패키지 만들기 = 검토 시작이다.** 서비스는 검토를 시작할 때 그 블로그의 프로필로 패키지를 만들어 그 블로그의 변형 칸에 저장한다. 그래서 `네이버 A` 와 `네이버 B` 는 **각자 독립**이다: 칩으로 고른 블로그 한 곳만 만들고, A 의 패키지는 B 의 칸에 들어가지 않으며 복사 단추는 지금 고른 블로그의 패키지만 복사한다(화면 상태가 블로그 열쇠를 함께 들고 있어 B 를 고른 채 A 의 글을 복사할 수 없다).

- **패키지 카드**(복사 준비됨·복사함일 때만): 제목·본문 글자 수와 문단 수·태그·이미지 자리 수·발행 전 체크리스트·주의(경고). 글 전체는 다시 그리지 않는다(위의 미리보기가 있다). 모든 글은 가린 뒤에 줄여 그린다.
- **복사 단추 넷**: `제목 복사`·`본문 복사`·`태그 복사`·`전체 복사`. **이 PC 의 클립보드에만 복사한다**(기존 `shell.copy` 길 — 쓴 뒤 다시 읽어 같은지 본다). 키·토큰 모양이 든 글은 복사하지 않고 이유를 알린다(저장 검사기가 아는 여섯 유형은 승인 때 이미 막히지만, 엔진만 아는 키 모양과 승인한 뒤 파일이 밖에서 바뀐 글은 이 복사 가드가 처음 막는다 — 검사는 작업 스레드에서 미리 해 둔 표시를 쓰고, 낱말 뒤에 숨은 글자를 두고 붙인 키 모양은 숨은 글자를 공백으로 바꾼 글도 엔진에 물어 막는다: 8-11 의 알려진 한계). **복사 단추는 상태를 바꾸지 않는다** — `복사했어요` 를 눌러야 '복사함' 이 된다(D-643).
- **상태 단추**: 복사 준비됨 → `복사했어요`(주요)·`승인 취소`. 복사함 → `발행 주소 기록`(주요)·`복사 표시 취소`(복사 준비됨으로 되돌린다). 직접 발행함 → 단추 없음(기록한 주소를 글자로 보이고 `주소 복사` 만 있다). 주요 단추는 늘 하나다.
- **발행 주소 기록 대화**(창 안 대화상자 — 칸의 글은 칸에만 있고 어느 길로 닫혀도 비운다): 칸 하나와 이유 줄. 눌렀을 때 **화면이 먼저 검사하고, 어댑터가 서비스를 부르기 전에 같은 규칙으로 다시 검사한다**(화면을 건너뛰는 호출도 막는다 — D-645, 재작업 1). 서비스 자신의 검사는 이보다 좁다 — https·네이버 호스트·계정 정보·저장 검사기 여섯 유형뿐이라 포트·경로 없음·500자 초과·엔진 전용 키 모양·주소 인자의 토큰은 거르지 못한다:

| 검사(화면과 어댑터가 같은 규칙) | 걸리면 |
|---|---|
| 비어 있다·공백이나 눈에 안 보이는 글자(제어·서식 글자)가 들어 있다·500자를 넘는다 | 이유 한 줄, 서비스를 부르지 않는다 |
| `https` 로 시작하지 않는다·주소 앞쪽에 계정 정보(`@`)가 있다 | 같음 |
| 블로그 주소가 `blog.naver.com` 이나 `m.blog.naver.com` 이 아니다·글 주소(경로)가 없다 | 같음 |
| 키·토큰 모양이 들어 있다(저장 검사기 + 가리기 엔진) | 같음 — 글은 되풀이하지 않고 `키·토큰처럼 보이는 글` 이라고만 말한다 |

  어댑터가 거절하면 서비스를 부르지 않으므로 상태는 그대로이고 기록은 0 이다(실패 종류는 저장 검사기가 아는 유형이면 `secret`, 그 밖은 `address` — 문장에 입력한 주소는 없다). 어댑터를 지난 주소는 서비스의 더 좁은 검사도 지난다(시험이 견준다). 어댑터는 화면처럼 앞뒤 공백을 떼어 서비스에 넘긴다.
  실패하면 대화는 열려 있고 칸의 글은 그대로다. 성공하면 대화가 닫히고 '직접 발행함' 과 기록한 주소(가린 뒤)가 보인다. 발행 주소는 앱을 닫아도 글 저장소에 남는다.
- **유사도 경고와 `그래도 승인하기`**: 두 블로그에 검토한 글이 모두 있으면 서비스가 비슷한 정도를 잰다(1a 가 이미 보인다 — 많이 비슷하면 `막힘`). 막힘이 **유사도 하나뿐**일 때만 승인 단추 옆에 보조 단추 `그래도 승인하기` 가 생긴다. 누르면 1a 의 승인 확인창보다 센 확인창이 먼저다(비슷한 정도·이유·`같은 글이 두 블로그에 올라가면 중복 글로 취급될 수 있어요` 를 보이고, 처음 포커스는 취소, 확인 단추는 `그래도 승인`). 확인창을 보이지 않고 이 승인을 시작하는 길은 없고, 건강 효과 단정·비밀 모양·승인 직전 재검사는 그대로 막는다(D-646).
- 이 흐름의 쓰기는 `posts-write` 한 작업이고(중복 누름은 거절), 복원이 도는 동안은 시작하지 않으며, 앱을 닫을 때 끝나기를 기다린다(1a 의 D-631 과 같다).

### 8-4. 발행 기록 화면

- **무엇을 보이나**: 글 저장소에서 **승인 이후 단계에 있는 (글, 플랫폼) 쌍** 한 줄씩 — 검토 전 단계(시작 전·글 만듦·검토 중)만 빼고 모두다(승인됨·복사 준비됨·복사함·직접 발행함·올리는 중·공개됨·실패 …). 닫힌 목록으로 못박지 않아서 앞으로 서비스에 새 상태가 생겨도(예: 병합 대기) 화면이 죽지 않고 그 줄이 `알 수 없음` 으로 보인다(D-653).
- **한 줄**: 글 제목(가린 뒤 줄임)·플랫폼 이름·상태 이름(글자 — 색만으로 말하지 않는다)·때(발행 주소를 기록한 때, 없으면 글을 마지막으로 고친 때, 한국 시각)·기록한 주소(있을 때, 가린 뒤)와 `주소 복사`(클립보드뿐).
- **순서**: 기본은 **오래된 순서**(기록은 시간 순으로 쌓인다)이고 `최신 순서로 보기` 단추로 바꾼다(같은 때는 글 번호·플랫폼으로 정해 늘 같은 순서). 한 번에 앞 50줄만 그리고 `더 보기` 로 늘린다.
- **여섯 상태**: 읽는 중(줄 모양 자리 표시, 취소 없음)·정상·빈(`아직 발행 기록이 없어요` + `글 검토로 가기`)·오류(쉬운 말 + `다시 시도` + 접힌 진단 정보)·일부만(읽을 수 없는 글 N개 안내 띠 — 나머지는 그대로)·오프라인(예시에서만).
- 화면을 열 때마다 읽는다(읽기만 — 파일도 폴더도 만들지 않는다). 쓰는 단추는 없다.

### 8-5. 작업 로그 보기

- **무엇인가**: 앱이 처리하지 못한 오류가 났을 때 남기는 작은 기록 파일(`logs/errors.log` 와 돌려쓰기 둘 — 오류 이름과 코드 위치뿐, `security/errorlog.py`)을 **읽어서 보이는** 카드다. 발행 기록 화면의 두 번째 카드이고 `작업 로그 보기` 단추로 펼친다(처음에는 접혀 있고 펼칠 때 읽는다).
- **읽기 전용**: 지우기·고치기·내보내기·복사 단추가 없다(문제를 알릴 때는 설정의 `진단 정보 복사` 가 있다). 파일이 없으면 만들지 않고 `기록된 오류가 없어요`. 서비스(`worklog.read_work_log`)는 세 파일 가운데 있는 것만 크기 한도 안에서 읽고, 링크는 따라가지 않는다(`logs` 폴더 자신이 링크여도 — 윈도 정션·심볼릭 링크 모두, 재작업 1).
- **키·토큰·끝 4자를 보이지 않게 한다(D-93) — 막는 범위는 엔진이 아는 모양과 긴 덩어리까지다**: 줄의 글을 그대로 내보내지 않는다. 서비스가 줄을 **칸(때·갈래·오류 이름·코드 위치)으로 쪼개 글자표(영문·숫자·밑줄·점·붙임표)를 통과한 칸만** 내고, 모양이 다른 줄은 몇 줄을 건너뛰었는지 개수만 알린다. 글자표를 지난 줄도 **가리기 엔진이 건드리는 줄(엔진이 아는 키·토큰 모양)과 영문·숫자·밑줄·붙임표가 24자 이상 이어지는 덩어리가 든 줄은 건너뛴다**(점·쌍점·띄어쓰기가 덩어리를 끊는다). 엔진은 키 바로 앞이 영문·숫자이면 키로 읽지 않아서 낱말에 붙여 손으로 고친 줄은 엔진만으로는 못 거르기 때문이다. 이 둘이 막는 것은 엔진이 아는 모양과 긴 덩어리이고, 그 밖의 모양으로 손으로 고친 줄의 값까지는 막지 못한다. **쓰는 쪽(`security/errorlog.py`)은 메시지·값을 읽지 않고 오류 클래스 이름과 파일 이름(폴더 없이)만 쓰므로 정상 줄에는 이런 긴 덩어리가 없다**(파일 이름은 점이 확장자를 떼어 내고 이 앱의 이름은 24자에 못 미친다 — 드물게 아주 긴 이름의 정상 줄이 건너뛰어져도 건너뛴 개수로 알린다). 화면은 그 칸마다 다시 가린 뒤 줄인다. 최근 200줄만 보이고 오래된 줄은 개수로 알린다(최신이 위).

### 8-6. 네이버 프로필 틈 — 데이터 형식을 바꾸지 않고 합쳐 읽는다

블로그 관리 화면은 채널 프로필 파일에 쓰고 서비스의 네이버 검토는 설정 파일의 프로필을 읽어서, **화면만 쓰는 사람은 네이버 검토를 켤 수 없었다**(1a 의 안내만 보였다). 가장 작은 길(D-648): 새 읽기 함수 `naver_profiles.profile_for` 가 **설정 파일의 프로필을 먼저** 쓰고(명령줄로 정한 값이 우선), 없을 때만 블로그 관리에 **블로그 ID 나 주소가 등록된** 슬롯에서 표시 이름·블로그 주소·주제·대상 독자·말투를 가져와 프로필을 만든다(나머지 칸은 프로필의 기본값). 만들 수 없으면(등록 안 됨·주소가 네이버 블로그 주소가 아님·파일이 읽히지 않음) 예전처럼 `NAVER_PROFILE_MISSING` 이다. 두 파일의 모양·위치·쓰는 길은 그대로이고 **데이터 이관은 없다** — 읽기만 하며 파일도 폴더도 만들지 않는다. 검토(`request_review`)와 명령줄 미리보기(`preview_naver`)가 이 함수를 부르고, 후보·초안·점검 도구는 아직 설정 파일의 프로필만 본다(알려 둔 한계). 화면은 `profile_keys` 로 어느 블로그를 검토할 수 있는지 안다.

### 8-7. 1a 에서 넘어온 것

- **건강 효과 단정 판정을 Pages 한 줄 설명·태그에도 건다**(1a 보고서 ⑤-4, D-652): 검토 때 한 줄 설명과 태그를 제목·본문과 같은 판정기에 문장(태그는 하나씩)마다 걸어 가장 높은 단계를 합친다. 막힘 단계면 승인 단추가 꺼진다. 승인 직전 재검사(어댑터)도 같은 값을 건다 — 검토 결과가 쓴 값을 승인 요청이 함께 들고 간다.
- **사이드바**(1a 보고서 ⑤-2, D-651): 1a 는 높이 488(경보 492·한도 500)에서 끝났다. 1b 는 메뉴 하나(44)를 더하고 다음 단계 상자(제목 + 줄 24)를 없앴는데 **잰 값은 줄지 않고 493 이었다**(처음 문서의 '줄거나 같다' 는 틀린 예상이다 — 상자는 간격이 0 으로 줄어든 최소 높이에서 제목과 줄 하나뿐이라 메뉴 하나보다 작았다). 시험의 경보 492 는 올리지 않고 아래 브랜드 카드의 위아래 여백만 8 에서 4 로 줄여 485 로 맞췄다 — 1a 가 줄인 간격(항목 사이 0·묶음 이름 아래 0)과 메뉴 줄 높이·글자·아이콘은 그대로다(D-651).
- 알 수 없는 새 상태: PUBPR 갈래가 곧 `MERGE_PENDING` 같은 상태를 더한다. 이 갈래는 상태 목록을 닫힌 집합으로 못박는 시험을 더하지 않고, 모르는 상태는 `알 수 없음` 으로 보인다(D-653).

### 8-8. 미루는 것 (1b-2·1c)

1b-2: 글 고치기·지우기(M04·M05) · 네이버 프로필 **편집**(만들기·고치기)을 이 화면에서 하는 것 · 글쓰기 페이지 열기를 글 흐름에도 두는 것(M17 — 초안 작성 화면에는 이미 있고, 복사 패키지는 접속이 없다는 약속을 지키려고 이번에는 단추를 두지 않았다) · 작업 로그 내보내기. 1c: Pages 올리기·공개 확인·Blogger 초안 — 외부 쓰기 스위치가 꺼져 있으므로 '이 버전에서는 꺼져 있어요' 안내와 자리, 설정의 연결 카드, 올리는 중 기록 읽기. 승인 확인창의 '외부로 올리는 기능이 꺼져 있어요' 문장은 1a 와 같고, 스위치를 켜는 갈래가 같이 고친다(1a 보고서 ⑦).

### 8-9. 결정 (운영자 위임 규칙 — 새 결정은 멈추지 않고 우선순위로 정하고 기록한다)

번호는 DECISIONS.md 의 같은 번호 행과 같다. 1a 재작업이 D-638–D-641 을 이미 써서 **이 갈래는 D-642 부터 쓴다**(지시서의 구간 D-638–D-659 에서 앞 넷이 쓰인 뒤다).

- **D-642 범위와 순서** — 1b 는 네이버 복사 패키지·복사 완료 표시·발행 주소 기록·유사도를 알고도 승인하기·발행 기록 메뉴·작업 로그 보기·네이버 프로필 틈이고 글 고치기·지우기는 1b-2 다. 새 메뉴는 `발행 기록` 하나. 근거: 최신 운영자 결정(v1.0 완료 기준 7번 먼저)·변경 최소화.

### 8-11. 재작업 1 — 독립 검증(안전 렌즈 S)의 필수 1·권고 3 (2026-11-26)

- **필수-1 발행 주소**: 어댑터가 서비스를 부르기 **전에** 화면과 같은 규칙(`post_rules.address_failure` — 가짜 공급자와 같은 함수)을 다시 건다. 이전에는 화면(컨트롤러)을 건너뛰는 호출이 포트(:443)·경로 없음·501자와 5,000자·엔진 전용 키 모양·주소 인자의 토큰이 든 주소를 서비스가 그대로 받아 직접 발행함으로 저장했다 — 서비스 자신의 검사는 https·네이버 호스트·계정 정보·저장 검사기 여섯 유형뿐이다. 이제 거절하면 서비스를 부르지 않으므로 상태는 그대로이고 기록은 0 이며 문장에는 입력한 주소가 없다. 눈에 안 보이는 글자(제어·서식 글자)도 공백처럼 거절한다(참고-1 — `주소 복사` 는 글자를 그대로 복사하기 때문이다).
- **권고-1 작업 로그의 링크**: `logs` 폴더 자신이 링크(윈도 정션·심볼릭 링크)여도, 기록 파일이 링크여도 따라가지 않는다 — 백업과 같은 기준(`fslink.is_link`). 이전에는 파일 링크만 보아 `logs` 를 폴더 밖으로 잇는 정션이 놓였다.
- **권고-2 숨은 글자 앞붙임 키 모양(임시 방어)**: 낱말 바로 뒤에 눈에 안 보이는 글자를 두고 키 모양을 붙인 글(`낱말` + 숨은 글자 + `키`)은 가리기 엔진(`security/mask.py`)이 키 앞이 영문·숫자라고 보아 가리지 못한다 — 엔진의 한계이고 SECSEP2 갈래가 고친다(이 갈래는 엔진을 건드리지 않는다). 그 전까지 복사 가드와 발행 주소 칸(`would_be_masked`)은 숨은 글자를 **공백으로 바꾼 글**도 엔진에 물어 하나라도 가려지면 막는다. 숨은 글자 없이 낱말에 바로 붙인 키는 평범한 긴 낱말과 구별할 수 없어 못 막고, 화면에 그려지는 글(미리보기·경고·체크리스트)에는 이 방어가 걸리지 않는다. `docs/SECURITY.md` 에 알려진 한계로 적었다.
- **권고-3 작업 로그의 약속**: 위 8-5 의 문장대로 약속을 '엔진이 아는 모양과 긴 덩어리' 로 낮추고, 서비스가 영문·숫자·밑줄·붙임표 24자 이상 덩어리가 든 줄을 건너뛰게 좁혔다. 글자표의 숫자는 ASCII 숫자뿐이다. 쓰는 쪽(`security/errorlog.py`)은 그런 줄을 만들지 않는다.
- **시험·변이**: 새 시험 36개(서비스 9·어댑터 9·순수 15·문서 3 — 기존 단언 변경 0·사라진 id 0)와 변이 25개(어댑터의 다시 걸기 삭제·공백 안 떼기·가짜 공급자 되돌리기·숨은 글자 규칙 되돌리기·임시 방어 삭제·폴더 링크 검사 삭제·긴 덩어리 검사 삭제·한도 바꾸기·문서 되돌리기 …)가 모두 잡혔다(원복 sha256 같음). 기준 소스에서 새 시험은 어댑터 119·순수 153·서비스 7건이 빨강이었다.
- **하지 않은 것**: 승인 쪽 검사(`text_blocks`)가 엔진 전용 키 모양까지 보게 하는 것·막힌 패키지에서 `복사했어요` 를 끄는 것·동시 수정에 대비한 판 번호(독립 검증 S 참고-2·3 — 낮은 위험이라 이번에 하지 않았다)·숨은 글자 없이 낱말에 바로 붙은 키(엔진 한계). 서비스의 주소 검사(`content/model.py`·`review.py`)와 `security/mask.py` 는 한 줄도 바꾸지 않았다.
