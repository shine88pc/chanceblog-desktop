# 설치 도구 시험 실행 안내 (운영자용)

이 문서는 **병합 뒤에** 운영자가 GitHub 화면에서 시험 한 번을 돌리고 결과를 알려 주는 방법이다. 개발자용 설명은 [`PACKAGE.md`](PACKAGE.md) 의 '설치 도구 시험' 절과 결정 D-700 에서 D-708([`DECISIONS.md`](DECISIONS.md))에 있다.

## 이게 무엇인가요

앱을 '설치 파일' 로 배포하려면 설치 도구를 골라야 한다. 후보는 Velopack(두 가지 모양)과 Inno Setup 이다. 이 시험은 GitHub 가 빌려 주는 **일회용 Windows 컴퓨터**에서 세 후보를 같은 앱 묶음에 적용해 보고 숫자를 모아 준다 — 조용히 설치되는지, 제거해도 글과 설정이 남는지, 업데이트가 깨끗한지, 한국어 안내가 있는지, Windows Defender 가 의심하는지, 파일 크기와 걸린 시간이 얼마인지.

- 이 PC 나 운영자 PC 에는 **아무것도 설치하거나 받지 않는다.** 모든 일은 일회용 컴퓨터 안에서 일어나고 끝나면 사라진다.
- 이 도구는 시작할 때 GitHub 의 일회용 Windows 컴퓨터 안인지 먼저 확인하고, 아니면 아무것도 하지 않고 **종료 코드 2** 로 멈춘다(작업 폴더도 만들지 않는다). 개발 PC 에서 실수로 돌려 방화벽 규칙이나 임시 사용자를 만드는 일을 막으려는 것이다. **이 확인은 개발 PC 에서 실수로 돌리는 것을 막는 장치이지 보안 장치가 아니다 — 환경 변수를 일부러 맞추면 통과한다.** 그러니 직접 돌리지 말고 아래 '하는 법' 대로 GitHub 화면에서만 돌린다.
- 블로그·글·설정·키에는 닿지 않는다. 비밀 값(키·토큰)을 쓰지 않는다. 앱의 코드도 바꾸지 않는다.
- 내려받는 것은 둘이다: 설치 파일 만드는 도구 vpk(약 147MB, GitHub 공식 릴리스)와 Velopack 파이썬 부품(약 1.4MB, PyPI). 둘 다 **크기와 지문(SHA-256)이 미리 적어 둔 값과 같을 때만** 쓰고 다르면 그 자리에서 멈춘다. 비용은 0 이다.
- 걸리는 시간은 약 40분에서 60분이다(한도 60분).

## 하는 법

1. 병합 부탁이 끝난 뒤(AI 가 '실행 부탁' 을 따로 보낸다) GitHub 의 앱 저장소에서 **Actions** 탭을 연다.
2. 왼쪽 목록에서 **Installer spike — 설치 도구 시험(수동, 병합 뒤 운영자 실행)** 을 누른다.
3. 오른쪽의 **Run workflow** 단추를 누르고 가지는 **main** 그대로 둔 채 초록색 **Run workflow** 를 한 번 누른다. 입력칸은 없다.
4. 잠시 뒤 목록에 노란 점의 실행이 생긴다. 끝날 때까지 기다린다(40분에서 60분). 중간에 화면을 열어 둘 필요는 없다.
5. 실행이 끝나면(초록 또는 빨강) 그 실행을 눌러 열고 **Summary**(요약) 화면의 **맨 아래**로 내려간다. **설치 도구 시험 결과 블록** 아래에 회색 코드 상자가 있다.
6. 그 상자의 글을 **통째로 복사**해 AI 가 알려 준 소유자 이슈 양식의 본문에 붙여 넣는다. 설명을 덧붙일 필요 없다. 상자의 첫 줄은 `INSTALLER_SPIKE_RESULT` 로 시작하고 마지막 줄은 `END` 로 끝난다.

상자에는 숫자와 통과·실패 말만 있다. 경로·사용자 이름·키는 들어 있지 않도록 만들었다(그래도 이상한 글이 보이면 붙이지 말고 알려 주세요).

## 빨갛게 끝나거나 상자가 없다면

- 실행 화면에서 **빨간 X 가 붙은 단계의 이름**만 알려 주세요. 단계 이름은 '빌드 도구를 잠금 파일의 정확한 버전으로 설치', '도구 받기', '도구 설치', '묶음 만들기', '설치 파일 만들기', '측정', '보고서와 작업 요약 결과 블록 만들기', '올리기' 중 하나다.
- **도구 받기** 에서 빨갈 때는 받은 파일의 크기나 지문이 적어 둔 값과 달라서 **일부러 멈춘 안전 장치**다 — 고장이 아니다. 그 사실만 알려 주세요.
- 측정 중 일부가 '시도 불가' 로 나오는 것은 정상이다(예: 일회용 컴퓨터 안에서 다른 사용자로 설치해 보는 것). 그런 항목은 나중에 운영자 PC 시험지로 넘긴다.

## 올라가는 파일

실행이 끝나면 **Artifacts** 에 `InstallerSpike-report` 하나가 14일 동안 남는다. 안에는 보고서 두 파일(`INSTALLER_SPIKE_REPORT.md`·`INSTALLER_SPIKE_REPORT.json`)뿐이다. 설치 파일·로그·시험 폴더는 올라가지 않는다. 결과 블록을 이슈에 붙이면 충분하고, 이 파일을 따로 받을 필요는 없다.

## 그다음은

결과를 받으면 AI 가 점수를 측정값으로 다시 매겨 어느 도구로 갈지 결정 기록에 적고(점수 차가 작으면 이미 승인된 Velopack 을 따른다) 알려 준다. 세 도구가 모두 탈락하는 경우에만 운영자에게 묻는다(설치 파일을 1.1 로 미루고 휴대용만 1.0 에 내는 방안). 시험용 파일은 결정 뒤에 지우는 정리 가지를 따로 부탁한다.

## 두 번째로 돌릴 때(1차 결과를 본 뒤)

1차 결과에서 시험 도구 자체의 결함이 여럿 나와 고쳤다(결정 D-810). **운영자가 할 일은 달라지지 않는다** — 위 '하는 법' 그대로 Run workflow 를 **같은 단추로 한 번** 누르고, 끝난 뒤 결과 상자를 **같은 곳(소유자 이슈 양식의 본문)** 에 붙이면 된다. 입력칸도 새 절차도 없다. 달라지는 것은 상자의 모양과 읽는 방법뿐이다.

- 첫머리 줄에 러너 이름·이미지 판·vpk 판·Inno 판이 채워진다. 읽지 못한 칸에는 물음표 대신 이유가 적힌다.
- 같은 항목의 작은 앱 결과와 실제 묶음 결과가 한 줄에 이어 붙지 않고 따로 한 줄씩 나온다.
- 표준 사용자로 설치해 보는 항목(M18)은 일회용 컴퓨터 안에서 확인되지 않으면 실패가 아니라 '시도 불가' 와 이유로 적힌다. 그 항목은 운영자 PC 시험지(T-INST-04)로 넘긴다.
- Inno Setup 은 6.5.0 이상이면 쓴다. 판을 여러 방법으로 읽고, 읽지 못해도 멈추지 않고 '미확인' 으로 적은 채 잰다.
- 설치본의 점검 결과는 앱이 가진 점검 목록 전부가 통과했는지로 본다. 상자에는 센 개수가 그대로 적힌다.
