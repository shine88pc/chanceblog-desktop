# 화면 상태와 작업 스레드 (PySide6)

> 홈의 '맞춤 주제 추천' 영역은 여섯 상태 중 하나다(`ui/core/app_state.py` 의 `LIST_STATES`). 상태는 뷰모델이 정하고 화면은 그리기만 한다. 기술 오류(영문 코드·HTTP 번호·예외 이름·경로·스택 트레이스)는 기본 화면에 나가지 않는다 — 접어 둔 **진단 정보**에만(오류 코드와 시각뿐, 비밀 모양은 가림). 값은 [`UI_DESIGN_SPEC.md`](UI_DESIGN_SPEC.md), 부품은 [`UI_COMPONENTS.md`](UI_COMPONENTS.md).

## 1. 홈의 여섯 상태

| 상태 | 언제 | 화면 | 다음 행동 |
|---|---|---|---|
| `normal` 정상 | 후보가 있음 | 필터 칩 5개 + 추천 행 5개 | 행 누르기·`초안 만들기`(안내)·`>`(상세 서랍) |
| `loading` 불러오는 중 | 후보를 가져오는 동안 | 줄 모양 자리 표시 4줄(움직이지 않음) + `후보를 불러오고 있어요…` + `불러오기 취소`. 다시 불러오기 단추는 꺼짐, 첫 불러오기이면 요약 카드는 `–` | 기다림·취소 |
| `empty` 빈 화면 | 후보가 하나도 없음 | 아이콘 + `아직 추천 주제가 없어요.` + 한 줄 안내 + `주제 분석 시작`(안내만 — 아직 없는 기능) | 단추 |
| `error` 오류 | 데이터를 못 가져옴 | 위험 색 아이콘 + 한 줄 원인(오류 코드 표의 쉬운 문장) + **`다시 시도`** + 접어 둔 `진단 정보 보기`(고정폭 글꼴: 오류 코드·시각) | 단추. 이전에 받은 데이터는 지우지 않는다 |
| `partial` 일부만 | 일부 지표(예: 추세)만 실패 | 위에 안내 띠 `검색 추세는 불러오지 못했지만 나머지 정보는 그대로 쓸 수 있어요.` + 행은 그대로(못 가져온 칸은 `데이터 없음`) — 화면을 막지 않는다 | 계속 사용 |
| `offline` 오프라인 | 저장해 둔 값으로 보여 주는 중 | 위에 안내 띠 `오프라인 상태예요. 저장해 둔 초안은 계속 고칠 수 있어요.` | 계속 사용 |

**오류 상태가 되는 길**: ① 서비스 층 오류(오류 코드 표의 쉬운 문장 — 읽기만 하는 화면이라 '저장하지 못했습니다' 류는 `데이터 폴더를 읽지 못했어요. …` 로 바꾼다) ② 직접 정한 `--data-dir` 가 없거나 파일이면 `지정한 데이터 폴더를 찾지 못했어요. 폴더 이름을 확인한 뒤 다시 열어 주세요.`(빈 화면이 아니다 — 기본 위치는 아직 없어도 오류가 아니라 빈 화면이다) ③ 화면 스레드의 결과 슬롯 안에서 예기치 못한 예외(이상한 데이터 등)가 나면 `작업을 마치지 못했어요. 입력한 내용은 그대로 남아 있어요.` + 진단 정보의 예외 **이름**뿐이고, 받아 둔 값은 버려진다(다시 시도하면 새로 받는다) — '불러오는 중' 에 멈추지 않는다. 어느 쪽이든 진단 정보에는 코드·시각만 있다.

가져올 수 없는 값은 지어내지 않는다 — 행의 검색량·문서 수·추세는 `데이터 없음`, 요약 카드의 집계 못 한 값은 `–` + `아직 집계하지 않아요`, 블로그 현황의 못 가져온 숫자는 아예 보이지 않는다. 가짜(예시) 데이터일 때만 `예시 데이터` 표시가 붙는다.

## 2. 작업 스레드(`ui/core/jobs.py`) — 화면 스레드를 막지 않는다

| 규칙 | 구현 | 시험 |
|---|---|---|
| 긴 일은 작업 스레드 | `JobRunner.start(key, work, …)` 가 `threading.Thread` 로 돌린다. `work(progress, cancelled)` | 1.2초짜리 불러오기 동안 5ms 타이머가 끊기지 않음(이 구현의 실측: 스레드 최대 176ms — 끝날 때 다시 그리는 시간 포함 — 대 직접 기다리면 1,236ms, 시제품 실측은 38ms 대 1,231ms) |
| 중복 클릭 방지 | 같은 이름의 작업이 돌고 있으면 `None`(새로 시작 안 함) → 화면은 `이미 불러오는 중이에요.` 안내 | 두 번째 `reload()` 거절 |
| 취소 | 협조적 — 작업이 `cancelled()` 를 보고 스스로 멈춘다. 취소를 눌렀으면 **늦게 온 결과도 버리고** '취소'로 알린다 → 보이던 내용 그대로 + `불러오기를 취소했어요. …` | 느린 불러오기 취소·늦은 결과 버림 |
| 실패해도 입력 보존 | 실패·취소 콜백이 시작할 때의 입력(`payload`)을 그대로 돌려준다. 오류 상태에서도 이전 데이터는 지우지 않는다 | 실패 뒤 데이터·입력 그대로 |
| 기술 문구를 내지 않음 | 예기치 못한 오류는 `작업을 마치지 못했어요. 입력한 내용은 그대로 남아 있어요.` + 예외 **이름**(진단용)만, 서비스 오류는 오류 코드 표의 문장 | 예외 글이 문구·코드에 새지 않음 |
| 콜백 | 작업 스레드에서 불린다 → `ui/qt/workers.py` 가 Qt 시그널로 화면 스레드에 넘긴다. 콜백이 예외를 내도 작업은 멈추지 않고 예외 이름만 남긴다. 끝난 뒤(콜백 안)에는 같은 작업을 다시 시작할 수 있다 | 화면 스레드에서 받음 |
| 작업이 `SystemExit` 로 끝남 | 예전에는 영원히 running 으로 남아 다시 불러오기가 막혔다 — 이제 어떤 종료도 '실패' 로 알리고 끝난 것으로 친다(입력 보존, 쉬운 안내 + 예외 이름) | `SystemExit`·`KeyboardInterrupt` 로 끝난 작업이 실패로 알려지고 다시 시작됨 |
| 화면 스레드 슬롯의 예외 | 결과를 받는 슬롯(`_on_loaded`·`_on_failed`·`_on_cancelled`) 안에서 난 예외는 `AppShell._guarded` 가 잡아 오류 상태로 바꾸고(오류 화면마저 못 그리면 안내만) 원인을 한 줄(예외 이름 + 가리고 경로를 지운 글, `report_unexpected`)로 표준 오류에 남긴다 — 조용한 실패가 아니다. 그 밖의 처리 못한 예외는 `sys.excepthook` 이 같은 한 줄만 표준 오류에 남긴다 | 이상한 데이터가 와도 오류 화면·회복, 훅의 한 줄에 키·경로·추적 없음 |
| 취소가 늦게 먹을 때 | 실제 서비스 어댑터는 단계 사이(후보 읽기 뒤·글 목록 읽기 뒤)에만 취소를 확인한다 — 한 단계가 도는 동안은 끊지 못하고 끝난 결과를 버린다. 그래서 **화면은 취소를 누르는 즉시** 보이던 모습으로 돌아가고(일이 아직 돌고 있어도 — 몇 초 동안 '불러오는 중' 에 멈춰 있지 않는다) 그동안 `다시 불러오기` 는 `이미 불러오는 중이에요.` 안내만 한다 | 끊을 수 없는 일의 취소(화면이 바로 풀리고 늦은 결과는 버려짐)·단계 사이 취소 |
| 창을 닫을 때 | 창을 먼저 숨기고(멈춘 창처럼 보이지 않게) 돌고 있는 작업을 취소한 뒤 최대 1초 기다린다 | 닫으면 작업이 멈춤·기다리기 전에 숨김 |

화면을 다시 그리는 데 드는 시간(전체 페이지를 새로 만드는 방식)은 별개다 — 실측은 [`UI_VISUAL_QA.md`](UI_VISUAL_QA.md) §4.

## 3. 안내(토스트)

한 번에 하나, 3.5초, **같은 안내가 또 오면 쌓지 않고 보이는 시간만 늘린다**(다른 안내는 그 자리를 바꾼다). 120자를 넘으면 줄인다. 아직 없는 기능은 `'초안 만들기' 은(는) 다음 단계에서 열려요.` 한 가지 모양으로 알린다 — 동작하는 척하지 않는다.

## 4. 아직 없는 화면

사이드바의 주제 후보·초안 작성·발행 기록·블로그 관리·설정은 `이 화면은 아직 만들고 있어요.` 안내와 `홈으로` 단추만 있다(다음 묶음에서 만든다).
