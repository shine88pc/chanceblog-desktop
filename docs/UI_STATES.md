# 화면 상태와 작업 스레드 (PySide6)

> 홈은 여섯 상태 중 하나다(`ui/core/app_state.py` 의 `LIST_STATES`) — 설정 화면(§5)도 같은 여섯 틀을 쓰고, 홈의 새 구역(§7)은 그 안에서 구역마다 따로 상태를 가진다. 상태는 뷰모델이 정하고 화면은 그리기만 한다. 기술 오류(영문 코드·HTTP 번호·예외 이름·경로·스택 트레이스)는 기본 화면에 나가지 않는다 — 접어 둔 **진단 정보**에만(오류 코드와 시각뿐, 비밀 모양은 가림). 값은 [`UI_DESIGN_SPEC.md`](UI_DESIGN_SPEC.md), 부품은 [`UI_COMPONENTS.md`](UI_COMPONENTS.md).

## 1. 홈의 여섯 상태

| 상태 | 언제 | 화면 | 다음 행동 |
|---|---|---|---|
| `normal` 정상 | 옛 후보 저장소에 후보가 있음 | KPI 넷 + Naver A·B 추천(각 최대 5줄) + 작성 중 초안·최근 발행 + 연결 상태 한 줄 — 구역마다 따로 상태(§7) | 추천 줄 누르기(Enter·Space) = 상세 서랍 |
| `loading` 불러오는 중 | 후보를 가져오는 동안 | 구역 자리에 줄 모양 자리 표시 4줄(움직이지 않음) + `후보를 불러오고 있어요…` + `불러오기 취소`. 다시 불러오기 단추는 꺼짐, 첫 불러오기이면 KPI 는 `집계 전` | 기다림·취소 |
| `empty` 빈 화면 | 옛 후보 저장소에 후보가 없음 | 홈의 추천은 주제 엔진 보관함에서 오므로 화면은 `normal` 과 같다 — 구역마다 자기 상태를 그린다(후보가 없으면 `아직 추천할 후보가 없어요.` 같은 **정상 빈 상태**, 쓰기 단추 없음 — 빈 상태의 `주제 분석 시작` 은 없앴다) | 계속 사용 |
| `error` 오류 | 홈 데이터를 통째로 못 가져옴 | KPI·제목은 그대로 + 구역 자리에 오류 카드 하나 — 위험 색 아이콘 + 한 줄 원인(오류 코드 표의 쉬운 문장) + **`다시 시도`** + 접어 둔 `진단 정보 보기`(고정폭 글꼴: 오류 코드·시각) | 단추. 이전에 받은 데이터는 지우지 않는다 |
| `partial` 일부만 | 일부 지표(예: 추세)만 실패 | 위에 안내 띠 `검색 추세는 불러오지 못했지만 나머지 정보는 그대로 쓸 수 있어요.` + 줄은 그대로(못 가져온 관심도는 `관심도 데이터 부족`) — 화면을 막지 않는다 | 계속 사용 |
| `offline` 오프라인 | 저장해 둔 값으로 보여 주는 중 | 위에 안내 띠 `오프라인 상태예요. 저장해 둔 초안은 계속 고칠 수 있어요.` | 계속 사용 |

**오류 상태가 되는 길**: ① 서비스 층 오류(오류 코드 표의 쉬운 문장 — 읽기만 하는 화면이라 '저장하지 못했습니다' 류는 `데이터 폴더를 읽지 못했어요. …` 로 바꾼다) ② 직접 정한 `--data-dir` 가 없거나 파일이면 `지정한 데이터 폴더를 찾지 못했어요. 폴더 이름을 확인한 뒤 다시 열어 주세요.`(빈 화면이 아니다 — 기본 위치는 아직 없어도 오류가 아니라 빈 화면이다) ③ 화면 스레드의 결과 슬롯 안에서 예기치 못한 예외(이상한 데이터 등)가 나면 `작업을 마치지 못했어요. 입력한 내용은 그대로 남아 있어요.` + 진단 정보의 예외 **이름**뿐이고, 받아 둔 값은 버려진다(다시 시도하면 새로 받는다) — '불러오는 중' 에 멈추지 않는다. 어느 쪽이든 진단 정보에는 코드·시각만 있다.

가져올 수 없는 값은 지어내지 않는다 — 추천 줄의 점수는 `점수 계산 전`·관심도는 `관심도 데이터 부족`(상세 서랍의 값 없는 칸은 `데이터 없음`), KPI 의 모르는 값은 `연결 전`·`집계 전`(0 이 아니다). 월 검색량·문서 수는 가져오지도 보이지도 않는다. 가짜(예시) 데이터일 때만 `예시 데이터` 표시와 줄마다 `예시` 꼬리표가 붙는다.

## 2. 작업 스레드(`ui/core/jobs.py`) — 화면 스레드를 막지 않는다

| 규칙 | 구현 | 시험 |
|---|---|---|
| 긴 일은 작업 스레드 | `JobRunner.start(key, work, …)` 가 `threading.Thread` 로 돌린다. `work(progress, cancelled)` | 1.2초짜리 불러오기 동안 5ms 타이머가 끊기지 않음(이 구현의 실측: 스레드 최대 176ms — 끝날 때 다시 그리는 시간 포함 — 대 직접 기다리면 1,236ms, 시제품 실측은 38ms 대 1,231ms) |
| 중복 클릭 방지 | 같은 이름의 작업이 돌고 있으면 `None`(새로 시작 안 함) → 화면은 `이미 불러오는 중이에요.` 안내 | 두 번째 `reload()` 거절 |
| 취소 | 협조적 — 작업이 `cancelled()` 를 보고 스스로 멈춘다. 취소를 눌렀으면 **늦게 온 결과도 버리고** '취소'로 알린다 → 보이던 내용 그대로 + `불러오기를 취소했어요. …` | 느린 불러오기 취소·늦은 결과 버림 |
| 실패해도 입력 보존 | 실패·취소 콜백이 시작할 때의 입력(`payload`)을 그대로 돌려준다. 오류 상태에서도 이전 데이터는 지우지 않는다 | 실패 뒤 데이터·입력 그대로 |
| 기술 문구를 내지 않음 | 예기치 못한 오류는 `작업을 마치지 못했어요. 입력한 내용은 그대로 남아 있어요.` + 예외 **이름**(진단용)만, 서비스 오류는 오류 코드 표의 문장 | 예외 글이 문구·코드에 새지 않음 |
| 콜백 | 작업 스레드에서 불린다 → `ui/qt/workers.py` 가 Qt 시그널로 화면 스레드에 넘긴다. 콜백이 예외를 내도 작업은 멈추지 않고 예외 이름만 남긴다. 끝난 뒤(콜백 안)에는 같은 작업을 다시 시작할 수 있다 | 화면 스레드에서 받음 |
| 작업이 `SystemExit` 로 끝남 | 예전에는 영원히 running 으로 남아 다시 불러오기가 막혔다 — 이제 어떤 종료도 '실패' 로 알리고 끝난 것으로 친다(입력 보존, 쉬운 안내 + 예외 이름) | `SystemExit`·`KeyboardInterrupt` 로 끝난 작업이 실패로 알려지고 다시 시작됨 |
| 화면 스레드 슬롯의 예외 | 결과를 받는 슬롯(`_on_loaded`·`_on_failed`·`_on_cancelled`) 안에서 난 예외는 `AppShell._guarded` 가 잡아 오류 상태로 바꾸고(오류 화면마저 못 그리면 안내만) 원인을 한 줄(예외 이름 + 가리고 경로를 지운 글, `report_unexpected`)로 표준 오류에 남긴다 — 조용한 실패가 아니다(**콘솔 실행 기준**: `pythonw`·창 없는 exe 처럼 표준 오류가 없는 실행에서는 어디에도 남지 않는다 — `report_unexpected` 가 `False` 를 돌려주고 화면에는 쉬운 안내만 보인다. 로그 파일은 설치 파일 묶음에서 정하고 이 묶음은 파일을 쓰지 않는다). 경로 지우기는 공백이 든 경로(`Jane Doe`·`Program Files`)도 반쪽만 지우지 않는다 — 드라이브·네트워크·유닉스식·`~` 경로를 따옴표로 열었으면 짝이 되는 따옴표 앞까지, 아니면 그 줄 끝까지 통째로 지운다(주소·날짜·`</p>` 는 그대로). 그 밖의 처리 못한 예외는 `sys.excepthook` 이 같은 한 줄만 표준 오류에 남긴다 | 이상한 데이터가 와도 오류 화면·회복, 훅의 한 줄에 키·경로·추적 없음 |
| 취소가 늦게 먹을 때 | 실제 서비스 어댑터는 단계 사이(후보 읽기 뒤·글 목록 읽기 뒤·홈의 새 구역을 읽는 사이마다 — 최근 발행은 글 사이마다)에만 취소를 확인한다 — 한 단계가 도는 동안은 끊지 못하고 끝난 결과를 버린다. 그래서 **화면은 취소를 누르는 즉시** 보이던 모습으로 돌아가고(일이 아직 돌고 있어도 — 몇 초 동안 '불러오는 중' 에 멈춰 있지 않는다) 그동안 `다시 불러오기` 는 `이미 불러오는 중이에요.` 안내만 한다. 일이 나중에 끝나며 보내는 **늦은 취소 신호는 무시**한다(같은 `불러오기를 취소했어요` 안내와 다시 그리기를 두 번 하지 않는다 — 예전에는 5초 일이면 5초 뒤에 안내가 다시 떴다) | 끊을 수 없는 일의 취소(화면이 바로 풀리고 늦은 결과는 버려짐)·단계 사이 취소 |
| 창을 닫을 때 | 창을 먼저 숨기고(멈춘 창처럼 보이지 않게) 돌고 있는 작업을 취소한 뒤 최대 1초 기다린다 | 닫으면 작업이 멈춤·기다리기 전에 숨김 |

화면을 다시 그리는 데 드는 시간(전체 페이지를 새로 만드는 방식)은 별개다 — 실측은 [`UI_VISUAL_QA.md`](UI_VISUAL_QA.md) §4.

## 3. 안내(토스트)

한 번에 하나, 3.5초, **같은 안내가 또 오면 쌓지 않고 보이는 시간만 늘린다**(다른 안내는 그 자리를 바꾼다). 120자를 넘으면 줄인다. 아직 없는 기능은 `'초안 만들기' 은(는) 다음 단계에서 열려요.` 한 가지 모양으로 알린다 — 동작하는 척하지 않는다.

## 4. 아직 없는 화면

사이드바의 실제 메뉴는 **완성된 화면(홈·주제 후보·초안 작성·Seed 관리·블로그 관리·설정)뿐**이다. 아직 만들지 않은 화면(발행 기록)은 메뉴가 아니라 '다음 단계' 목록에 이름만 있고(클릭 불가·Tab 제외·`준비 중` 배지) **열 수 없다** — 옛 `이 화면은 아직 만들고 있어요.` 자리표시 화면과 `홈으로` 단추는 없앴다(UI-C1a, D-172). 설정은 P4a 가 새 화면으로 만들었고(아래 §5, 결정 D-90) 블로그 관리는 P4b 가, 주제 후보는 P4d 가, 초안 작성은 P4e 가 만들었다(아래 §5-2·§5-5·§5-6, 결정 D-210·D-270·D-280~D-289). 어느 메뉴가 어느 화면인지는 `ui/qt/screens.py` 의 `SCREEN_BUILDERS` 표 한 곳이 정하고, 표의 열쇠는 실제 메뉴와 같다(시험이 지킨다).

## 5. 설정 화면(연결 관리)의 상태 — 홈과 같은 여섯 틀

설정 화면도 여섯 상태 중 하나다(`AppState.conn_state` — 홈의 `list_state` 와 따로). 상태는 뷰모델(`ui/core/settings_view.py`)이 정하고 화면은 그리기만 한다. 기술 오류(영문 코드·예외 이름·경로)는 기본 화면에 나가지 않는다 — 접어 둔 **진단 정보**에만.

| 상태 | 언제 | 화면 | 다음 행동 |
|---|---|---|---|
| `normal` 정상 | 용도를 읽었음 | 접이식 다섯 묶음(머리 한 줄 + 요약 칩 — 마지막 '정보' 묶음은 칩 없이 버전 + 접어 둔 진단 정보, 늘 접힌 채 시작) + 용도 카드(사용량은 기간마다 막대 한 줄) + 안내 한 줄 | 머리를 눌러 펴고 접기·`연결 상태 다시 읽기` |
| `loading` 불러오는 중 | 처음 읽는 동안·오류 뒤 다시 읽는 동안(이미 보이는 내용이 있으면 그대로 두고 새 값이 오면 바꾼다) | 줄 모양 자리 표시 3줄 + `연결 상태를 읽고 있어요…`. 새로 읽기 단추는 꺼짐. **취소 단추는 없다**(이 PC 의 파일·보관소만 읽는 짧은 일 — 창을 닫으면 읽기도 취소된다) | 기다림 |
| `empty` 빈 화면 | 보여 줄 용도가 하나도 없음 | 아이콘 + `보여 드릴 연결 정보가 없어요.` + `다시 읽기` | 단추 |
| `error` 오류 | 연결 설정 파일이 깨졌거나 데이터 폴더를 쓸 수 없음 | 위험 색 아이콘 + 한 줄 원인(명령 없는 화면 문장) + `다시 시도` + 접어 둔 `진단 정보 보기`(오류 코드·시각만). 파일은 고치거나 지우지 않는다 | 단추 |
| `partial` 일부만 | 키 보관소를 못 열었거나 사용량 기록을 못 읽음 | 위에 안내 띠(하나 또는 둘) — 키가 있는지 모르는 항목은 `연결 확인 필요`, 못 읽은 사용량 줄은 막대 없이 `확인할 수 없어요` 글만(빈 막대도 없다 — 0% 로 읽히므로) | 계속 사용 |
| `offline` 오프라인 | 예시 데이터에서만(실제 읽기는 네트워크를 쓰지 않아 만들지 않는다) | 위에 안내 띠 `오프라인 상태예요. 이 PC 에 저장해 둔 정보만 보여 드려요.` | 계속 사용 |

**읽는 방법**: 설정 화면은 열 때마다 읽는다(`go("settings")`) — 앱이 열릴 때도 홈의 연결 한 줄을 채우려고 같은 읽기를 한 번 돌린다(D-203, 이미 읽는 중이면 또 시작하지 않는다). 읽기는 작업 이름 `settings-load` 로 작업 스레드에서 돌고(보관소 읽기 포함, 홈 불러오기와 서로 막지 않는다) 결과는 시그널로 화면 스레드에 온다. 읽는 중에 다른 화면으로 가면 값만 받아 두고 그 화면은 다시 그리지 않는다. 슬롯에서 예외가 나면 '읽는 중' 에 멈추지 않고 오류 상태가 된다(`작업을 마치지 못했어요. …` + 진단 정보의 예외 이름뿐). 진단 정보는 정상일 때 읽은 시각·용도 수·항목 수·보관소·사용량 읽기 성공 여부이고(접힌 '정보' 묶음 안에서 `진단 정보 보기` 로 연다), 항목 이름·키 값·끝 4자는 어디에도 없다.

## 5-2. 블로그 관리 화면의 상태 (P4b) — 읽기 세 상태와 쓰기 동작의 결과

읽기 상태는 홈·설정과 같은 틀의 일부다(`AppState.blogs.state` — 따로 돈다): `loading`·`normal`·`error`(빈·일부만·오프라인은 이 화면에 없다 — 슬롯이 비면 정상 상태의 '등록' 카드다). 상태는 뷰모델(`ui/core/blogs_view.py`)이 정하고 화면은 그리기만 한다. 영문 코드·예외 이름·경로·파이썬 목록은 기본 화면에 나가지 않는다 — 접어 둔 **진단 정보**에만(코드·시각).

| 상태 | 언제 | 화면 | 다음 행동 |
|---|---|---|---|
| `normal` 정상 | 프로필 다섯 슬롯을 읽었음. 파일이 아직 없어도 기본 프로필 다섯으로 정상이고 안내 띠가 한 줄 붙는다(`아직 저장한 블로그 정보가 없어요. 처음 저장하면 이 PC 의 데이터 폴더에 파일이 만들어져요.`) | 슬롯 카드 다섯 + 폼 + 아래 고정 행동 줄 | 고르기·고치기·저장·복제·삭제 |
| `loading` 읽는 중 | 화면을 열 때마다·`새로 읽기`·낡은 판이 감지돼 다시 읽을 때(이미 보이는 내용이 있으면 그대로 두고 새 값이 오면 바꾼다). 쓰는 중에는 읽지 않는다 | 줄 모양 자리 표시 3줄 + `블로그 정보를 읽고 있어요…`. 새로 읽기 단추는 꺼짐 | 기다림 |
| `error` 읽기 오류 | 프로필 파일이 깨졌거나 읽을 수 없음 | **폼 없이** 위험 색 아이콘 + `블로그 정보를 읽지 못했어요.` + `프로필 파일은 고치거나 지우지 않았어요 …` + `다시 읽기` + 접어 둔 진단 정보(코드·시각) — 틀린 파일 위에 쓸 길이 없다 | 단추 |

**쓰기 동작(저장·복제·삭제)**: 누르면 작업 이름 `blogs-write` 로 작업 스레드에서 돈다(읽기 `blogs-load` 와 따로). 도는 동안 모든 칸·단추가 꺼지고 `저장하는 중이에요…` 가 보이며 두 번째 클릭·새로 읽기·슬롯 고르기는 아무 일도 하지 않는다. 끝나면 결과를 알림 줄로 알린다(입력은 실패해도 그대로 남는다):

| 결과 | 알림 줄 | 입력 |
|---|---|---|
| 저장·복제·삭제 성공 | 초록 `저장했어요.`·`복제했어요 …`·`프로필을 지웠어요. 슬롯은 비어 있는 상태예요.` | 그 슬롯의 초안을 비운다(복제는 새 슬롯을 선택) |
| 바뀐 것 없음 | 파랑 `바뀐 내용이 없어요.` | — |
| 틀린 값(저장 전 검사) | 빨강 `입력한 값 중에 확인할 곳이 있어요. 표시된 칸을 고쳐 주세요.` — **서비스를 부르지 않는다**. 문제 칸 옆 문장 + 첫 문제 칸으로 포커스. 우선·제외 키워드에 같은 낱말이 있으면(P4c) **두 칸 모두** 옆에 `제외 키워드에도 있는 낱말이 있어요. 한쪽에서만 적어 주세요.`/`우선 키워드에도 …` (고친 칸에 먼저, 저장을 시도하면 둘 다 — 입력한 낱말은 되풀이하지 않는다) | 그대로 |
| 서비스가 거절(틀린 값·키 모양·키워드 겹침) | 같은 문장 + 거절한 칸 옆 문장(그 칸을 다시 고치면 지운다 — 겹침은 두 칸 모두에 붙는다) | 그대로 |
| 낡은 판(다른 곳이 먼저 저장) | 빨강 → 곧바로 최신 내용을 읽는다(읽기만) → 노랑 `다른 곳에서 바뀐 내용을 다시 불러왔어요. 입력한 내용은 그대로 두었어요. 확인한 뒤 다시 저장해 주세요.` — **자동으로 다시 저장하지 않는다** | 그대로 |
| 다른 창이 잠금 중·읽기 전용·디스크 가득·파일 손상 | 빨강 — 종류마다 정해진 쉬운 문장(파이썬 오류 글 없음) | 그대로 |

창을 닫을 때 쓰기가 돌고 있으면 끝나기를 최대 10초 기다린다. 화면 스레드의 슬롯에서 예외가 나면(읽기·쓰기 모두) 받아 둔 값을 버리고 쉬운 문장(`작업을 마치지 못했어요. …`)과 진단 정보의 예외 이름뿐이며 입력한 초안은 남긴다. 슬롯 선택·고친 입력은 앱이 열려 있는 동안 메모리에만 있다(디스크에 쓰지 않는다).

## 5-3. Seed 관리 화면의 상태 (Seed 관리) — 읽기 세 상태와 쓰기 동작의 결과

읽기 상태는 홈·설정·블로그 관리와 같은 틀의 일부다(`AppState.seeds.state` — 따로 돈다): `loading`·`normal`·`error`(빈 목록은 정상 상태의 안내 카드다). 상태는 뷰모델(`ui/core/seeds_view.py`)이 정하고 화면은 그리기만 한다. 영문 코드·예외 이름·경로·파이썬 목록은 기본 화면에 나가지 않는다 — 접어 둔 **진단 정보**에만(코드·시각).

| 상태 | 언제 | 화면 | 다음 행동 |
|---|---|---|---|
| `normal` 정상 | Seed 를 읽었음. 파일이 아직 없어도 빈 목록으로 정상이고 안내 띠가 한 줄 붙는다(`아직 저장한 Seed 가 없어요. …`) | 개수 요약 카드 + Seed 줄 목록(없으면 `아직 Seed 가 없어요.` 안내 카드 — `제안 파일 불러오기` 를 알린다) | 거르기·고르기·서랍·승인·바꾸기·등록·불러오기 |
| `loading` 읽는 중 | 화면을 열 때마다·`다시 읽기`·낡은 판이 감지돼 다시 읽을 때(이미 보이는 내용이 있으면 그대로 두고 새 값이 오면 바꾼다). 쓰는 중에는 읽지 않는다 | 줄 모양 자리 표시 3줄 + `Seed 를 읽고 있어요…`. 다시 읽기·쓰는 단추는 꺼짐 | 기다림 |
| `error` 읽기 오류 | `seeds.json` 이 깨졌거나(글자·JSON·모양이 틀림) 읽을 수 없음 | **목록·서랍 없이** 위험 색 아이콘 + `Seed 를 읽지 못했어요.` + `Seed 파일은 고치거나 지우지 않았어요 …` + `다시 읽기` + 접어 둔 진단 정보(코드·시각). 등록·불러오기 단추는 꺼진다 — 틀린 파일 위에 쓸 길이 없다 | 단추 |

**쓰기 동작(승인·바꾸기·저장·등록·불러오기)**: 누르면 작업 이름 `seeds-write` 로 작업 스레드에서 돈다(읽기 `seeds-load` 와 따로). 도는 동안 모든 칸·단추가 꺼지고 `저장하는 중이에요…` 가 보이며 두 번째 클릭·다시 읽기는 아무 일도 하지 않는다. 끝나면 결과를 알림 줄로 알린다(입력은 실패해도 그대로 남는다):

| 결과 | 알림 줄 | 입력 |
|---|---|---|
| 승인·쉬게 하기·다시 쓰기·일괄 바꾸기·저장·등록·불러오기 성공 | 초록(`승인했어요. 이제 후보 생성에 쓰여요.`·`쉬게 했어요. 후보 생성에서 빠져요.`·`다시 쓰기로 했어요.`·`N개를 사용 중으로 바꿨어요.`·`저장했어요.`·`승인 전 Seed 로 등록했어요 …`·`N개를 승인 전 Seed 로 등록했어요 …`) | 그 씨앗의 초안을 비운다(등록은 새 씨앗의 서랍이 열린다, 불러오기는 `승인 전` 으로 거른다) |
| 바뀐 것 없음 | 파랑 `바뀐 내용이 없어요.` | — |
| 틀린 값(저장 전 검사) | 빨강 `입력한 값 중에 확인할 곳이 있어요. 표시된 칸을 고쳐 주세요.` — **서비스를 부르지 않는다**. 문제 칸 옆 문장 + 첫 문제 칸으로 포커스 | 그대로 |
| 서비스가 거절(틀린 값·키 모양) | 같은 문장 + 거절한 칸 옆 문장(그 칸을 다시 고치면 지운다) | 그대로 |
| 낡은 판(다른 곳이 먼저 저장) | 빨강 `다른 곳에서 먼저 바뀌었어요 …` → 곧바로 최신 내용을 읽는다(읽기만) → 노랑 `다른 곳에서 바뀐 내용을 다시 불러왔어요. 입력한 내용은 그대로 두었어요. 확인한 뒤 다시 해 주세요.` — **자동으로 다시 저장하지 않는다** | 그대로 |
| 다른 창이 잠금 중·읽기 전용·디스크 가득·파일 손상 | 빨강 — 종류마다 정해진 쉬운 문장(파이썬 오류 글 없음) | 그대로 |
| 확인창에서 취소·Esc | 아무 일 없음(확인창을 보였다는 표시도 거둔다 — 다시 부르는 길도 막혀 있다) | 고른 상자는 그대로 |

## 5-4. 키 연결의 상태 (P4f) — 쓰기와 그 결과

설정 화면의 읽기 여섯 틀(§5)은 그대로이고, 키 행동은 **쓰기 동작**의 상태를 따로 가진다(`KeysController` — 비밀이 아닌 값만).

| 상태 | 화면 | 단추 |
|---|---|---|
| 쓰기 없음 | 평소 모습 | 켜질 수 있는 단추만 켜짐 |
| 쓰는 중(`keys-write` 작업) + 쓴 뒤 새 값을 읽는 중 | 위쪽 안내 띠 `저장하는 중이에요…` | **모두 꺼짐**(`연결 상태 다시 읽기` 포함)·두 번째 클릭은 아무 일도 하지 않음(통은 비워짐) |
| 성공 | 안내 띠 `키를 저장했어요 …`/`키를 지웠어요`/`키 사용 설정을 바꿨어요`/`별칭을 바꿨어요`/`우선순위를 바꿨어요`, 연결 시험은 그 행의 글(`연결을 확인했어요` …) | 새 값을 읽은 뒤 켜짐, 포커스는 방금 누른 단추 근처로 |
| 실패 | 안내 띠에 쉬운 문장(종류별: 한도·중복·입력 모양·약관·보관소·없음·잠금·디스크·쓰기 실패·파일 이상·정리 실패 — 키를 새로 넣는 일이 아니면 `키는 다시 입력해 주세요` 가 빠진다) — 서비스 오류의 세부·경로·코드·입력한 값은 없다. 고칠 수 있는 입력 문제는 대화상자를 다시 열어 칸 옆에. **삭제 도중의 저장 실패**(쓰기 실패·디스크)는 키 저장소의 키가 이미 지워졌는지 오류 종류만으로는 알 수 없어 `바뀐 것은 없어요` 대신 어느 쪽이어도 참인 따로 정한 문장(`키가 이미 지워졌을 수도 있어서 목록을 다시 읽어 드릴게요 …`)이다(독립 검증 M1) | 입력(별칭)은 남고 키만 다시 입력, 이미 지워졌거나 파일이 이상하거나 삭제 도중 저장이 실패하면 다시 읽음(키가 이미 지워졌다면 그 행이 `보관소에서 이 키를 찾지 못했어요` 로 보이고 `삭제` 를 한 번 더 누르면 정리됨) |
| 키 저장소를 못 씀 | 카드에 `이 컴퓨터에서는 키 저장소를 쓸 수 없어요.` + 이유(상태이지 오류가 아니다) | 등록·삭제·별칭·시험 꺼짐(파일만 바꾸는 상태·순서는 켜짐) |
| 키 없음 | `연결 안 됨 — 키 없이도 쓸 수 있어요` | `키 등록` 켜짐 |

## 5-5. 주제 후보 화면의 상태 (P4d) — 읽기 상태와 후보 만들기의 결과

읽기 상태는 홈·설정·블로그 관리·Seed 관리와 같은 틀의 일부다(`AppState.candidates.state` — 따로 돈다): `loading`·`normal`·`error`(빈 목록은 정상 상태의 안내 카드다). 상태는 뷰모델(`ui/core/candidates_view.py`)이 정하고 화면은 그리기만 한다. 영문 코드·예외 이름·경로·파이썬 목록은 기본 화면에 나가지 않는다 — 접어 둔 **진단 정보**에만(코드·시각).

| 상태 | 언제 | 화면 | 다음 행동 |
|---|---|---|---|
| `normal` 정상 | 후보를 읽었음 | 거르기 카드 + 카드 격자(24장씩) + 고정 상세 창(창 논리 폭 1366 이상 — 안 골랐으면 `후보를 골라 보세요`)·서랍(그보다 좁을 때) | 거르기·찾기·고르기·`후보 만들기`·다시 읽기 |
| `loading` 읽는 중 | 화면을 열 때마다·`다시 읽기`·후보를 만든 뒤(이미 보이는 내용이 있으면 그대로 두고 새 값이 오면 바꾼다). 만드는 중에는 읽지 않는다 | 줄 모양 자리 표시 3줄 + `후보를 읽고 있어요…`. `후보 만들기`·다시 읽기는 꺼짐(이유는 툴팁), 고정 상세 창 없음 | 기다림 |
| `error` 읽기 오류 | 보관함이 깨졌거나(더 새로운 판·열 수 없음) 읽을 수 없음 | **카드 격자·거르기 카드·상세 창 없이** 위험 색 아이콘 + `후보를 읽지 못했어요.` + `후보 보관함은 고치거나 지우지 않았어요 …` + `다시 읽기` + 접어 둔 진단 정보(코드·시각). `후보 만들기` 는 꺼진다 — 읽지 못한 보관함 위에 쓸 길이 없다 | 단추 |

**빈 목록 다섯**(정상 상태의 안내 카드 — 서로 다른 안내이고 주요 단추를 더하지 않는다. 주요 행동은 머리의 `후보 만들기` 하나다. 후보가 하나도 없는 넷은 거르기 카드도 고정 상세 창도 없다):

| 종류 | 언제 | 제목 | 다음 행동 |
|---|---|---|---|
| 보관함 없음 | 후보 보관함 파일이 아직 없거나 0바이트 | `후보를 보관하는 파일이 아직 없어요.` — 이 화면은 읽기만 해서 새로 만들지 않았다는 설명(내 데이터이면 위에 파랑 안내 한 줄도) | 머리의 `후보 만들기`(확인창에서 처음 한 번 만드는 단계를 말한다) |
| 옛 구조 | 보관함이 옛 판 | `후보 보관함이 옛 구조라 읽지 않았어요.` — 읽기만 해서 바꾸지 않았고 `후보 만들기` 를 하면 새 구조로 올리고 옛 모양 사본을 남긴다는 설명 | 머리의 `후보 만들기` |
| 후보 없음 | 보관함은 있는데 후보가 없음 | `아직 후보가 없어요.` | 머리의 `후보 만들기`(승인한 Seed 가 있으면) |
| 점수를 못 믿어 모두 뺌 | 저장된 후보가 모두 채널 가중치로 다시 계산한 점수와 달라 빠짐 | `보여 줄 수 있는 후보가 없어요.` — 블로그 관리의 채널 가중치를 확인하라는 설명 | 블로그 관리 확인 |
| 거른 결과 없음 | 후보는 있는데 거르기·검색에 맞는 것이 없음 | `조건에 맞는 후보가 없어요. 거르기를 풀어 보세요.` + 보조 단추 `거르기 풀기` | 거르기 풀기 |

**후보 만들기의 단계와 결과**: 미리 보기(서비스 `plan_candidates` — 읽기뿐, 작업 이름 `candidates-write` 로 작업 스레드에서 돈다)가 끝나면 새 후보가 있을 때만 확인창이 뜬다. `만들기` 를 누르면 같은 작업 이름으로 쓰기가 한 번 돈다(읽기 `candidates-load` 와 따로). 도는 동안 `후보 만들기`·다시 읽기가 꺼지고 `후보를 만드는 중이에요…` 가 보이며 두 번째 요청은 아무 일도 하지 않는다. 끝나면 결과를 알림 줄로 알리고 목록을 다시 읽는다(읽기만):

| 결과 | 알림 줄 | 목록 |
|---|---|---|
| 미리 보기 — 새 후보 있음 | (알림 없음) 확인창이 뜬다 | 그대로 |
| 미리 보기 — 만들 수 없음 | 준비 안내 카드(무엇이 모자란지·`Seed 관리 열기`·`블로그 관리 열기`·`닫기`) — 확인창 없음 | 그대로 |
| 미리 보기 — 실패 | 빨강 `만들 후보를 미리 보지 못했어요. 아무것도 바뀌지 않았어요.`(또는 종류별 문장) | 그대로 |
| 확인창에서 취소·Esc·취소 위의 Enter | 아무 일 없음(확인창을 보였다는 표시도 거둔다 — 다시 부르는 길도 막혀 있다. 열린 확인창이 다른 대화상자로 바뀔 때도 마찬가지다 — 결정 D-277 ⑦) | 그대로 |
| 만들기 성공 | 초록 `후보 N개를 만들었어요.`(+ 같은 후보 건너뜀·키 모양 글이 든 후보는 저장하지 않음 안내) → 목록을 다시 읽는다 | 후보가 지워지지 않고 **더해진다** |
| 새로 만든 후보 없음 | `새로 만든 후보가 없어요.` | 그대로 |
| 만들기 실패 — 다른 창이 보관함을 씀 | 빨강 `다른 창에서 후보 보관함을 쓰고 있어서 만들지 못했어요 …` | 그대로(바이트 같음) |
| 저장 공간 부족·읽기 전용·더 새로운 판·깨진 파일·설정 파일을 읽지 못함·그 밖 | 빨강 — 종류마다 정해진 쉬운 문장(`cand_fail_disk`·`io`·`newer`·`corrupt`·`invalid`·`other`)이고 오류 원문·경로·입력한 글은 없다 | 그대로(바이트 같음) |

**남긴 한계 — 쓰다가 프로세스가 죽은 뒤**(독립 검증 중간 2, 결정 D-278): 후보를 쓰는 도중(몇 ms) 앱이 강제로 꺼지면 후보 보관함 옆에 저널(`…-journal`)이 남는다. 이 화면의 읽기는 읽기 전용 열기라 그것을 정리하지 못해 읽기 오류(`후보 보관함에 정리하지 못한 저장이 남아 있어 읽지 못했어요. 파일은 바뀌지 않았어요.`)가 되고, 읽기 오류에서는 `후보 만들기` 도 꺼지므로 **이 화면 안에서는 복구하는 길이 없다**(`다시 읽기` 로는 풀리지 않는다). 쓰기로 여는 길은 열면서 저널을 정리하므로 거기서 복구된다(명령줄 `topics init --yes` 한 번 — 오류 도움말이 안내하는 길이고 `-journal` 파일은 지우면 안 된다). 쓰는 시간이 몇 ms 라 확률은 아주 낮다 — 다음 묶음 후보.

## 5-6. 초안 작성 화면의 상태 (P4e) — 만드는 상태와 고치기·복사·떠나기의 결과

상태는 컨트롤러(`ui/core/drafts_view.py` 의 `DraftsController` — `AppState.drafts` 가 들고 있고 다른 화면과 따로 돈다)가 정하고 화면은 그리기만 한다. 초안은 **메모리에만** 있다(저장하지 않는다). 영문 코드·예외 이름·경로·입력한 글은 기본 화면에 나가지 않고 접어 둔 **진단 정보**에만(코드·시각) 있다.

| 상태 | 언제 | 화면 | 다음 행동 |
|---|---|---|---|
| `empty` 후보 없음 | 메뉴로 열었거나 후보 없이 들어옴 | 상태 카드 `주제 후보에서 후보를 골라 '이 주제로 만들기' 를 눌러 주세요` + `주제 후보로 가기`(머리의 되돌아가기는 없다) | 단추 |
| `loading` 만드는 중 | `이 주제로 만들기`·오류의 `다시 만들기` | 줄 모양 자리 표시 3줄 + `초안을 만드는 중이에요…` + `← 주제 후보`. 두 번째 요청은 아무 일도 하지 않는다 | 기다림(떠나면 작업을 취소한다) |
| `normal` 초안 | 초안을 받음 | 두 칸(또는 한 칸) 화면 + 아래 고정 행동 줄 — [`UI_DESIGN_SPEC.md`](UI_DESIGN_SPEC.md) §4-7 | 고치기·검사·복사·열기·다시 만들기 |
| `refused` 거절 | 안전 판정이 '자동 초안 중지' 인 후보, 또는 네이버 블로그가 아닌 채널의 후보를 코드로 불렀을 때(**서비스·공급자를 부르지 않고** 거절한다 — 단추도 이미 꺼져 있다) | 주황 상태 카드 `이 후보는 초안을 자동으로 만들지 않아요.`(또는 `이 후보는 네이버 블로그용이 아니에요.`) + 까닭 한 줄 + 후보 제목 + `주제 후보로 가기` | 단추 |
| `notfound` 후보 없음 | 보관함에서 그 후보가 없어짐(번호 전체가 같은 후보를 못 찾음) | 상태 카드 `후보를 찾지 못했어요.` + `주제 후보로 가기` | 단추 |
| `error` 오류 | 읽기·파일 오류 등 | 위험 색 상태 카드 `초안을 만들지 못했어요.` + 종류별 고정 문장 + `다시 만들기` + 접어 둔 진단 정보 + `← 주제 후보` | 단추 |

**실패 종류별 문장**(오류 원문·경로·입력한 글은 없다): 파일을 읽지 못함(`io`)·더 새로운 판의 보관함(`newer`)·깨진 파일(`corrupt` — `파일은 고치거나 지우지 않았어요`)·후보 글을 초안에 쓸 수 없음(`invalid`)·보관함에 그 후보가 없음(`notfound`)·그 밖(`other`). 선택 입력의 한 칸이 잘못되면(`option`) 화면은 오류 상태로 가지 않고 이전 초안과 고친 글을 지키며 알림 줄에 `‘칸 이름’ 칸을 다시 확인해 주세요 — 이유` 만 보인다.

**동작과 결과**:

| 동작 | 결과 | 초안·고친 글 |
|---|---|---|
| 만들기 성공 | 초안 화면. 후보가 '제외' 상태면 알림 줄에 `초안만 만들었고 후보 상태는 바꾸지 않았어요`, 다른 블로그로 만들었으면 그 안내 | 새 초안 |
| 다시 만들기(만드는 방법 칸) | 고친 제목·본문이 있으면 먼저 확인창(`고친 내용이 사라져요 — 다시 만들까요?` — 처음 포커스는 취소). 도는 동안(`locked`)에는 제목·본문이 **읽기 전용**이고 제목 후보가 눌리지 않는다(새 초안에 덮여 친 글이 조용히 사라지는 틈을 막는다 — 화면 읽기 프로그램에는 `새 초안을 만드는 동안에는 고칠 수 없어요.` 가 읽힌다). 성공하면 `새 초안을 만들었어요.` 하고 다시 고칠 수 있다 | 새 초안(고친 글은 사라진다 — 확인한 뒤에만) |
| 다시 만들기 실패 | 알림 줄에 실패 이유(종류별 고정 문장) | **이전 초안과 고친 글을 그대로 둔다** |
| 제목 후보 고르기 | 고친 제목이 있으면 확인창 → `제목 바꾸기` 를 눌러야 입력 칸이 바뀐다 | 본문은 그대로 |
| 검사하기 | 검사 카드의 결과(키·토큰 모양 — 걸린 자리 앞부분 포함·건강 효과 단정·확인이 필요한 곳·직접 쓴 글의 건강 낱말·거의 안 고침). 걸린 것이 없을 때의 초록 문구는 본 범위(`경험·방문·가격·날짜·통계 표시와 키 모양, 건강 단정 낱말`)와 `숫자로 말한 효과나 협찬 표시처럼 이 검사가 보지 못하는 것은 직접 확인해 주세요` 를 함께 말한다(D-313). 글을 고치면 `글을 고쳤어요 — 다시 검사해 주세요` | 바뀌지 않는다 |
| 복사 단추 | 관문을 지나면 클립보드에 쓰고 그 단추가 1.8초 동안 `✓ … 복사됨`. 관문이 막으면(키·토큰 모양·건강 효과 단정) 어느 부분이 걸렸는지 앞부분을 짚은 안내창(확인만 — 주소 안의 이름 있는 비밀 인자·웹훅은 글자 없이 `[가림]` 으로 어디서부터인지만 짚는다, D-312. 건강 효과 단정 막음은 효과가 없다고 알리거나 주의를 주는 문장도 막을 수 있고 건너뛰는 단추가 없다 — 문장을 고쳐 쓰면 풀린다, D-313), 확인이 필요하면 확인창(처음 포커스는 취소, `그래도 복사`). 클립보드 실패면 `복사하지 못했어요. 다시 시도해 주세요.` 안내만(복사됨 모양 없음) | 바뀌지 않는다 |
| `네이버 글쓰기 열기` | 주소(`https://blog.naver.com/<아이디>?Redirect=Write`)만 연다. 브라우저를 못 열면 `주소를 열지 못했어요.` | 바뀌지 않는다 |
| 다른 화면으로 가기·`← 주제 후보` | 고친 내용(고친 제목·본문, 반영하지 않은 선택 입력)이 있으면 `고친 내용이 사라져요` 확인창(처음 포커스는 취소 — `그래도 이동`). 없으면 바로 간다 | 가면 지운다 |
| 앱 닫기 | 고친 내용이 있으면 닫기를 막고 확인창(`그래도 닫기`). 없으면 그대로 닫힌다. 윈도가 종료·로그오프하는 중이면 확인창으로 붙잡지 않는다 | 닫으면 사라진다 |
| 창 크기를 1280 경계로 바꿈 | 화면을 다시 그려 칸 수만 바뀐다 | 고친 글·선택 입력·펼침 상태 유지 |
| 만드는 중에 떠남 | 작업을 취소하고, 떠난 뒤 늦게 온 답(다른 후보·중지 후보의 답도)은 버린다 | 지운다 |

## 5-6b. 글 모양 점검 카드의 상태 (N-2) — 경고만 하는 카드

초안 작성 화면 오른쪽 칸의 `검사 결과` 카드 **바로 아래** 카드다(복사 전 관문·검사 카드와 **다른 결과 칸**이다 — 서로의 결과를 읽지 않는다). 상태는 컨트롤러가 정하고(`ui/core/draft_garbage.py` 의 `GarbageTracker` — Qt 도 작업 스레드도 모르는 순수 논리) 화면은 그리기만 한다. 검사는 **`검사하기` 를 눌렀을 때만** 돈다 — 글을 치는 동안(타이머·글 바뀜 신호)이나 복사·화면 그리기에서는 돌지 않는다. 모든 경고는 **복사를 막지 않고** 복사·관문으로 이어지는 단추나 새 확인창도 없으며(있는 단추는 `무시` 계열뿐이다) 글을 고치거나 지우지도 않는다. 색은 안내 파랑(`info`)과 흐린 회색(`muted`)뿐이다(빨강은 막음, 주황은 확인창, 초록은 '안전' 의 뜻이라 쓰지 않는다).

| 상태 | 언제 | 카드 | 단추 |
|---|---|---|---|
| 검사 전(`before`) | 초안이 처음 오거나 새 초안이 왔다 | 회색 `아직 점검하지 않았어요.` | `검사하기` |
| 검사 중(`running`) | `검사하기` 를 누른 뒤 결과가 오기 전 | 회색 `글 모양을 살펴보는 중이에요…` — 이 동안에도 글을 칠 수 있다(글 모양 점검은 작업 스레드에서 돈다 — 같은 단추의 기존 검사 `inspect()` 는 아직 화면 스레드에서 동기로 돈다, D-320 ㉩) | `검사 중…`(꺼짐 — 중복 실행 방지, 끝나면 포커스를 돌려준다) |
| 결과 있음(`found`) | 걸린 것이 있다 | 파랑 `살펴볼 곳이 N건 있어요.` + 종류별 묶음(깨진 문자·보이지 않는 글자·제어 문자·HTML 표시·코드 블록 표시·자리표시·같은 낱말 반복·같은 문장 반복 — 고정 순서)마다 **이유 한 번**과 항목 줄들 — **한 종류에 최대 10건**이고 나머지는 `… 외 N건` 으로 개수만 보인다 | 항목마다 `무시`, 둘 이상이면 `모두 무시(N건)`(숨은 건까지 무시하므로 건수를 적는다) |
| 결과 없음(`clean`) | 걸린 것이 없다 | 회색 `찾지 못했어요 — 이 점검이 보지 못하는 것은 직접 확인해 주세요.`(초록이 아니다 — 모두 안전하다는 말이 아니다) | `검사하기` |
| 모두 무시함 | 보이는 항목이 모두 무시됨 | 회색 `보이는 항목이 없어요 — 무시한 것이 N건 있어요.` | `무시한 N건 다시 보기` |
| 본문이 변경됨(`stale`) | 검사한 뒤 글이 바뀜 — 검사한 제목·본문의 지문(해시)과 지금 글을 견줘 안다 | 결과는 **지우지 않고** 위에 `본문이 변경됨 — 아래는 검사했을 때의 글 기준이에요. 다시 검사해 주세요.`(제목만 바뀌었으면 `제목이 변경됨 — …`). 글이 되돌아 같아지면 사라진다 | 그대로 |
| 너무 길어 건너뜀(`skipped`) | 제목이나 본문이 10만 자를 넘음(복사 관문의 키 모양 검사와 같은 상한) | 회색 `글이 너무 길어(10만 자 넘음) 이번 점검은 건너뛰었어요.` — 조용히 건너뛰지 않는다 | `검사하기` |
| 실패(`failed`) | 규칙이 예외를 냈다(있으면 버그다) | 회색 `점검을 끝내지 못했어요. ‘검사하기’ 를 다시 눌러 주세요.` — 초안 화면은 오류 상태가 되지 않는다 | `검사하기` |

항목 한 줄은 `위치 · 보이는 조각 · 이유 이름` 이다 — 위치는 `본문 3문단 2번째 줄 앞에서 12번째 글자`(문단은 빈 줄로 가른 덩어리, 공백이나 보이지 않는 글자뿐인 줄도 빈 줄이다. 빈 줄 위의 글자는 `본문 2문단 다음 빈 줄 앞에서 1번째 글자`, 제목은 `제목 앞에서 7번째 글자`), 조각은 앞 글 8자(`‘…먹었어요’ 바로 뒤`)와 걸린 글 12자(넘으면 `…`)까지만이고 곁에 키 모양이 있으면 그 자리를 `[가림]` 으로 가린다. 보이지 않는 글자·제어 문자는 글자 대신 이름과 코드(`폭 없는 공백(U+200B) 7개`)를 보이고, 같은 글자(보이지 않는 글자)·같은 표시(코드 블록 표시 줄)는 **한 건으로 묶어** 처음 위치와 `외 N곳` 을 보인다.

**동작과 결과**:

| 동작 | 결과 | 글·복사 |
|---|---|---|
| `검사하기` | 검사 카드는 곧바로, 글 모양 점검은 **작업 스레드**에서 돌아 결과가 따로 채워진다(글의 바뀌지 않는 복사본만 넘기고 걸린 글이 없는 결과 값만 받는다). 도는 동안 다시 눌러도 하나만 돈다 | 바뀌지 않는다 |
| 글을 침(제목·본문) | 규칙은 돌지 않는다. 카드의 `본문이 변경됨` 줄만 그 자리에서 바뀐다(화면 전체를 다시 그리지 않는다) | — |
| `무시`(항목) | 그 항목과 **같은 지문**(종류 + 걸린 글의 모양을 해시한 값 — 깨진 문자는 하위 종류 + 걸린 글자들)의 것을 모두 숨긴다 — 이 화면의 메모리에만 기억하고(위치로 기억하지 않아 글을 고쳐도 밀리지 않는다) 파일·설정·기록에 쓰지 않는다. 포커스는 이웃 `무시` 단추로 간다 | 바뀌지 않는다 |
| `모두 무시(N건)`·`무시한 N건 다시 보기` | 개수로만 보이던 것까지 모두 무시 / 모두 되살림 | 바뀌지 않는다 |
| 다음 `검사하기` | 같은 지문이 아직 있으면 무시를 유지하고 없어진 것의 무시는 조용히 지운다. 새로 생긴 것은 새 항목으로 보인다 | — |
| 새 초안·`다시 만들기`·화면 떠남·앱 닫기 | 도는 검사의 결과를 버리고(세대 번호가 달라 어디에도 보이지 않는다) 결과·무시 기억을 모두 지운다. 작업자 종료를 기다리지 않는다 | — |

**세대 번호**: 검사를 시작할 때마다·새 초안이나 떠남으로 초기화할 때마다 번호가 오르고, 도착한 결과의 번호가 지금 도는 검사의 번호와 같을 때만 한 번 받는다. 늦게 온 낡은 결과가 새 글의 결과인 척하지 않고, 낡은 검사의 실패가 지금 검사를 실패로 만들지도 않는다. 이 논리는 Qt 를 모르는 순수 층에 있어 CI 가 시험한다([`UI_VISUAL_QA.md`](UI_VISUAL_QA.md) §10-8).

## 5-6c. 내 글 문체 참고값 보기 대화상자의 상태 (N-3a) — 읽기 전용

설정 화면 맨 아래의 작은 카드(`열기` 단추 하나)가 여는 창 안 대화상자다(결정 D-330부터 D-339까지, 변경 등급 T1). 상태는 컨트롤러가 정하고(`ui/core/style_view.py` 의 `StyleStudy` — Qt 도 작업 스레드도 서비스도 모르는 순수 논리) 화면(`ui/qt/style_dialog.py`)은 그리기만 한다. **저장 단추·체크 칸·확인창이 없다** — 고른 글은 이 PC 의 메모리에서만 읽어 숫자만 세고, 프로필·설정·보관함은 읽지도 쓰지도 않으며, 창을 닫으면 입력 칸·고른 글·결과를 모두 버린다.

| 상태(`phase`) | 언제 | 대화상자 | 단추 |
|---|---|---|---|
| 고르기(`select`) | 열었을 때·실패한 뒤·`다른 글로 다시 하기` 뒤 | 제목·안내(`직접 쓴 글 1–2개를 이 컴퓨터 안에서만 읽어 숫자로 보여 드려요. …`)·`직접 쓴 글만 골라 주세요` 파랑 안내·`파일 고르기`·고른 글 줄(`글 1 · 파일에서 가져옴` + `빼기` — 파일 이름·위치는 보이지 않는다)·붙여 넣기 칸(`N자` 글자 수)·거절·실패 문장(빨강 계열 하나뿐)·상태 줄(아무것도 없으면 `글 파일을 고르거나 글을 붙여 넣은 뒤 ‘계산하기’ 를 눌러 주세요.`) | `파일 고르기`(파일과 붙여 넣은 글이 합쳐 둘이면 꺼짐)·`계산하기`(고른 글이 없으면 꺼짐)·`닫기` |
| 세는 중(`running`) | `계산하기` 를 누른 뒤 결과가 오기 전(작업 스레드) | 같은 모습에서 입력이 모두 꺼지고 `숫자를 세는 중이에요…` | `닫기` 만 켜짐(닫으면 계산을 취소하고 늦게 온 답은 버린다) |
| 결과(`result`) | 결과가 왔다(붙여 넣기 칸은 이 순간 비워진다) | 안내·고르기 칸은 접히고 `세어 본 숫자` 표 카드(항목 × 글 1[·글 2·범위·두 글 합산])·`센 개수`(문장·문단·목록·글자)·`알아 두세요` 안내들·신뢰 안내 한 문장·`직접 쓴 글만 골랐을 때의 숫자예요. …` 한 줄·`문장 나누기와 문장 끝은 글자 모양만 보고 세는 규칙이라, …` 한 줄 | `다른 글로 다시 하기`·`닫기` |

| 동작 | 결과 | 값은 어디에 남나 |
|---|---|---|
| `열기` | 다른 대화상자가 열려 있으면 열지 않는다. 열리면 `파일 고르기` 에 포커스 | 없음 |
| 파일 선택 창을 취소 | 읽지 않고 아무것도 바꾸지 않는다 | 없음 |
| 파일을 고름 | 읽기 기반의 검사(형식·크기·링크·글자표·글자 수·같은 파일 두 번)를 곧바로 한다. 거절하면 고정 문장(`기존 글 파일 — …`)을 창 안에 보이고 더하지 않는다(몇 번째 파일이 문제인지·파일 이름은 말하지 않는다) | 고른 위치는 컨트롤러만 쥔다(화면·오류·로그에 되풀이하지 않는다) |
| 셋째 글을 고르려 함 | 파일 선택 창을 열기도 전에 막는다 — `파일 고르기` 가 꺼지고(힌트 `글은 파일과 붙여 넣은 글을 모두 합쳐 최대 2개예요.` 는 늘 보인다) 컨트롤러가 직접 불려도 `글은 최대 2개까지 고를 수 있어요.` 로 거절하고 공급자를 부르지 않는다 | 없음 |
| `빼기` | 그 파일을 빼고 `파일 고르기` 가 다시 켜진다 | 없음 |
| 붙여 넣기 | 글자 수만 센다(10만 자까지 — 넘으면 `계산하기` 가 고정 문장으로 거절하고 칸은 그대로). 붙여 넣은 글은 파일과 합쳐 둘 가운데 하나다 | 입력 칸 하나뿐 |
| `계산하기` | 고른 글이 없으면 `글 파일을 고르거나 …` 안내만. 있으면 작업 스레드에서 읽고 센다 | 붙여 넣은 글은 값으로 한 번 넘기고 컨트롤러는 쥐지 않는다 |
| 결과 도착 | 세대 번호가 지금 기다리는 것과 같을 때만 받고 표를 그린다. 붙여 넣기 칸은 되돌리기 기록까지 비운다. 포커스는 몸(스크롤)으로 | 숫자뿐 |
| 실패(읽을 수 없게 됨 등) | 고정 문장만 보이고 고르기 모습으로 돌아간다. 고른 글·붙여 넣은 글은 남아 다시 시도할 수 있다 | 없음 |
| 화면 쪽 예상 못 한 예외 | `숫자를 세지 못했어요. 글을 다시 골라 주세요.` 만 보이고 고르기 모습으로 돌아간다(표준 오류에는 예외 이름만) | 없음 |
| `다른 글로 다시 하기` | 결과·고른 글·붙여 넣기 칸을 모두 비우고 고르기 모습으로. `파일 고르기` 에 포커스 | 없음 |
| 닫기(단추·Esc·다른 대화상자로 바뀜·앱 닫기) | 입력 칸·고른 글·결과를 모두 버린다. 계산 중이면 취소하고 늦게 온 결과는 흔적 없이 버린다. 포커스는 설정 화면의 `열기` 로 돌아간다 | 없음 |

결과 표의 모습: 글이 하나면 `글 1` 열 하나뿐이다(붙여 넣은 글 하나여도 구별할 열이 없어 머리는 그대로). 글이 둘이면 `글 1`·`글 2`(붙여 넣은 글은 `글 2 (붙여 넣음)` — 파일이 먼저, 붙여 넣은 글이 맨 뒤)·`범위` 열과 `두 글 합산` 열(합산은 두 글의 문장·문단을 모아서 센 값)이고, 두 글의 차이가 운영자가 정한 기준 넷 가운데 하나라도 넘으면 합산 열을 빼고 `글 사이 차이가 커서 평균 대신 범위만 보여 드려요.` 라고 말한다. 숫자를 셀 수 없는 항목(문장이 없다·소제목 표시가 없는 형식)은 0 이 아니라 `알 수 없음` 이다. 안내(`알아 두세요`)는 글마다 따로 붙고(글이 둘이면 `글 1 — …`) 짧은 글(문장 10개 미만이거나 글자 600자 미만)·인용 많음·한글 적음·이모지로 끝남·줄바꿈 습관(줄마다 한 문장으로 읽었는데 문장 중간에서 끝난 줄이 섞인 글도 켜진다)·CP949 로 읽음이다. 결과 맨 아래에는 늘 세 줄이 있다 — 참고값 안내 한 문장, 직접 쓴 글만 골랐을 때의 숫자라는 한 줄(고르기 모습의 부탁 문장은 결과 모습에서 접히므로), 글자 모양 규칙이라 문장 수·문단 수·질문형·목록 비율이 실제와 조금 다를 수 있다는 한 줄.

**알려 둔 한계 — 화면이 따로 안내하지 않는 것**(N3AFIX, 결정 D-432·D-433): 숫자는 형태소 분석이 아니라 글자 모양 규칙으로 센 값이라 아래 모양의 글에서는 오차가 있다. 화면은 이것들을 하나하나 알리지 않고 결과 맨 아래의 한 줄(`문장 나누기와 문장 끝은 글자 모양만 보고 세는 규칙이라, 문장 수·문단 수·질문형·목록 비율이 실제와 조금 다를 수 있어요.`)로만 알린다. 어떤 숫자에 어떻게 나타나는지는 아래와 같다(시험 `KnownLimitsTest` 가 이 숫자를 못박는다 — 한계를 고치면 시험이 깨져 이 표도 같이 고친다).

| 입력 모양 | 사람이 세면 → 셈 | 흔들리는 숫자 |
|---|---|---|
| 밑줄 제목(`제목` 아래 `=====`) | 소제목 1·문장 1·문단 1 → 소제목 0·문장 2·문단 2 | 소제목 수·문장 수·문단 수 |
| 네 칸 들여쓴 코드 블록 | 문장 2 → 4(글자 16 → 30)·문단 2 → 3 | 문장 수·평균 문장 길이·문단당 문장 수 |
| 참조식 링크 정의 줄(`[1]: 주소`) | 문장 1 → 2(글자 14 → 23) | 문장 수·평균 문장 길이 |
| 공백 낀 가로줄(`* * *`) | 목록 0 → 1 | 목록 사용 비율(오른다) |
| 번호 목록 바로 뒤의 점 목록 | 목록 2 → 1 | 목록 사용 비율(내려간다) |
| 한 겹 밑줄 기울임(`_기울임_`) | 글자 9 → 11 | 평균 문장 길이(오른다) |
| `ㅎㅎ` 감탄 조각(`맛있다!! ㅎㅎ`) | 문장 1 → 2(글자 5 → 7) | 문장 수·`그 밖` 끝 비율(이모지 끝 안내는 그런 문장이 20% 이상일 때만) |
| 한국식 불릿 `·`(U+00B7)·`◆`·`▷`·`★`·`※` 와 `(1)`·`가.` | 목록 1 → 0, 줄마다 문장 +1(`가.` 는 +2) | 목록 사용 비율(0 으로 나온다)·문장 수·문단 수 |
| 굵은 라벨(`**해석.**`) | 문장 1 → 2(3자 문장 하나) | 문장 수·평균 문장 길이(내려간다) |
| 물음표 없는 `…나요`·`…ㄴ가요` 질문 | 질문 3 → 1 | 질문형 비율(내려간다) |

앞서 알려 둔 것(약어 `Dr.`·`No.1` 과 문장 가운데 말줄임표는 문장 +1, `…요` 로 끝나는 명사는 해요 부류, 제목 줄은 문장 +1, 큰따옴표 속 남의 말은 문장 수 2 → 4)도 같은 한계다. 한 줄로 안전하게 고친 둘 — 평서 `…아니다`(합쇼가 아니라 평서 부류)와 `Q.`·`A.` 라벨(문장이 아니다) — 은 표에서 빠졌다(D-433). 줄바꿈 습관 안내는 억지 줄바꿈을 줄마다 한 문장으로 잘못 읽었을 수 있는 글에서도 켜지므로, 문장 수가 틀렸는데 줄바꿈 안내가 없는 글은 시험 묶음(짧은 문장 여섯 묶음 × 폭 81가지 × 두 형식)에서 0 이다(D-430).

## 6. 상태 색과 안내 부품 — 새 상태색(UI-C0)

C-Type 기준의 상태 모델은 안내·경고·오류·성공 네 가지이고, 각 상태는 **제목·설명·행동** 세 칸을 갖춘다(파이썬 목록·열거형·스택 트레이스를 화면에 그대로 내지 않는다는 규칙도 그대로다). 상태 색은 값이 바뀌었다(이전 → 현재는 [`UI_DESIGN_SPEC.md`](UI_DESIGN_SPEC.md) §2):

| 상태 | 색(토큰) | 옅은 면 | 글자용 변형(흰 바탕 대비) |
|---|---|---|---|
| 안내(정보) | `info` `#2F6FED` | `info_100` `#EAF2FF` | `info_text` `#245ACC`(6.16) |
| 성공 | `success` `#159A6C` | `success_100` `#E9F8F2` | `success_text` `#137D60`(5.08) |
| 경고 | `warning` `#E49A19` | `warning_100` `#FFF5DE` | `warning_text` `#8F5600`(6.00) |
| 오류(위험) | `danger` `#D94A4A` | `danger_100` `#FDECEC` | `danger_text` `#BA4247`(5.31) |

- **기존 `Banner`(일부만·오프라인 안내 띠)와 `StateCard`(빈·오류 상태)는 그대로 동작하고 새 색을 자동으로 따라간다** — 구조·글은 바뀌지 않았고 띠의 바탕·글자(`warning_100`·`warning_text`)와 오류 아이콘 색(`danger` 계열)만 새 값이다. 위 여섯 상태(§1·§5)의 화면 구성과 문구도 그대로다.
- **필수 칸 규칙**: 빈 상태는 아이콘 + 한 줄 제목 + 짧은 설명 + 주요 행동 1개, 오류 상태는 아이콘 + 제목 + 원인 + `다시 시도`(진단 정보는 접어 둔다). 지금의 빈·오류 화면(홈·설정)은 제목·설명·행동 단추를 모두 채워 쓴다.
- **새 `StatusBanner`(안내·경고·오류·성공 + 제목·설명·행동 한 벌)는 이번 묶음에서 만들지 않았다** — 쓸 화면이 생기는 묶음에서 위 색과 필수 칸 규칙으로 만든다(D-153).
- 사용량 막대(`UsageBar`)의 경고·위험도 같은 색(`warning`·`danger`)을 쓰되 색만이 아니라 `주의`·`위험` 글을 함께 보인다([`UI_DESIGN_SPEC.md`](UI_DESIGN_SPEC.md) §2-2).

## 7. 홈의 새 구역의 상태 — 읽어서 그린다(데이터 UI-C1c · 모양 UI-C1d)

홈 뷰모델의 새 키 `board`(`ui/core/board_view.py`, D-190~D-193)를 새 홈 화면이 **그린다**(`ui/qt/board.py`·`screens.py`, D-201·D-202 — 옛 필터 칩·추천 행·요약 카드·오른쪽 현황 패널은 없어졌다). `board["state"]` 는 `ready`(값이 있다)·`loading`(홈 데이터를 읽는 중)·`unavailable`(홈 데이터가 없다 — 못 읽었거나 아직 안 읽음)·`before_connect`(이 공급자는 새 구역을 읽지 않는다) 중 하나이고, 읽기 전에도 구역(추천 둘·작성 중 초안·최근 발행)은 늘 같은 모양으로 있다. 구역마다 따로 상태를 가진다 — **한 구역의 읽기 실패는 그 구역만 오류로 두고 다른 구역·홈 전체를 막지 않는다.** 홈 전체의 여섯 상태(§1)는 그 위의 틀이다 — 읽는 중에는 구역 자리에 자리 표시 하나(KPI 는 `집계 전`), 홈 데이터를 통째로 못 읽으면 구역 자리에 오류 카드 하나(KPI·제목은 그대로)이고, 그 밖의 상태(정상·빈 화면·일부만·오프라인)에서는 구역을 모두 그린다.

| 구역 | 상태 | 언제 | 보이는 것 |
|---|---|---|---|
| 채널 A·B 추천 | `normal` | 우수 후보가 있다(최대 5) | 줄마다 점수 링(44px — 링 안은 숫자만)·링 옆 구간 이름(80/65/50, 점수 링과 같은 기준)·변화량(이전 점수가 있을 때만)·제목·최근 관심도(방향 아이콘 + 글자)·채널 열쇠 A·B. **월 검색량·문서 수는 없다** |
| | `empty` | 후보가 없다 — **정상 빈 상태**(오류가 아니다). 주제 엔진 보관함이 아직 없거나 옛 구조일 때도 같다 | `아직 추천할 후보가 없어요.` + 한 줄(보관함이 없거나 옛 구조면 '읽기만 해서 새로 만들지·바꾸지 않았어요'). **쓰기 단추 없음**(`주제 분석 시작` 은 후보를 저장하는 일이라 없앴다) |
| | `off` | 그 채널의 후보 생성이 꺼져 있다 | `이 채널은 후보 생성이 꺼져 있어요.` |
| | `error` | 보관함·설정 파일을 못 읽었다 | 쉬운 문장(명령줄 글 없음)과 접어 둔 진단 정보(오류 코드). 점수를 확인할 수 없어 서비스가 뺀 후보가 있으면 그 수를 한 줄로 안내 |
| 작성 중 초안 | `normal`·`empty`·`error` | 승인 전(초안 생성됨·검토 필요) 글 최대 5 · 없음 · 글 목록을 못 읽음 | 제목·단계·고친 때(한국 시각). 읽지 못해 건너뛴 글 수 안내 |
| 최근 발행 | `normal`·`empty`·`error` | 발행한 글 최대 5 · 없음 · 글 목록을 못 읽음 | 제목·발행일(한국 날짜). **모르면 `발행일 확인 불가`**(글 하나가 못 읽히거나 시간이 넘어도 그 글만 — 고친 때로 대신하지 않는다) |
| KPI 넷 | 값 · `연결 전` · `집계 전` | 값이 있다 · 읽는 곳이 아직 연결되지 않았다(새 구역을 읽지 않는 공급자·주제 엔진 보관함이 아직 없음) · 연결은 됐으나 못 셌다(일부 채널 실패·글 수 못 셈·홈 데이터 아직 없음) | `N개`(진짜 0 은 `0개`) · `연결 전` · `집계 전` — **알 수 없는 값을 0 으로 단정하지 않는다**. 숫자 28px 굵게·이름 13px·보조 글 12px, 모르는 값은 17px 굵은 글 |
| 연결 요약 | `ready`·`before`·`loading`·`error` | 설정 정보를 읽었다 · 아직 안 읽었다 · 읽는 중 · 읽기 실패 | 설정 묶음 머리와 같은 칩 글을 한 줄로(`준비 중 4 · 연결 확인 필요 1`). 홈이 열릴 때 직접 새로 읽지 않고, 앱이 열릴 때 설정 읽기를 **한 번** 같이 돌려 채운다(D-203 — 읽기 전후 바이트 같음을 시험으로 증명). 읽기 실패는 이 한 줄만 `연결 상태를 읽지 못했어요.` 로 바꾼다 |

- **화면**: KPI 넷(한 줄에 4·2·1) → (안내 띠) → Naver A·B 추천(폭 980 이상이면 나란히, 아니면 위아래) → 작성 중 초안·최근 발행(폭 820 이상이면 나란히) → 연결 상태 한 줄 — 열 수는 논리 폭 규칙(`part_rules`, D-202). 추천 줄은 누르면(Enter·Space 포함) 기존 상세 서랍을 연다(서랍의 내용·동작은 그대로 — 줄이 아는 값만 채우고 나머지는 `데이터 없음`, 닫으면 포커스가 그 줄로 돌아온다). KPI 카드·글 줄·연결 한 줄은 눌리지 않는다(포커스도 받지 않는다). 한 구역이 못 읽히면 그 자리에는 쉬운 문장과 접어 둔 진단 정보뿐이다.
- **예시 표시**: 예시(가짜) 값은 줄마다 `예시` 꼬리표가 붙는다(`sample`). 실제 값에는 없다.
- **점수 없음·관심도 없음·이전 점수 없음**: 점수가 없으면 링 없이 `점수 계산 전`(0점이 아니다), 관심도가 없으면 `관심도 데이터 부족`, 이전 점수가 없으면 변화량은 숨긴다. 관심도를 못 가져왔다고 표시한 데이터(`partial` 의 `trend`)는 값이 남아 있어도 보이지 않는다.
- **글은 가린 뒤에 줄인다**: 제목·채널 이름·오류 문장은 비밀 모양을 가린 뒤에 줄인다. 내부 번호(후보·글 번호)와 영문 상태 이름은 뷰모델의 글에 없다.
- **시험**: `tests/test_ui_c1c_core.py`(순수 — 값 모양·점수/구간 경계·상태·KPI·연결 요약·시간 제한 도우미)·`tests/test_ui_c1c_adapters.py`(실제 서비스를 읽는 어댑터 — 보관함 없음·0바이트·깨짐·새 버전·후보 천 개·읽기 전용 전후 비교·실패 격리·시간 제한)·`tests/test_ui_qt_c1c.py`(새 구역이 그려진 모습 — 예시 보드의 모든 줄 종류·상태별 문구·연결 한 줄·새 KPI 글이 카드에 들어감)·`tests/test_ui_c1d_core.py`(열 수 규칙·홈 모양·읽기 전 문구·서랍 규칙·연결 정보 읽기의 바이트 동일 증명·없앤 것이 되살아나지 않음)·`tests/test_ui_qt_c1d.py`(첫 화면·글자 잘림 없음·줄 모양·KPI·구역 상태·연결 한 줄·접근 이름·Tab 순서·포커스).
