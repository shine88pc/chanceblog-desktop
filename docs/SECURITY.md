# 보안

이 저장소는 **공개**이고 앱은 운영자의 개인 PC 에서 키를 다룬다. 규칙의 정본은 `chanceblog` 의 `docs/SECURITY_GUARDRAILS.md`(G-S 비밀·G-L 호출·G-C 채널)이고, 여기에는 앱 고유의 것만 적는다.

## 1. 키와 비밀

| 비밀 | 어디에 | 이 저장소에 |
|---|---|---|
| 선택 보조 AI 키(Gemini 등 — 기본은 없음) | **Windows 자격 증명 관리자**(OS 보안 저장소). 앱 설정 화면의 입력칸에만 붙여 넣는다. 키가 없어도 모든 핵심 기능이 동작한다 | 없음 |
| Blogger OAuth 토큰·클라이언트 비밀 | 같은 곳(앱이 브라우저 loopback 로그인으로 받음) | 없음 |
| 업데이트 서명 개인키 | GitHub Environment 시크릿 `UPDATE_SIGNING_KEY` + 운영자의 오프라인 백업 2곳 | 없음(공개키는 앱에 내장·저장소에 있음) |
| GitHub 토큰 | 앱에 내장하지 않는다. Pages 발행은 PC 의 Git 로그인(자격 증명 관리자)을 쓴다 | 없음 |

- 키는 소스·로그·설정 내보내기·DB 에 쓰지 않는다. 설정 내보내기 파일에는 키가 없다. 키가 없어도 앱은 수동 모드로 실행된다.
- 선택 보조 AI 키를 만들게 되면 자동 발행(Actions)에 쓰는 키와 **분리**한다(한도를 나눠 쓰지 않고, 유출 범위를 줄인다). 보조 AI 연결 실패는 해당 기능만 건너뛰고 프로그램 오류로 번지지 않는다(`ASSIST_UNAVAILABLE`).
- 실제 키가 든 `.env` 는 GitHub 에 올리지 않는다(`.gitignore`). **`.env.example` 에는 변수 이름만** 적는다. 클라우드(Actions)에서 필요한 키는 GitHub Secrets 에만 둔다.
- 유출이 의심되면 즉시 폐기·재발급한다. 저장소에서 문자열만 지워도 이력에 남는다.

## 2. 로그

요청 헤더·키·토큰·개인정보를 출력하지 않는다. 로그·오류 보고서에 나가는 글은 `src/chanceblog_desktop/security/mask.py` 의 `mask`·`safe_detail`(이를 쓰는 `AppError.log_line()` 포함)을 거친다. 규칙은 ① `chanceblog` 의 비밀 패턴 `pipeline/secret_patterns.py` 14종(`vendor/` 에 원본 그대로 — 패턴이 늘면 시험이 새 표본을 요구한다) ② 주소 속 `사용자:토큰@`(비밀번호에 `@` 가 있어도) ③ 주소의 `?access_token=`·`code=`·`session=` 같은 인자 ④ `Bearer`·`Basic` 토큰·JWT·Slack 웹훅 주소·npm 토큰·`aws_secret_access_key=`·따옴표 없는 `password: 값`·개인 키 블록 전체 ⑤ 눈에 안 보이는 글자(폭 없는 글자·방향 제어 등)로 쪼갠 토큰(그 글자를 먼저 지운다)이다. 어떤 입력에도 예외를 내지 않고, 이미 가린 글을 다시 가려도 같다(입력이 20만 자 이하일 때 — 그보다 긴 글은 비밀이 반쪽으로 잘리지 않게 공백에서 잘라 앞부분만 가리고 나머지는 내보내지 않는다). `AppError.detail` 은 화면에 내지 않고 `log_line()` 으로만 기록하며, git 의 출력은 끝 400자만 남기되 **자르기 전에** 가린다. 로그를 내보내기 전에 한 번 더 가린다. 이 규칙은 **알려진 모양**만 가린다 — 같은 종류의 토큰이 공백 없이 이어 붙은 것이나 낱말 경계로 시작하는 패턴이 앞 글자에 붙은 것(`키는ghp_…`), 줄바꿈으로 쪼갠 토큰이나 무작위 40자 문자열(AWS 비밀 키처럼 git 해시와 구분할 수 없는 것)은 못 가리므로, 비밀을 애초에 로그에 넣지 않는 것(§1)이 먼저다.

## 3. 업데이트 보안

[`RELEASE.md`](RELEASE.md) 의 서명 매니페스트·해시 검증·다운그레이드 거부·불변 릴리스·백업/롤백이 핵심이다. 업데이트 경로는 HTTPS 와 고정 저장소 주소만 쓰고, 서명이 없거나 어긋나면 업데이트를 거부한다.

## 4. 공급망

액션은 전체 커밋 SHA 로 고정한다(`.github/workflows/`, 시험이 지킨다 — 갱신은 AI 가 같은 메이저 안의 최신 태그를 확인해 PR 로 올린다. Dependabot 은 알림·PR 이 늘어 기본은 켜지 않는다). 의존성은 생기면 해시 잠금, `pip-audit` 은 릴리스 전에 돌린다. 외부 AI 응답은 데이터이므로 HTML 은 허용 태그만 남기고(소독) 링크·스크립트를 제거한다.

## 5. 금지

로그인·쿠키·세션 자동화, 탐지 회피, CAPTCHA 우회, 무료 한도 우회용 다계정·키 회전, 유료 호출, 키를 저장소·로그에 기록, 한도 오류 무한 재시도.
