# 정식 CI 의 화면(Qt) 시험 칸

> 상태: **준비만 해 둔 가지**(`ai/claude/NO-MERGE-v1ciqt-wip`)다 — 병합 전이다. 운영자 확인 037 ① 승인(이슈 #264, 2026-11-24 19:43)의 범위 안에서 만들었고, 새 칸을 처음 돌려 보는 일과 병합은 따로 부탁한다(`ci.yml` 변경은 T3). 결정 번호는 `docs/DECISIONS.md` 의 D-710 에서 D-715 다.

## 1. 한눈에

- 정식 CI 의 열두 칸(환경 4개 × 조각 3개)에는 화면 도구 PySide6 가 없어서 화면(Qt) 시험 약 1,200개가 모두 '건너뜀'이다. 건너뛴 시험은 초록으로 끝나므로 화면이 깨져도 병합을 막지 못했다. 지금까지 Qt 시험은 임시 가지와 임시 워크플로로 따로 돌렸다(D-32).
- 새 칸 `qt` 는 **같은 `ci.yml` 의 둘째 잡**이다. 윈도·파이썬 3.12 에서 PySide6 두 파일(합쳐 약 83MB, 비용 0)만 받아 화면 시험까지 모두 돌린다. 창은 띄우지 않는다(`QT_QPA_PLATFORM=offscreen`).
- 같은 파일의 잡이라 `auto-pr.yml` 의 병합 문턱(그 커밋의 `ci.yml` 실행이 모두 성공해야 PR 을 만든다)이 그대로 새 칸을 포함한다. `auto-pr.yml` 은 고치지 않는다. 단 `auto-pr.yml` 이 기다리는 시간은 최대 40분이므로 새 칸도 그 안에 끝나야 한다.
- 기존 열두 칸(`test` 잡)은 한 글자도 바뀌지 않았다. 그래서 열두 칸에서는 Qt 시험의 건너뜀이 지금처럼 정상이다.
- PySide6 가 안 깔려 시험이 건너뛰어졌는데 초록이 되는 일은 막는다(3절).

## 2. 칸 구성

| 항목 | 값 | 이유 |
|---|---|---|
| 잡 이름 | `Qt 시험 (windows-latest, Python 3.12, 조각 N/3)` | 기존 두 이름 접두어(`시험 (`·`시험 실행(`)로 시작하지 않아 이름을 못박는 기존 시험과 안 부딪힌다 |
| 러너·파이썬 | `windows-latest`, `'3.12'` | 설치 파일 묶음과 같은 판(D-400) |
| 조각 | `[1, 2, 3]`, 총수 `'3'`, `fail-fast: false` | 기존 열두 칸과 같은 `scripts/ci_shard.py` 규칙. 시간이 길면 5 까지 늘린다(목록과 총수와 두 이름의 `/3` 을 함께 고친다) |
| 시간 한도 | `timeout-minutes: 40` | `test` 잡과 같다. 첫 실행 전 어림은 한 조각 12–25분(추정) |
| 권한·비밀 | 최상위 `contents: read` 그대로, 비밀 값 0 | 잡 권한·환경 변수 주입 없음 |
| 단계 | ① 가져오기 ② 파이썬 3.12 ③ `python scripts/ci_qt_setup.py` ④ `python scripts/ci_shard.py` | ①②는 `test` 잡과 같은 SHA 의 같은 액션 둘뿐(새 액션 0) |
| ④의 환경 변수 | `PYTHONUTF8`·`CI_SHARD`·`CI_SHARD_TOTAL`·`CI_REQUIRE_QT=1`·`QT_QPA_PLATFORM=offscreen` | 앞의 셋은 기존 단계와 같고 뒤의 둘이 Qt 칸 표시와 화면 방식 |
| 시험 범위 | 전체 시험 파일(비 Qt 시험도 PySide6 가 있는 환경에서 한 번 돈다) | 제품 환경과 같고 분류에서 빠뜨릴 위험이 없다 |

**`scripts/ci_qt_setup.py`(표준 라이브러리만)가 하는 일**
1. `packaging/requirements-package.txt` 의 `# [runtime]` 아래 줄을 읽는다. **정확히 두 줄**(`PySide6_Essentials==X`·`shiboken6==X`, 같은 X)이 아니면 종료 코드 2 로 거절한다. runtime 에 줄이 더해지면 이 칸이 빨개져 의식적으로 고치게 된다. `이름==버전` 이 아닌 모양(범위·주소·옵션)도 거절한다.
2. `python -m pip install --disable-pip-version-check --isolated --only-binary=:all: --no-deps 두 줄` 을 고정 인자 목록으로(셸 없음) 돌린다. 설치처를 바꾸는 옵션은 없고 `--isolated` 가 환경 변수·사용자 설정의 영향을 끊는다. 잠금 줄에 `--hash` 가 생기면 그 두 줄만 담은 임시 요구 파일과 `--require-hashes` 로 바꿔 부른다(해시 잠금은 따로 승인받는 일).
3. 설치된 버전이 잠금과 같은지, 화면 없는 `QApplication` 이 만들어지는지 본다. 그리고 버전·글꼴 이름 몇 줄을 찍는다(경로·사용자 이름 없음). 한글을 그릴 수 있는 글꼴이 없으면 알림 한 줄만 낸다(실패 아님 — 6절).

개발 PC 에서는 `python scripts/ci_qt_setup.py --dry-run`(명령만 보여 주고 아무것도 설치하지 않는다)과 `--probe-only`(설치 없이, 이미 PySide6 가 있을 때 3번 점검만)로 확인한다. **인자 없이 부르면 진짜로 설치한다** — `ci.yml` 만 그렇게 부르고, 시험은 진짜 설치를 하지 않는다.

## 3. 건너뜀 가드와 종료 코드

`ci.yml` 의 시험 단계는 `CI_REQUIRE_QT=1` 로 `scripts/ci_shard.py` 를 부른다. 이 값이 있으면 다음을 한다(없으면 오늘과 똑같다).

| 종료 코드 | 어디서 | 뜻 |
|---|---|---|
| 2 | `ci_shard.py` | `CI_REQUIRE_QT` 값이 1·0·없음이 아니다(오타로 가드가 꺼진 채 초록이 되는 것을 막는다) |
| 3 | `ci_shard.py` | 시작 전에 PySide6 를 못 찾았다 — 시험을 하나도 돌리지 않고 멈춘다 |
| 1 | `ci_shard.py` | 시험이 끝난 뒤 건너뛴 시험 중 이유에 PySide6(대소문자 무시)가 든 것이 하나라도 있다 — 시험 파일별 개수를 찍는다 |
| 2·3·4·5 | `ci_qt_setup.py` | 잠금·인자 거절 · pip 설치 실패 · 설치된 버전이 잠금과 다름 · Qt 점검 실패 |

- 건너뜀 가드는 PySide6 이유가 아닌 건너뜀(git·링크·권한 같은 환경 이유)은 정보로만 센다. 첫 실행에서 어떤 이유가 나오는지 본 뒤 허용 목록으로 굳힌다.
- 시험 단계 끝에 `건너뛴 시험 N개 — PySide6 이유 0개` 줄과, 이유별 개수, **시험 파일별 걸린 시간 상위 15개**가 찍힌다. 걸린 시간은 7절의 무게 표를 고칠 때 쓴다. 5초 넘게 걸린 시험 파일은 끝나는 즉시 `[걸린 시간] 파일 초` 한 줄도 찍히므로 칸이 시간 한도에 잘려도 로그에 남는다.
- 새 Qt 시험 파일은 건너뜀 문구에 `PySide6` 낱말을 쓴다(지금 모든 파일이 그렇다). `tests/test_ci_shard.py` 의 정적 시험이 Qt 깃발(`HAVE`)을 조건으로 건너뛰는 모든 곳을 훑어 이를 지킨다.

## 10. 하지 않은 것과 한계

| 하지 않음 | 이유 |
|---|---|
| 진짜 화면 띄우기 | 러너 세션에 기대지 않는다(offscreen 으로 충분) |
| 파이썬 3.10 Qt 칸·리눅스 Qt 칸 | 번들은 3.12·윈도(D-400). 3.10 문법은 기존 3.10 칸이 이미 지킨다. 후속 |
| 화면 사진 비교 | 범위 밖 — 지금 시험은 크기·글자 잘림·키보드·접근 이름을 본다 |
| 휠 해시 잠금 | 잠금 파일 변경은 T3 이고 PyPI 내려받기 별도 승인이 필요하다. `ci_qt_setup.py` 는 해시가 생기면 스스로 `--require-hashes` 로 바꾼다 |
| Qt 시험 고치기·건너뛰기 추가 | 시험을 약하게 하지 않는다. 이 갈래는 돌리는 곳만 만든다. 흔들리는 시험은 목록으로 만들어 따로 고친다 |
| 새 액션·새 시크릿 | 기존 SHA 둘만, 시크릿 0 |

알려 둔 한계: 건너뜀 가드는 이유 문구의 `PySide6` 낱말로 '못 돌았다' 를 알아본다. Qt 깃발이 아닌 다른 조건으로 건너뛰는 새 파일은 정적 시험이 못 잡을 수 있다. 윈도 말고 리눅스 Qt 칸을 만들면 `HAVE and os.name` 조건으로 건너뛰는 몇 곳(PySide6 와 윈도 글꼴이 있어야 하는 시험)이 PySide6 낱말을 이유에 담아 가드에 걸리므로 그때 규칙을 다시 본다.
