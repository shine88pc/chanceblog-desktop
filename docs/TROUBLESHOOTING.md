# 오류 안내 — 오류 코드와 하실 일 (규칙 기반, AI 없이)

> 모든 실패는 **오류 코드 하나**로 모이고, 화면에는 코드·원인·하실 일이 쉬운 말로 나옵니다. 이 문서가 코드와 안내 문구의 **정본**입니다. 코드 쪽 카탈로그(`src/chanceblog_desktop/errors/catalog.py`)는 이 표에서 `python scripts/sync_errors.py` 가 **만든 파일**이라 직접 고치지 않고, 시험이 둘이 같은지 확인합니다 — 표를 고치고 다시 만들지 않으면 시험이 실패합니다. 로그와 오류 보고서에는 키·토큰을 쓰지 않습니다(보안 모듈이 가립니다).

표기: **재시도** — 앱이 자동으로 다시 해 볼 수 있는가(횟수 제한 있음). 사용자 문구는 화면에 그대로 보이는 말입니다.

## 1. Blogger

| 코드 | 언제 | 사용자 문구 | 하실 일 | 재시도 |
|---|---|---|---|---|

| `BLOGGER_NOT_FOUND` | HTTP 404 | 블로그 또는 글을 찾을 수 없습니다. | 설정의 블로그 선택을 다시 하거나, 글이 Blogger 에서 삭제되지 않았는지 확인합니다. | 아니오 |

## 3. 파일·이미지·디스크

| 코드 | 언제 | 사용자 문구 | 하실 일 | 재시도 |
|---|---|---|---|---|
| `FILE_WRITE_FAILED` | 파일 만들기·저장 실패 | 파일을 저장하지 못했습니다: **「경로」**. | 저장 경로가 있는지, 쓰기 권한이 있는지(읽기 전용 폴더 등 — 다른 프로그램이 파일을 열고 있는 경우는 따로 안내합니다) 확인하고 다른 폴더를 고릅니다. 연결한 저장소의 `.git` 폴더에 올리기 잠금 파일(`chanceblog-desktop-publish.lock`)을 못 만들었다는 세부가 있으면 그 폴더에 쓸 수 있는지(권한·읽기 전용) 확인합니다 — 앱은 같은 저장소에 쓰는 다른 앱(`--data-dir` 이 다른 앱 포함)을 막을 수 없는 채로는 올리지 않으며 글도 저장소도 바꾸지 않았습니다. | 아니오 |
| `FILE_IN_USE` | 다른 프로그램이 파일을 열어 두어 git 이 그 파일을 바꾸지 못함(`unable to unlink` 등) | 다른 프로그램이 쓰고 있어서 파일을 바꾸지 못했습니다: **「경로」**. | 그 폴더의 파일을 열어 둔 프로그램(편집기·미리보기·동기화 앱·백신)을 닫고 다시 시도합니다. 중간에 멈췄다면 앱이 중간까지 바뀐 파일을 병합 전 상태로 되돌리려고 시도하고, 되돌리지 못한 파일은 세부에 이름이 적힙니다. | 고친 뒤 |
| `FILE_PATH_TOO_LONG` | Windows 경로 길이 초과 | 저장 경로가 너무 깁니다. | 더 짧은 폴더(예: `C:\work\chanceblog`)로 옮깁니다. | 아니오 |
| `DISK_FULL` | 디스크 공간 부족 | 저장 공간이 부족합니다. | 디스크 공간을 확보한 뒤 다시 시도합니다. | 아니오 |
| `IMAGE_NOT_FOUND` | 글이 가리키는 이미지 파일 없음 | 이미지 파일을 찾을 수 없습니다: **「파일」**. | 이미지를 다시 고르거나 파일 위치를 확인합니다. | 아니오 |
| `IMAGE_TOO_LARGE` | 이미지 용량·크기 초과 | 이미지가 너무 큽니다(허용 **「허용 용량」**). | 이미지를 줄여 다시 고릅니다. | 아니오 |
| `DATA_DIR_UNSAFE` | 사용자 데이터 폴더가 git 저장소 안이거나 프로그램 폴더 안임 | 데이터를 둘 폴더가 안전하지 않습니다: **「경로」**. | 원고·설정이 저장소에 올라가지 않도록 데이터 폴더는 저장소 밖에 둡니다. `--data-dir` 로 다른 폴더(예: 사용자 폴더 아래)를 지정하거나 환경 변수 `CHANCEBLOG_DESKTOP_DATA` 를 바꿉니다. | 고친 뒤 |
| `SETTINGS_INVALID` | 앱이 저장해 둔 설정 파일(`settings.json`)이나 발행 기록 파일(`publish/글번호.json`)을 읽을 수 없거나 모양이 틀림, 또는 올림(PUSHED)·기록(COMMITTED) 상태인데 발행 기록 파일이 없음 | 앱의 설정·기록 파일을 읽을 수 없습니다: **「파일」**. | 그 파일은 지우거나 고치지 않았습니다. 설정 파일이면 이름을 바꿔 두고(지우지 마세요) 다시 실행하면 새로 만들어집니다(연결한 저장소와 블로그 프로필은 다시 정합니다). 발행 기록 파일이면 연결한 chanceblog 폴더에 올리지 않은 글 기록(commit)이 남았는지 확인해 알려 주세요. '올림(PUSHED) 상태인데 발행 기록 파일이 없다' 는 세부(글을 지웠다가 백업으로 되살렸거나 오래된 백업으로 되돌렸을 때 생깁니다)면 `check-deploy` 로 이을 수 없으니 세부의 `delete 글번호 --yes` 로 그 글의 기록을 지웁니다 — 올라간 글은 저장소에 그대로 있고(공개 주소는 사이트에서 직접 확인합니다) 이 앱은 올라간 글을 지우지 않습니다. | 고친 뒤 |

## 10. 오류 보고서와 개발자 메모

- **오류 보고서**(설정 → 로그 내보내기): 코드·시각·단계·마스킹된 세부만 담고 키·토큰·원고 본문은 담지 않습니다. 운영자는 이 파일을 AI 코딩 도구나 개발 지원에 그대로 붙여 넣어도 됩니다.
- **새 오류 코드를 만들 때**: ① 이 문서의 표에 행(코드·언제·사용자 문구·하실 일·재시도)을 더하고 ② `python scripts/sync_errors.py` 로 `errors/catalog.py` 를 다시 만들고 ③ 시험이 문서와 카탈로그가 같은지 확인합니다. '재시도' 칸은 `아니오`·`예`·`예(최대 N회)`·`예(N회)`·`예(자동)`·`예(자동 재확인)`·`예(연결되면)`·`로그인 뒤`·`고친 뒤`·`해결 뒤`·`시각 이후`·`선택` 만 쓸 수 있고, 다른 말을 쓰면 만드는 단계에서 실패합니다(새 문구가 꼭 필요하면 `errors/model.py` 의 `parse_retry` 와 시험을 함께 고칩니다). 사용자 문구의 `「이름」` 은 코드가 값을 넣는 자리표시자입니다.
- 외부 응답(HTTP 본문 등)은 데이터이므로 사용자 문구에 그대로 끼워 넣지 않고 정해진 칸(`경로`·`파일`·`시각` 등)에만 길이·제어 문자를 정리해 넣습니다.
- AI 는 이 안내를 대신하지 않습니다. 보조 AI 를 켜 두어도 이 표의 규칙 문구가 먼저 나오고, AI 설명은 그 아래 '보조 의견(미검증)'으로만 붙습니다([`ARCHITECTURE.md`](ARCHITECTURE.md) §7).
