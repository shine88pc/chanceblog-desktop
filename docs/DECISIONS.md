# 설계 결정 기록

> 번호·날짜·근거·기본값을 적는다. 운영자의 채팅 답은 날짜와 함께 그대로 요약한다. 바꾸려면 새 행으로 덮는다(지우지 않는다). 규칙의 정본은 `chanceblog` 이고, 이 표는 이 저장소 범위의 결정만 담는다. 배경 분석은 `chanceblog` 의 `docs/analysis/2026-10-30_desktop-publisher-reconciliation.md`(브랜치 `ai/claude/desktop-plan`).

| 번호 | 날짜 | 결정 | 상태·근거 |
|---|---|---|---|
| D-01 | 2026-10-30 | **티스토리 제외·격리.** 구현은 `chanceblog` 보관 브랜치 `ai/claude/tistory-naver`(삭제 금지)에 두고 앱의 화면·배포·시험에서 뺀다. 공식 글쓰기 API 가 없고 로그인·쿠키 자동화는 하지 않는다 | 확정(운영자 채팅) |
| D-02 | 2026-10-30 | **네이버 블로그 B** 추가는 **확인사항**: 블로그 주소·주제·대상 독자·말투·하루 편수·A 와 구분하는 기준을 받은 뒤 번호 있는 승인 요청(T3). A·B 가 각자 독립 프로필을 갖는 틀은 먼저 만든다 | 보류(운영자 정보 대기) |
| D-03 | 2026-10-30 | 프로그램은 **새 저장소 `chanceblog-desktop`**(운영자가 직접 생성, 공개)에서 독립적으로 개발한다. `chanceblog` 는 GitHub Pages 콘텐츠·자동 배포를, 이 저장소는 프로그램 소스·설치 파일·버전·업데이트·플랫폼 연동을 관리한다. 앱은 **기존 `chanceblog` 로컬 저장소를 연결**해 GitHub Pages 글·이미지를 만들고 기존 자동 배포 흐름을 쓴다 | 확정 |
| D-04 | 2026-10-30 | **틀**: 기존 파이썬 코어 재사용 + 화면 **PySide6 또는 pywebview**(첫 구현에서 비교해 정한다) + PyInstaller `--onedir` + **Velopack**(2순위: Inno Setup + tufup). Electron·Tauri 는 쓰지 않는다 | 승인('네') |
| D-05 | 2026-10-30 | **배포·업데이트**: Actions 가 설치 파일을 **초안 릴리스**로 올리고 운영자가 'Publish release' 한 번. **무서명 + 자체 Ed25519 서명 매니페스트·SHA256**, 유료 코드 서명 인증서는 사지 않음. 먼저 **개인 PC 의 Smart App Control 상태**를 확인 | 승인('네') — 서명 비밀키는 시크릿이라 만들 때 번호 있는 요청(T3) |
| D-06 | 2026-10-30 | 개인 PC 는 **Windows 10/11**, 관리자 권한 없이 사용자 폴더에 설치. 프로그램 코드의 수정·유지보수는 **운영자가 필요할 때 Claude Code 나 다른 AI 코딩 에이전트를 직접 실행**하는 방식이다 | 확정 |
| D-07 | 2026-10-30 | 선택 보조 AI 의 키(Gemini 등)는 **필요성이 확인되기 전에는 만들지 않는다**. 만들 때는 자동 발행(Actions)용 키와 **분리**하고 앱의 Windows 자격 증명 관리자에만 둔다. 결제수단 등록 금지 | 확인사항(기본: 안 함) |
| D-08 | 2026-10-30 | **Blogger 연동**: 우선순위에는 있다(Pages 다음). 시작할 때 운영자가 영문·한글 각각 '데스크톱 앱' 유형 OAuth 클라이언트를 구글 Cloud 에서 발급해야 한다(T3) | 확인사항(시작 시점에 요청) |
| D-09 | 2026-10-30 | **저장소 감시·예약 실행·배포 확인·실패 감지·알림은 지금처럼 AI 없는 GitHub Actions(chanceblog)로 둔다.** 앱의 감시·Windows 알림은 첫 버전에 넣지 않는다 | 확정 |
| D-10 | 2026-10-30 | 요구서 원문(`blog_publisher_claude_handoff_v0.2.0.md`)은 공개 저장소에 올리지 않고 정합 분석만 올린다 | 확정 |
| D-11 | 2026-10-30 | **핵심 코드 가져오기**: `vendor/pipeline/` 에 원본 그대로 복사 + `vendor/VENDOR.json`(커밋·해시) + `scripts/sync_core.py` + 해시 시험. 서브모듈·패키지 설치는 쓰지 않는다([`ARCHITECTURE.md`](ARCHITECTURE.md) §4). 가져올 때 원본 폴더의 origin 이 chanceblog 인지·가져올 커밋이 origin/main 에 병합된 것인지·목록의 파일이 일반 파일(링크·하위 모듈·폴더 아님)인지 확인하고, 확인 시험은 vendor/ **전체**의 목록 밖 파일을 막는다 | 확정(구현·병합됨, 독립 검토 반영) |
| D-12 | 2026-10-30 | **개발 순서**(운영자 우선순위 2026-10-30): ① 독립적인 데스크톱 프로그램 구조 ② 회사 PC → 개인 PC 이관 ③ GitHub Pages 자동 발행 유지 ④ Blogger 초안 저장 유지 ⑤ 네이버 A/B 독립 프로필 ⑥ 네이버 제목·본문·이미지·태그 패키지 ⑦ 반자동(확인 후 직접 발행) ⑧ 콘텐츠·플랫폼별 발행 상태 관리 ⑨ 버전·변경 이력 ⑩ GitHub Releases 설치 파일 ⑪ 업데이트·백업·복구·로그·오류 관리 ⑫ 다른 AI 코딩 도구도 이어받는 문서. 규칙 기반 오류 안내(D-17)는 ①과 함께 뼈대로 먼저 둔다 | 확정(운영자 지시) |
| D-13 | 2026-10-30 | **라이선스**: 아직 정하지 않았다. 파일이 없으면 모든 권리가 저작자에게 남는다. 무료 코드 서명(SignPath)을 쓰려면 OSI 라이선스가 필요하다. 기본 제안은 MIT | 운영자 결정 대기 |
| D-14 | 2026-10-30 | **무료 AI 로 세션형 코드 개발·수정(Claude Code 같은 일)을 대신하지 않는다.** 감시·판정·알림은 AI 없이 한다 | 확정(운영자 지시) |
| D-15 | 2026-10-30 | **AI Router·다중 AI 공급자·한도 소진 시 자동 전환 구조는 초기 필수 범위에서 제외**한다(복잡한 AI Provider 구조도 만들지 않는다). 무료 AI 는 ① 감시 결과 한 줄 요약 ② 긴 오류 로그의 간단한 설명 ③ 사용자가 확인할 조치 추천 ④ 주간 운영 결과 요약 **선택 보조 기능에 한정**하고, **실제 필요성이 확인됐을 때만** 추가한다. 기본값은 비활성이고, 이후를 위한 **최소한의 선택형 인터페이스**(`assist/`)만 둔다 | 확정(운영자 지시) |
| D-16 | 2026-10-30 | 기존 Gemini 기능(클라우드 파이프라인)은 삭제하지 않고 **앱에서는 선택 기능으로 격리**한다. Gemini 연결 실패가 프로그램 전체 오류로 이어지지 않는다(`ASSIST_UNAVAILABLE`) | 확정(운영자 지시) |
| D-17 | 2026-10-30 | **오류 안내는 AI 보다 규칙 기반**을 우선한다 — 오류 코드와 플랫폼별 안내 문구([`TROUBLESHOOTING.md`](TROUBLESHOOTING.md) ↔ `errors/catalog.py`, 시험으로 일치 확인). 예: Blogger HTTP 401 → 인증 만료·재로그인, Git push 실패 → 저장소 인증·네트워크 확인, Actions 실패 → 실패한 워크플로·잡 표시, 파일 생성 실패 → 경로·권한 확인, API 호출 제한 → 재시도 가능 시각 표시 | 확정(운영자 지시) |
| D-18 | 2026-10-30 | **AI 없이 반드시 동작해야 하는 기능**(콘텐츠 작성·수정·불러오기, Markdown·HTML 변환, 미리보기, Pages 생성·배포, Blogger 초안, 네이버 A/B 패키지·복사·글쓰기 페이지 열기, 이미지·삽입 위치, 상태·URL 기록, 예약 작업, 배포 성공·실패 감지, 규칙 기반 오류 안내, 작업 로그, 백업·복구, 버전 확인·업데이트)를 시험으로 지킨다([`ARCHITECTURE.md`](ARCHITECTURE.md) §8) | 확정(운영자 지시) |
| D-19 | 2026-10-30 | **보안 점검**: Gemini 키가 일반 파일·과거 커밋에 노출됐는지 먼저 확인했다 — `chanceblog` 전체 이력(모든 브랜치 585 커밋)에서 키 모양 문자열 9종 0건, 이 저장소도 0건. 키는 GitHub Actions 시크릿(클라우드)과 Windows 자격 증명 관리자(개인 PC)에만 둔다. `.env` 는 올리지 않고 `.env.example` 에는 변수 이름만 둔다. 로그·오류 보고서에는 키·토큰을 쓰지 않는다 | 확인됨 |

## 1.0.0 완료 기준

개인 PC 에서 새로 clone 해 빌드·시험 가능 · 어느 AI 도구든 문서만으로 구조 이해 · **AI 없이** 앱 실행과 위 D-18 의 모든 기능 사용 가능(AI 연결 실패가 프로그램 오류로 번지지 않음) · 기본 설정에서 유료 호출 불가 · GitHub Pages 테스트 글을 연결한 chanceblog 저장소에 만들고 승인 뒤 배포까지 성공 · Blogger 테스트 글 초안 저장 성공(D-08 이후) · 네이버 A/B 각각 독립 패키지 생성과 중복 경고 · 티스토리가 기본 화면·빌드에서 제외 · 업데이트 전 백업과 실패 시 복구 성공 · 로그·오류 보고서에 키·토큰이 남지 않음 · 설치형과 휴대용 모두 실행 · 버전·변경 이력이 화면과 GitHub Release 에서 일치.
