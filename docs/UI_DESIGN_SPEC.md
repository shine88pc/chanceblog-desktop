# 화면 설계 기준 — 값·틀·검증 환경 (PySide6, 화면 기초 'G0')

> 정식 화면(GUI) 첫 묶음의 설계 기준이다. 화면 도구는 **PySide6** 로 확정됐다([`DECISIONS.md`](DECISIONS.md) D-32, D-04 의 '또는' 을 닫음). 값의 출처는 운영자가 승인한 화면 목업과 UI 명세(v1.0.0·정밀 보완 v1.1.0)·2026-11-03 22:27 채팅 세부 기준이고, **원문은 비공개라 여기에는 값(색·크기·간격)과 이름만 옮기고 문장은 새로 썼다.** 구조는 [`ARCHITECTURE.md`](ARCHITECTURE.md) §5.1, 부품은 [`UI_COMPONENTS.md`](UI_COMPONENTS.md), 상태는 [`UI_STATES.md`](UI_STATES.md), 검수는 [`UI_VISUAL_QA.md`](UI_VISUAL_QA.md).

## 1. 목표 한 줄

비개발자가 설명서 없이 **추천 주제 확인 → 블로그 선택 → 초안 만들기 → 항목별 복사** 네 걸음을 끝낼 수 있게, 화면은 기능 수보다 **다음에 할 행동**을 먼저 보여 준다. 내부 값(번호·영문 상태 코드·경로·원문 응답·오류 코드)은 기본 화면에 내지 않는다(오류 코드는 접어 둔 '진단 정보' 에만).

## 2. 값은 한 곳에서 — 디자인 토큰 (`src/chanceblog_desktop/ui/core/tokens.py`)

Qt 스타일시트(`ui/qt/theme.py` 의 `build_qss`)는 이 파일의 값으로만 만든다. 화면 코드에 색(`#RRGGBB`)·글꼴 이름·인라인 스타일·배율 값을 직접 쓰지 않는다 — 시험이 소스를 훑어 막는다.

**Text Token(글자 색 5개 — 운영자 기준 그대로)**

| 이름 | 값 | 쓰임 | 흰 바탕 대비 |
|---|---|---|---|
| `Text/Strong` | `#0B1736` | 제목·큰 숫자 | 약 17 |
| `Text/Primary` | `#14213D` | 본문·단추 글자 | 약 16 |
| `Text/Secondary` | `#5F6B7A` | 보조 설명 | 약 5.4 |
| `Text/Muted` | `#8491A3` | 힌트·빈 값(꼭 읽어야 하는 글에는 쓰지 않는다) | 약 3.2 |
| `Text/Disabled` | `#AAB4C3` | 꺼진 단추의 글자(꺼진 것에만) | 약 2.1 |

**완전한 검정(`#000000`)을 기본 글자색으로 쓰지 않는다.** 시험이 코드·스타일시트·팔레트 어디에도 순수 검정이 없음을 확인하고, 본문·제목·보조 글자의 흰 바탕·앱 바탕 대비가 4.5 이상, 글자로 쓰는 색 계열(성공·경고·위험·보라·주 색)도 4.5 이상임을 확인한다.

**Theme Token(색 — 밝은 테마만)**: 바탕 앱 `#F6F8FC`·사이드바 `#F3F6FB`·카드 `#FFFFFF`·보조 면 `#F8FAFD`·선택 `#EEF5FF`·올림 `#F5F8FE` / 테두리 `#E2E8F0`·진하게 `#CCD6E4`·포커스 `#2F6FED` / 주 색상 `#2F6FED`·`#245ED4`·`#EAF2FF` / 성공 `#22B573`·`#E9F9F1`, 경고 `#E69B2D`·`#FFF4DF`, 위험 `#E05252`·`#FDECEC`, 보라 `#7A5AF8`·`#F0ECFF` / 블로그 A 바탕 `#E5F0FF` 글자 `#1456B8`, 블로그 B 바탕 `#FFF0DD` 글자 `#A95312`(**색만으로 구분하지 않고 `블로그 A`·`블로그 B` 글자를 함께 쓴다**). 명세에 없어서 더한 것: 글자로 쓸 때 대비 4.5 이상이 되게 진하게 만든 변형(`primary_text`·`success_text`·`warning_text`·`danger_text`·`purple_text`)과 말풍선·토스트 바탕(`inverse_bg`)·꺼진 바탕(`disabled_bg`). **첫 버전은 밝은 테마만이고 사용자 화면에 테마 선택이 없다** — 다만 모든 색이 `THEMES` 의 테마 값으로 한 곳에서 관리되므로 어두운 테마는 같은 키를 가진 사전을 하나 더하면 된다(시험: 팔레트 하나를 바꾸면 스타일시트가 따라 바뀜).

**글꼴(Typography Token)**: **특정 글꼴 이름을 코드에 두지 않는다.** 일반 글자는 `QFontDatabase.systemFont(GeneralFont)`(한국어 윈도에서는 시스템이 정한 글꼴 — 이 PC 는 '맑은 고딕'), 로그·경로·진단 정보만 `FixedFont` 고정폭을 쓴다. Family 는 시스템을 따르고 **크기·굵기·행간만 토큰**이 정한다.

| 역할 | 크기/굵기/행간 | 글자 색 |
|---|---|---|
| `display` 큰 제목 | 28/700/1.30 | Strong |
| `h1`·`h2`·`metric` | 22·18·28 / 700 / 1.35·1.40·1.20 | Strong |
| `body_lg` 행 제목 | 15/600/1.60 | Primary |
| `body`·`button` | 14/400/1.60 · 14/600/1.20 | Primary |
| `small`·`caption`·`sub` | 13·12·14 / 400 / 1.50·1.45·1.60 | Secondary |
| `muted` | 14/400/1.60 | Muted |
| `mono` 고정폭 | 13/400/1.50 | Primary |

행간은 줄바꿈하는 글(`Label(wrap=True)`)에 `line-height` 로 적용한다(스타일시트에는 행간이 없다). 글은 HTML 로 해석하지 않고 이스케이프해서 그대로 보인다.

**간격·모서리·그림자·움직임**: 모서리 단추·입력 10·카드 14·칩 999 · 안내(토스트) 3.5초 · 움직임은 **서랍 여닫기 200ms 만 실제로 쓴다**(`MOTION_MS["panel"]`), 과한 효과 없음.
**안 쓰는 값**(토큰에 정해만 두었고 화면 코드는 쓰지 않는다 — 시험이 지킨다): 간격 `SPACE`(4px 격자 4·8·12·16·20·24·32·40·48)·그림자 `SHADOW`(카드 `0 2px 10px` 불투명도 .05·띄운 것 `0 8px 24px` .10, 색은 `Text/Primary` 의 RGB — 순수 검정 아님)·복사 표시 시간 `COPY_FEEDBACK_MS`(1.8초 — 이미지 화면 묶음에서 단추의 '복사됨' 상태에 쓴다)·움직임 `hover` 120ms·`page` 180ms(마우스를 올릴 때·화면이 바뀔 때 효과를 입히지 않는다 — 예전 문서의 '올림 120ms·화면 전환 180ms' 는 값만 있었다).
**알려 둔 한계**: ① 부품·화면의 여백·간격은 토큰 키가 아니라 숫자를 직접 적었고, **4px 격자 값(4·8·12·16·20·24)뿐 아니라 2·6·10·14·18·22px 도 있다**(예전 문서의 '4px 격자 값' 은 사실이 아니었다 — 다음에 `SPACE` 로 정리한다) ② 이 묶음의 카드는 테두리만 쓰고 그림자를 입히지 않았다(명세: 그림자는 카드를 나누는 데에만 최소로).

**크기**: 단추 큰 주 단추 44 · 표준 40 · 작은 단추 보이는 높이 34(**누르는 칸 36**) · 아이콘 단독 단추 36 · 칩 보이는 높이 34(누르는 칸 36) · 메뉴 한 줄 44 · 요약 카드 최소 108 · 추천 행 최소 96 · 썸네일 64(모서리 12) · 입력 40. 누르는 칸은 모두 36 이상이다(시험이 화면의 모든 단추를 잰다). 아이콘 크기는 [`UI_ICONS.md`](UI_ICONS.md).

## 3. 화면 틀 (AppShell)

```text
┌ 위 막대(높이 64: 로고·앱 이름 … 설정 아이콘) ──────────────────────────┐
├ 사이드바 210 ┬ 본문(스크롤, 최대 폭 1280+여백, 가운데) ────────┬ 오른쪽 패널 280 ┤
```

- **사이드바**: 홈·주제 후보·초안 작성·발행 기록·블로그 관리·설정(**6개를 넘기지 않는다** — 시험). 현재 메뉴는 연한 파랑 바탕+파란 글자·아이콘. 아래에 짧은 한 줄과 앱 이름·버전.
- **오른쪽 패널**(내 블로그 현황·빠른 작업·닫을 수 있는 활용 팁): 본문 폭이 1100px 이상일 때만 옆에 두고, 좁으면 본문 아래로 내려가 폭에 맞춰 3·2·1열이 된다.
- **반응형 규칙**(`ui/qt/screens.py`): 요약 카드 4열→2열→1열(한 칸 최소 190), 추천 행은 행 자신의 폭이 800 미만이면 지표 칸(월 검색량·문서 수·추세)을 접는다. **가로 스크롤 막대는 규칙으로 끈다**(스크롤 영역의 가로 막대 정책이 꺼짐 — 시험이 지킨다 — 그리고 배치를 바꿔 맞춘다). 검증한 크기·글꼴(1366×768·1920×1080·100·125·150% 흉내·글꼴 바꾸기·200자 제목·긴 영어 낱말)에서는 넘치지 않았다. **다만 보장은 아니다**: 가로 막대를 끈 대신, 줄을 바꿀 자리가 없이 칸보다 길게 이어지는 글(아주 긴 한 낱말)이나 큰 글자(윈도 '텍스트 크기' 설정은 반영하지 않는다)에서는 글이 잘릴 수 있다. 블로그 이름과 한 줄 설명은 한 줄 줄임표로 줄이고(툴팁은 부품이 받은 글 — 뷰모델이 이미 줄인 글이라 블로그 이름은 어댑터가 가린 뒤 30자까지, 한 줄 설명은 300자까지이고 그보다 긴 원문은 툴팁에도 없다) 제목은 줄을 바꾼다. 서랍·대화상자는 창 폭의 92%·94% 를 넘지 않는다.
- **창 크기**: 기본 1440×900 근처(작은 화면이면 화면의 96%·94% 로 줄임), 최소 900×560. 본문은 스크롤된다.
- 위 막대에는 기능이 없는 장식(전역 검색·알림·사용자 메뉴)을 두지 않는다. 눌러도 되는 척하는 단추를 만들지 않는다 — 아직 없는 기능은 `'…' 은(는) 다음 단계에서 열려요.` 안내(토스트)만 보인다.

## 4. 홈 화면

인사 한 줄 + 날짜 → 요약 카드 4개(추천 주제·작성 완료·발행 완료·저장된 아이디어 — 아이콘 바탕과 숫자에만 색, 눌러서 이동) → **맞춤 주제 추천**(필터 칩 5개 → 추천 행 5개) + 오른쪽(내 블로그 현황·빠른 작업 4개·활용 팁). 행은 왼쪽 64×64 이미지 자리 표시(주제 색 그라디언트+아이콘 — 깨진 그림 아이콘을 쓰지 않는다) · 제목·한 줄 설명·키워드 칩 · 월 검색량·블로그 문서 수·추세(아이콘+글자) · 블로그 배지 · 단추. **선택된 행**은 옅은 파랑 바탕·파란 테두리·큰 `이 주제로 초안 만들기`, 나머지는 작은 `초안 만들기`, 행 끝의 `>` 단추가 주제 상세 서랍을 연다.

**데이터 원칙**: 목업의 숫자·이미지를 실제 데이터처럼 하드코딩하지 않는다. 가짜 데이터는 `FakeHomeProvider` 안에만 있고 화면에 `예시 데이터` 표시(누르면 설명 대화상자)가 붙는다. 실제 어댑터가 가져올 수 없는 값(총 글·이번 달 글·집계 못 한 완료 수)은 보이지 않거나 `–`·`데이터 없음` 이다. 미구현 기능은 안내만 한다.

## 6. 화면 배율 — 지원 제한이 아니라 검증 범위

필수 검증 **1366×768/100%·1920×1080/100%·1920×1080/125%**, 조건부 검증 **1920×1080/150%**(핵심 기능을 쓸 수 있는지만). 앱 코드는 Qt6 의 High DPI 자동 처리를 그대로 쓰고 **배율을 수동으로 곱하거나 고정하지 않는다**(논리 px 만 쓴다 — 시험이 `QT_SCALE_FACTOR`·배율 곱셈·`devicePixelRatio` 계산이 앱 코드에 없음을 확인). 고정 폭·높이를 최소화하고 `QLayout`·`QSizePolicy` 로 배치하며, 작은 창에서는 배치를 바꾸고 본문은 스크롤된다. 아이콘은 SVG 를 그릴 때마다 그려 어느 배율에서도 선명하다. 125%에서 텍스트 잘림·단추 높이·배지·툴팁·대화상자를 확인한다 — 결과와 한계는 [`UI_VISUAL_QA.md`](UI_VISUAL_QA.md).

## 7. 접근성·키보드

Tab 으로 모든 눌리는 곳을 한 바퀴 돌 수 있고(중간에 갇히지 않음), Enter·Space 로 단추·카드·행을 누르며, 포커스 링을 지우지 않는다(채워진 단추는 어두운 링 — 시험이 단추 종류마다 포커스 전후의 모양과 테두리 색을 잰다). 윈도 기본 포커스 사각형이 메뉴 단추의 파란 링 안에 겹치던 것은(진짜 윈도 창에서만 보였다) 스타일시트의 `outline: none` 으로 막았다 — offscreen 에서도 윈도 11 스타일에 진짜 Tab 키 이벤트를 주면 같은 사각형이 그려져 시험한다(고치기 전 검은 점 356 → 0). 서랍·대화상자가 열려 있으면 Tab 은 그 안에서만 돌고, Esc 로 닫으면(대화상자 먼저) 눌렀던 곳으로 포커스가 돌아온다. 아이콘만 있는 단추는 접근 이름과 툴팁이 필수이고 툴팁은 마우스를 올릴 때와 키보드 포커스가 올 때 모두 보인다. 색만으로 상태를 구분하지 않는다(블로그 글자·추세 아이콘). 안내(토스트)는 화면 읽기 프로그램에 알림 이벤트로 알린다. 칩을 키보드로 눌러 화면이 다시 그려져도 포커스가 같은 칩에 남는다. **실제 화면 읽기 프로그램(Narrator 등)·한글 입력기 확인은 운영자 PC 검증으로 남는다.**

## 9. 알려 둔 한계 (독립 검증의 지적 포함 — 고치지 않은 것)

- **명세와 다른 곳**: `body_lg`(행 제목)는 15/600(명세 500)·날짜는 14px `Secondary`(명세 12~13px `Muted`)·설정 아이콘은 슬라이더(톱니바퀴 아님)·초안 아이콘은 문서(연필 없음)·오류 아이콘은 삼각형(원 아님)·안 쓰는 아이콘 13개·추천 행의 지표 칸은 행마다 가로 위치가 달라 열이 안 맞고 제목 줄 수 제한이 없다(명세 2줄).
- **읽기 전용의 결과**: 활용 팁을 닫아도 저장하지 않아 앱을 다시 열면 다시 보인다(`DECISIONS.md` D-32 의 결정 항목).
- **좁은 곳**: 진짜 윈도 창의 기본 크기에서 요약 카드 1번의 `새 후보 N개 포함` 이 두 줄로 꺾일 수 있고, 큰 숫자(1억 이상)에 배지 둘과 큰 단추가 붙은 좁은 행에서는 긴 제목이 잘릴 수 있다. 창 최소 크기(900×560)는 논리 높이가 512 이하인 화면(1366×768 에서 150%)보다 크다.
- **툴팁**: `월 검색량`·`블로그 문서 수` 설명은 마우스를 올릴 때만 뜬다(아이콘 단추의 툴팁은 키보드 포커스에서도 뜬다).
- **명령줄과 같은 것**: 메인 `python -m chanceblog_desktop --help` 목록에는 `gui` 가 없다(`service/cli.py` 는 이 묶음이 건드리지 않는다 — `python -m chanceblog_desktop gui --help` 가 따로 있다). 서비스 오류 문구에는 명령줄용 안내(`--data-dir`·환경 변수 이름·`.git` 잠금 설명)가 섞일 수 있고 200자에서 끊긴다. 닿지 않는 네트워크 경로(UNC)는 27초쯤 기다린 뒤에 안내가 나온다.
- **가리기 규칙의 한계**: 공유 가리기 규칙(`security/mask.py`)이 **알아보지 못하는** 모양은 후보 제목·키워드·이유·서랍·툴팁·블로그 이름에 **그대로 보인다**(화면 쪽에서 막을 방법이 없다 — 규칙이 알아보게 해야 한다): ① AWS 임시 키 `ASIA…`(`AKIA…` 는 가려진다) ② Stripe `sk_live_…`(밑줄) ③ GitLab `glpat-…` ④ 접두어가 없는 16진 문자열(40·64자 등)·긴 영숫자 덩어리·base64 모양 ⑤ 그 밖의 임의 접두어 모양(예: `naver-…` 꼴) ⑥ Slack `xapp-` 앱 토큰(`xoxb-`·`xoxp-` 토큰과 웹훅은 가려진다). 가려지는 것은 규칙이 아는 모양 — 구글 `AIza…`·GitHub `ghp_…`·AWS `AKIA…`·`sk-…`(영숫자만 이어진 긴 모양과, 입력값 비노출 마무리 묶음('c3', 2026-11-04 병합)이 더한 `sk-proj-`·`sk-ant-api03-`·`sk-or-v1-` 같은 붙임표가 든 새 모양 — 이 셋은 그 묶음 전에는 이 목록의 첫 줄이었다)·Slack(웹훅·`xoxb-`·`xoxp-` 토큰 — `xapp-` 앱 토큰은 위 ⑥ 처럼 못 알아봄)·npm·Telegram·JWT·`Bearer …`·`password=…` 같은 대입 등이다(예전 문장 '구글·GitHub·AWS 등은 가려진다' 의 AWS 는 `AKIA…` 한정이었다). 이 목록은 'c3' 가 병합된 뒤(2026-11-04)의 `security/mask.py` 로 직접 확인한 것이다 — 규칙이 위 모양을 알아보게 되면 그 모양을 목록에서 뺀다(시험이 ①~⑥ 이 아직 안 가려진다는 것을 확인한다 — 규칙이 알아보게 되면 시험이 이 목록을 고치라고 알린다). 이 묶음은 `security/` 를 건드리지 않는다.
- **경로 지우기가 알아보는 모양**(한 줄 기록 `unexpected_line`, 'G0c'): 드라이브(`C:\`·`C:/`)·네트워크(`\\서버\공유`·`//서버/…`)·유닉스식(`/home/…`·`경로:/home/…`)·`~/`·`file:///…`(윈도·유닉스 모두, 대소문자 무관)이다. 경로의 시작을 보이지 않는 글자(폭 없는 글자 등)로 쪼갠 것은 줄 가르는 글자를 줄바꿈 하나로 통일하고 보이지 않는 글자를 지운 뒤에 알아본다. **알아보지 못하는** 모양: 상대 경로(`폴더\파일`)·`%USERPROFILE%`·`$HOME`·퍼센트로 인코딩한 경로(`file:///%2Fhome/…`)·다른 사용자의 홈(`~사용자/…`)·따옴표로 연 `file://` 주소(따옴표를 못 알아봄)·호스트가 있는 주소(`file://서버/…`·`https://…` — 주소는 경로가 아니라 그대로 둔다). 따옴표로 연 경로는 짝이 되는 따옴표 앞까지, 아니면 그 줄 끝까지 지워 뒤 설명도 함께 사라질 수 있다(어디서 끝나는지 모를 때는 더 지우는 쪽이 안전하다). 날짜(`11/04`)·`a/b`·닫는 태그·나눗셈은 경로가 아니다.
- **표준 오류가 없는 실행**: 처리하지 못한 예외의 한 줄 기록(`report_unexpected`)은 표준 오류에 쓴다. `pythonw`·창 없는 exe 처럼 표준 오류가 없는 실행에서는 어디에도 남지 않는다(`False` 를 돌려주고 화면에는 쉬운 안내만 보인다) — '조용한 실패도 아니다' 는 **콘솔 실행 기준**이다. 로그 파일은 설치 파일 묶음에서 정한다(이 묶음은 파일을 쓰지 않는다 — 읽기 전용 원칙).
- **취소**: 실제 서비스 어댑터는 단계 사이(후보 읽기 뒤·글 목록 읽기 뒤)에만 취소를 확인한다 — 한 단계가 도는 동안은 끊지 못하고 끝난 결과를 버린다 — 그래도 화면은 취소를 누르는 즉시 보이던 모습으로 돌아간다([`UI_STATES.md`](UI_STATES.md) §2). 창을 닫을 때는 창을 먼저 숨기고 끝나지 않은 작업을 최대 1초 기다린다.
- **성능**: 후보 10만 개에서 `home_view()` 가 0.52초(화면 스레드)다 — 후보가 그렇게 많아지면 목록 화면 묶음에서 나눠 그린다.
- **창을 띄우지 않은 확인**: 실제 윈도 125·150% 렌더·한글 입력기·화면 읽기 프로그램·고대비 모드·개인 PC 는 운영자 PC 검증으로 남는다([`UI_VISUAL_QA.md`](UI_VISUAL_QA.md) §6).
