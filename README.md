# chanceblog-desktop

여러 블로그(GitHub Pages·Blogger·네이버)의 글을 **한 곳에서 쓰고·검수하고·플랫폼별로 내보내는 개인용 Windows 데스크톱 프로그램**입니다. 한국어 화면이 기본이고, **AI 없이도 모든 핵심 기능이 동작합니다**(무료 AI 는 선택 보조이고 기본은 꺼짐).

> **상태: 설계 단계입니다. 아직 설치할 수 있는 버전이 없습니다.** 첫 설치 파일은 `0.1.0` 부터 [Releases](../../releases) 에 올라옵니다.

## 이 저장소와 `chanceblog` 의 관계

| | [`chanceblog`](https://github.com/shine88pc/chanceblog) | 이 저장소(`chanceblog-desktop`) |
|---|---|---|
| 역할 | **GitHub Pages 콘텐츠와 클라우드 자동 발행·감시** — GitHub Actions 가 PC·AI 없이 매일 글을 만들어 올린다(GitHub Pages 자동, Blogger 초안, 네이버 초안 이슈), 감시·텔레그램 알림, 운영자 요청 채널 | **개인 PC 작업대** — 원고를 직접 쓰거나 불러와 검사·미리보기·승인 뒤 플랫폼별로 내보낸다. 설치 파일·버전·업데이트·플랫폼 연동을 GitHub Releases 로 배포한다 |
| 둘의 연결 | 앱이 **기존 `chanceblog` 로컬 저장소를 연결**해 GitHub Pages 용 글·이미지를 만들고 push → **기존 자동 배포 흐름**을 그대로 쓴다 | |
| 규칙의 정본 | `AGENTS.md`·`docs/CHARTER.md`·`docs/SECURITY_GUARDRAILS.md`·`docs/AGENT_RUNBOOK.md` | `AGENTS.md`(이 저장소에만 필요한 것만 적고 나머지는 위를 따른다) |
| 운영자 호출 | 텔레그램 알림(요청 파일 `인수인계/요청함/R-nnn_*.md` 를 `ai/claude/**` 브랜치로 push) | **이 저장소에는 알림 워크플로·시크릿이 없다.** 운영자에게 알릴 일은 `chanceblog` 로 보낸다 |

글을 만드는 **핵심 코드(검사 규칙·프로필·Blogger 어댑터 등)는 `chanceblog` 의 것을 정해진 버전으로 가져다 쓴다**([`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §4). 프로그램 코드의 수정·유지보수는 운영자가 필요할 때 Claude Code 나 다른 AI 코딩 에이전트를 직접 실행하는 방식이며, 무료 AI 로 세션형 개발을 대신하지 않습니다.

## 명령줄로 써 보기

설치 파일은 아직 없고 화면은 일부뿐입니다(아래 '화면(GUI) 열어 보기'). **명령줄**로 글을 만들고 검토해 GitHub Pages(연결한 `chanceblog`)에 올릴 수 있습니다(Python 3.10 이상과 Git 이 필요하고, AI 는 쓰지 않습니다). 저장소 폴더에서 처음 한 번 `set PYTHONPATH=src`(PowerShell 은 `$env:PYTHONPATH = "src"`)를 실행한 뒤 아래 명령을 씁니다. 글번호는 앞 4자만 써도 되고, 모든 명령에 `--json`(프로그램이 읽는 출력)을 붙일 수 있으며, 종료 코드는 0(정상)·1(처리된 오류 — 오류 코드와 하실 일을 보여 줍니다)·2(사용법 오류)입니다.

```text
python -m chanceblog_desktop doctor                          # 상태 점검(읽기만 합니다)
python -m chanceblog_desktop connect C:\work\chanceblog      # 올릴 chanceblog 폴더를 연결(한 번)
python -m chanceblog_desktop new --title "제목" --file 원고.md  # 글 만들기(기존 HTML 글은 import-html)
python -m chanceblog_desktop list                            # 글 목록과 상태
python -m chanceblog_desktop review 글번호 --platform pages --category 경제·일 --lang ko --image-url https://… --tags 태그1,태그2
python -m chanceblog_desktop approve 글번호 --platform pages   # 미리 보기를 읽고 직접 승인(검사를 다시 통과해야 합니다)
python -m chanceblog_desktop publish-pages 글번호              # 먼저 미리 보기 — 아직 아무것도 하지 않습니다
python -m chanceblog_desktop publish-pages 글번호 --yes        # 정말로 기록(commit)하고 올립니다(push)
python -m chanceblog_desktop check-deploy 글번호               # 공개 주소가 열리는지 확인(열리면 '공개됨')
```

- **이 시험 버전은 외부 게시가 완전히 꺼져 있습니다.** `publish-pages`·`check-deploy`·`doctor --online` 은 아무것도 보내지 않고 `EXTERNAL_WRITE_DISABLED` 로 멈춥니다(PC 에 Git 로그인이 있어도 마찬가지이고 켜는 설정·옵션도 없습니다 — [`docs/SECURITY.md`](docs/SECURITY.md) 'PCSEC1' 절). 글은 이 PC 에서 쓰고 `preview`·`naver-package` 로 검토·복사해 직접 올립니다. `connect` 는 폴더 파일만 읽어 확인합니다.
- **글에 붙여 넣은 키·토큰은 저장하지 않습니다.** 원고 제목·본문·후보·네이버 프로필을 저장하기 전과 `backup` 전에 Google API 키·GitHub 토큰·Bearer 토큰·OAuth 토큰·AWS 액세스 키·개인 키 모양을 검사해, 있으면 위치(칸·줄)와 유형만 알리고 멈춥니다(`SECRET_SHAPE_FOUND`). 앱은 글을 자동으로 지우거나 바꾸지 않고 '무시하고 저장'도 없습니다 — 그 줄을 직접 지운 뒤 다시 실행합니다.

- **확인 없이는 올리지 않습니다.** `publish-pages` 는 `--yes` 가 없으면 무엇을 할지 보여 주기만 하고, 글 지우기(`delete`)도 `--yes` 가 있어야 합니다. 올리다 멈추면 같은 명령을 다시 실행하면 이어서 하고, 올리지 않고 되돌리려면 `publish-pages 글번호 --cancel --yes` 입니다. 다른 창에서 같은 글을 올리는 중이면 `PUBLISH_IN_PROGRESS` 로 멈추고 아무것도 바꾸지 않습니다(작업이 죽어 남은 잠금은 그 프로세스가 끝났으면 바로, 아니면 30분 뒤 넘겨받습니다). **다른 글**이 같은 저장소에 올라가는 중이면 끝나기를 기다렸다가(최대 2분) 이어서 올리고(이 잠금은 저장소의 `.git` 폴더 안에 있어서 `--data-dir` 을 다르게 준 다른 앱도 서로를 압니다 — `.git` 에 잠금 파일을 못 만들면 올리지 않고 멈춥니다), 끝내 안 끝나면 `PUBLISH_REPO_BUSY` 로 아무것도 바꾸지 않고 물러납니다 — 같은 명령을 다시 실행하면 됩니다. 올리지 않은 commit 이 이미 있으면(앱이 올리다 멈춘 글·직접 만든 commit) 새 글을 올리지 않고, 어느 글을 어떻게 하면 되는지(이어서 올리기·나중 글부터 `--cancel --yes`·직접 확인) 한 가지를 알려 줍니다. 올리고 나서 멈춘 글에 `--cancel` 을 쓰면 `PUBLISH_ALREADY_PUSHED` — `--cancel` 없이 같은 명령을 실행하면 마무리합니다. 기록(commit) 직후에 멈춘 경우에도 같은 명령이 이어받고 `--cancel --yes` 가 되돌립니다(`doctor` 가 알려 줍니다). 글에 HTML 태그·`javascript:` 주소·`{% %}`/`{{ }}`·광고 스크립트·눈에 안 보이는 글자가 있으면 검사가 막습니다(글자의 표시 방향을 바꾸는 제어 문자는 한 개만 있어도 막습니다) — 제목·분야·태그·이미지 주소·설명 같은 머리말 값도 같고, 제목은 글을 만들 때(`new`)·고칠 때(`edit`)부터 막습니다. `delete` 는 `--yes` 가 없으면 어느 글인지만 보여 주고, 지울 때는 먼저 백업합니다. 올렸지만 공개 확인이 끝나지 않은 글(`PUSHED`)은 먼저 `check-deploy` 로 마쳐야 지울 수 있습니다(지우면 발행 기록이 함께 지워져 공개 확인을 이어갈 수 없게 됩니다). `restore` 도 `--yes` 가 없으면 어느 백업인지만 보여 주고 아무것도 바꾸지 않으며(`restore --latest --yes`), 바꾸기 직전 상태를 따로 백업해 둡니다.
- 네이버: `naver-profile set naver_a --name 표시명 --url https://blog.naver.com/아이디` 로 블로그 프로필을 정한 뒤 `review 글번호 --platform naver_a` → `naver-package 글번호 --blog naver_a`(복사용 제목·본문·태그·이미지 자리) → 직접 발행 → `naver-done 글번호 --blog naver_a --url 발행한_주소`. 네이버 A·B 글이 많이 비슷하면 `--similarity-approved` 로 직접 승인해야 합니다. 앱은 네이버에 로그인하거나 글을 대신 올리지 않습니다.
- **주제 후보**(쓸 글감): 후보를 직접 적거나 CSV 로 가져오거나 **프로필로 먼저 제안받아** 목록에서 고르고, 고른 후보를 쓰고 있는 글과 잇습니다. 네이버 검색 데이터를 모으는 일(키가 필요합니다)과 초안을 쓰는 일은 아직 없습니다.

```text
python -m chanceblog_desktop candidates add --topic "겨울 보일러 점검 순서" --keyword "보일러 점검" --blog naver_a   # 후보 직접 추가(--blog 는 여러 번 또는 쉼표로)
python -m chanceblog_desktop candidates import-csv 후보.csv --blog naver_a --data-date 2026-11-02            # CSV 가져오기(다시 가져와도 겹치지 않습니다)
python -m chanceblog_desktop candidates list --status 선택됨 --blog naver_a                                  # 목록(읽기만 합니다 — 거르기는 선택)
python -m chanceblog_desktop candidates show 3                                                              # 하나를 자세히(지표·연결한 글)
python -m chanceblog_desktop candidates select 3 --blog naver_a                                             # 그 블로그용으로 고르기(같은 키워드를 최근에 골랐다면 경고만 합니다)
python -m chanceblog_desktop candidates hold 3        # 보류      (reject 3 = 제외, review 3 = 검토 중, restore 3 = 제외한 후보 되살리기)
python -m chanceblog_desktop candidates link 3 글번호 # 후보 3번과 쓰고 있는 글을 잇기(unlink 3 으로 끊기)
python -m chanceblog_desktop candidates delete 1a2b3c4d --yes # 지우기 — 순번이 아니라 list 에 보이는 '번호'(앞 8자)로(되돌릴 수 없으니 다시 볼 후보는 reject — --yes 가 없으면 아무것도 지우지 않습니다)
```

후보가 하나도 없어도 **프로필로 먼저 제안**받을 수 있습니다(`naver-profile set` 으로 주제를 적어 두면 됩니다 — 쉼표로 나눠 적으면 더 정확합니다).

```text
python -m chanceblog_desktop naver-profile set naver_a --name 블로그에이 --url https://blog.naver.com/아이디 --topic "생활 절약, 난방, 가계부" --tags 절약,보험   # 제안의 씨앗(주제·카테고리 매핑·기본 태그)
python -m chanceblog_desktop candidates suggest                                      # 후보 10개를 먼저 제안(읽기만 합니다 — 보관함을 만들거나 바꾸지 않습니다)
python -m chanceblog_desktop candidates suggest --blog naver_a --count 20 --month 12 --type 비교형   # 블로그·개수(1~50)·달(1~12)·글 유형을 정해서
python -m chanceblog_desktop candidates suggest --blog naver_a --add 1,3             # 번호 1·3 을 넣을 목록만 보입니다(아직 아무것도 넣지 않습니다)
python -m chanceblog_desktop candidates suggest --blog naver_a --add 1,3 --yes       # 새 후보로 보관함에 넣습니다(같은 명령을 되풀이해도 겹치지 않습니다)
python -m chanceblog_desktop candidates list --priority                              # 보관함 후보에 콘텐츠 작성 우선도·적합도를 덧붙여 보입니다(저장된 값은 바뀌지 않습니다)
```

- **프로필 제안**(`candidates suggest`): 블로그 프로필의 주제·카테고리 이름·기본 태그를 씨앗으로(대상 독자는 '대상 독자 + 씨앗' 보조 키워드로) 글 유형별 제목 틀(정보형·비교형·문제 해결형·제품·서비스 소개형·장소·업체 정보형 — 직접 겪은 일을 전제하는 틀은 없습니다)과 이번 달에 해마다 흔히 찾는 일반 주제(김장·장마·연말정산 …)를 조합해 후보를 만들고, 제외 주제·금지 표현·이미 쓴 글(보관함의 원고 제목과 고른 후보의 주제)과 비슷한 것을 걸러 냅니다. 최근에(그 블로그 프로필의 같은 주제 재사용 기준 일수 안에) 고른 같은 키워드와 보관함에 이미 있는 후보는 목록에서 숨깁니다. 제안마다 **콘텐츠 작성 우선도**(0~100점, 70점 이상 높음·40점 이상 보통·그 아래 낮음)·**블로그 프로필 적합도**·추천 이유(어느 요인이 몇 점, 비중 몇 %)가 붙고 같은 입력이면 같은 순서입니다(네트워크·AI 를 쓰지 않습니다). 같은 씨앗·같은 틀·같은 글 유형이 위쪽을 독점하지 않고 비슷한 키워드는 함께 오르지 않습니다. 프로필에 비밀 모양의 글이나 겪은 일·결과 보장을 뜻하는 낱말(후기·내돈내산·써본·무조건·최저가·월 천만원 …)이 든 씨앗은 쓰지 않고, 몇 개를 버렸는지 화면에 알립니다(직접 겪지 않은 일을 제안 제목으로 지어내지 않기 위해서입니다). **이 거르기는 한국어 낱말 규칙이라 놓치기도 하고 정상 주제를 잘못 걸러 내기도 합니다**(독립 검증이 새 예문으로 잰 값은 `docs/DECISIONS.md` D-29 ⑫ 에 있습니다) — 제안은 고르는 후보일 뿐이니 제목이 어색하거나 겪지 않은 일을 전제하면 `--add` 하지 않고 넘기세요. 프로필에 주제가 없으면 오류가 아니라 '주제를 적어 달라' 는 안내와 함께 빈 목록이 나옵니다. 프로필(주제)을 저장하는 곳은 네이버 A·B 뿐이라 다른 블로그는 제안하지 않습니다.
- **외부 지표는 '데이터 없음'**: 월간 검색 수요·관련 블로그 검색 결과 수·최근 관심도 변화·모바일 비중 같은 외부 지표는 아직 모으지 않으므로 비어 있고 **점수에 넣지 않습니다** — 없는 것을 0점으로 치지 않고 나머지 요인(프로필 적합도 30·시기 20·신선도 20·주제 균형 15)의 비중을 다시 나눕니다. CSV 로 가져온 같은 키워드의 지표가 있으면 키워드 기회도(수요는 많을수록·검색 결과 수는 적을수록·관심도는 상승일수록 높음, 비중 15)로 반영하고 조회일과 며칠 지났는지를 보이며 30일을 넘으면 '오래된 데이터' 라고 알립니다. 점수는 작성 순서를 정하는 참고값이고 검색 결과나 방문자 수를 약속하지 않으며, 계절표와 글 틀은 일반적인 시기 주제와 틀일 뿐 검색 수요를 보증하지 않습니다.
- **`--add` 로 넣기**: `--yes` 가 없으면 넣을 목록만 보이고 아무것도 넣지 않습니다. `--yes` 로 넣은 제안은 '새 후보'(추천 이유 앞에 '프로필 제안 —' 출처 표시)가 됩니다. 번호는 같은 입력이면 같은 번호이고 넣은 제안·최근에 고른 제안은 목록에서 숨겨지되 **번호가 그대로**라서, 같은 `--add 1,2 --yes` 를 되풀이해도 다른 제안이 들어가지 않습니다(넣는 순간에도 같은 키워드·같은 블로그의 후보가 이미 있으면 건너뜁니다). `all` 은 처음 보이던 번호 1~개수 전부이고, 첫 쪽을 넣고 나면 화면에 다음 쪽(예: 11번부터)이 보이므로 그 번호 범위(`--add 11-20`)로 넣습니다 — 화면의 '넣으려면' 안내가 이 화면의 범위를 적어 줍니다. 번호는 `--count`·`--month`·`--type` 에도 따라 달라지므로 화면의 '넣으려면' 안내 명령은 그 값들도 그대로 적어 줍니다. 그 사이 보관함이 바뀌어 번호가 달라질 수 있으면 번호 대신 키워드를 따옴표로 묶어 적습니다(`--add "난방 점검"` — 보여 준 개수 밖의 제안에서도 찾습니다). `--add` 를 여러 번 적으면 이어 붙입니다(`--add 1 --add 3,5` 는 `--add 1,3,5` 와 같고 `all` 은 다른 값과 함께 쓸 수 없습니다). 없는 번호·키워드가 하나라도 있으면 `SUGGESTION_NOT_FOUND` 로 아무것도 넣지 않습니다(프로필을 저장하지 않는 블로그면 그 이유도 적어 줍니다).
- `candidates list --priority` 는 보관함 후보에 같은 계산(우선도·적합도·요인별 점수로 보는 이유·조회일)을 덧붙여 보이고 `show` 는 '왜 이 우선도인지' 를 보입니다 — 둘 다 읽기만 하며 저장된 값은 바뀌지 않습니다(사람이 적거나 CSV 로 가져온 우선도·적합도·기회도 값은 '이전에 적어 둔 값' 으로 따로 표시되고 계산에는 쓰이지 않습니다). 알려 둔 한계: 기존 글은 보관함의 원고 제목과 고른 후보의 주제만 읽습니다(연결한 chanceblog 저장소의 글 제목은 아직 읽지 않습니다).
- 후보는 `list` 에 보이는 **순번**(만든 시각 순, 1~999)이나 **번호**(앞 4자 이상 — `list` 의 '번호 1a2b3c4d' 는 앞 8자입니다)로 고르고, 앞부분이 여러 후보와 겹치면 어느 후보들인지 알려 줍니다. 순번은 후보를 지우면 뒤가 하나씩 당겨지므로 **지울 때는 번호 앞 8자만** 받습니다 — 순번이나 짧은 앞부분과 `--yes` 를 주면 아무것도 지우지 않고 지울 명령(`candidates delete 번호 --yes`)을 후보 제목과 함께 알려 줍니다(같은 명령을 되풀이해도 다른 후보가 지워지지 않습니다). 1000번 이상은 순번으로 고를 수 없어 번호로 고릅니다. 시각과 '며칠 전' 은 한국 시간으로 보입니다(저장은 UTC). 번호 전체와 영문 상태 코드는 `--json`·`--verbose` 에서만 보입니다. `list`·`show` 는 보관함을 만들거나 바꾸지 않고, 보관함이 없거나 옛 구조면 '아직 후보가 없습니다' 로 알립니다(쓰는 명령을 처음 실행하면 보관함이 올라갑니다). 앱이 쓰다 꺼져 끝내지 못한 저장이 남았으면 읽기만 하는 명령은 멈추고, `list`(글 목록)나 `candidates add …` 를 한 번 실행하면 정리됩니다.
- CSV 는 UTF-8(BOM 있어도)이나 엑셀의 cp949 파일(5MB·2000줄 이하, '다른 이름으로 저장 → CSV UTF-8' 도 됩니다)이고 **첫 줄에 열 이름**이 있어야 합니다 — `주제`·`핵심 키워드`·`대상 블로그`(없으면 `--blog`)와 선택 열(`보조 키워드`·`글 유형`·`월간 검색 수요`·`관련 블로그 검색 결과 수`·`최근 관심도 변화`·`모바일 비중`·`계절성`·`기존 글 중복 여부`·`블로그 프로필 적합도`·`콘텐츠 작성 우선도`·`키워드 기회도`·`추천 이유`·`데이터 조회일`, 영어 이름도 됩니다). 모르는 열은 무시하고 알려 줍니다. **지표가 하나라도 있는 줄에는 조회일이 필요**하고(열이 없으면 `--data-date`, 오늘보다 하루 뒤까지만 받습니다), 잘못된 줄은 줄 번호와 이유를 보이고 그 줄만 거절하며 나머지는 저장합니다. 마지막 줄의 `N개 추가·M개 건너뜀·K개 거절` 이 결과이고, 거절한 줄이 있으면 종료 코드가 1 입니다(이미 들어간 줄은 다시 가져와도 건너뜁니다). 가져오기는 한꺼번에 저장하므로 같은 파일을 두 곳에서 동시에 가져와도 겹치지 않고, 도중에 멈추면 아무것도 저장되지 않으니 같은 명령을 다시 실행합니다. 폴더나 `CON` 같은 장치 이름은 읽지 않습니다.
- **연결 설정(키)·한도 안전장치**: NAVER API HUB·이미지(Unsplash)·AI 보조 같은 서비스의 키를 용도별로 넣어 두는 곳입니다. 키는 **Windows 자격 증명 관리자에만** 저장하고 파일·화면·기록에는 남기지 않으며(보이는 것은 상태와 이름뿐), 키가 없어도 모든 핵심 기능은 그대로 됩니다. 아직 어느 서비스도 실제로 부르지 않습니다(키를 저장해 두고 사용량·한도 틀만 갖췄습니다).

```text
python -m chanceblog_desktop keys purposes                                        # 용도 목록과 받는 칸·한도(읽기만 합니다)
python -m chanceblog_desktop keys add image_provider --name 기본 --project 데스크톱    # 키를 칸마다 숨김 입력으로 묻습니다(화면에 보이지 않고, 명령 인자로는 받지 않습니다)
python -m chanceblog_desktop keys list                                            # 용도별 상태와 항목(제공자·번호·등록 여부·마지막 연결 시험·등록 시각 — 키 원문도 끝 4자 같은 일부도 없습니다)
python -m chanceblog_desktop keys usage                                           # 사용량·한도·절약 모드·다음 초기화 시각(읽기만 합니다)
python -m chanceblog_desktop keys usage naver_apihub                              # 이 용도만 — NAVER API HUB 는 오늘·이번 달 시도/성공·마지막 성공·오류·호출 중지 사유도 보입니다(읽기만 합니다)
python -m chanceblog_desktop keys add image_provider --name 예비 --project 다른앱 --i-understand-terms --state 예비   # 같은 용도의 둘째 키는 약관 확인 표시가 필요합니다
python -m chanceblog_desktop keys policy image_provider --on-limit save           # 한도에 걸려도 다른 키로 넘어가지 않고 절약 모드만(기본은 허용된 다음 키로 전환)
python -m chanceblog_desktop keys remove 1a2b3c4d --yes                           # 지우기 — 순번이 아니라 list 의 '번호'(앞 8자)로, 보관소의 키도 함께 지워집니다
```

- **Blogger 로그인 정보(OAuth)는 이 시험 버전이 받지 않습니다**(`keys add blogger` 도 거절하고 화면에는 입력 칸이 없습니다 — Blogger 초안 기능을 만들 때 따로 검증한 뒤 엽니다).
- 키를 **새로 더할 수 있는 수**는 서비스마다 다릅니다(NAVER API HUB·Unsplash·Pexels·Pixabay·네이버 검색광고는 **1개**, Blogger 는 **2개**, AI 보조(Gemini)는 **3개** — 이미 더 많이 들어 있는 옛 파일은 그대로 읽히고 지울 수만 있습니다). 같은 앱·프로젝트의 키는 한도를 함께 씁니다. 한도에 걸리면 먼저 저장해 둔 값을 쓰고 호출을 줄이며(절약 모드), 허용된 다음 키로 넘어가는 것은 429·기간 한도·일시 서버 오류·시간 초과일 때만입니다(인증 오류 같은 것은 숨기지 않고 조치 안내만 합니다). **Unsplash 와 NAVER API HUB 는 어떤 오류에도 다른 키로 자동 전환하지 않습니다.** 자세한 규칙은 [`docs/SECURITY.md`](docs/SECURITY.md) §7, 용도 표는 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §5 `service/` 에 있습니다.
- **NAVER API HUB 검색어 트렌드**(`naver_apihub`)는 안전 장치(틀)만 있고 아직 부르지 않습니다(`keys test` 는 '준비 중' 이라고만 합니다). 키(Client ID·Client Secret)는 하나만 받고 어떤 오류에도 다른 키로 넘어가지 않으며, 프로그램 안 기준은 하루 100회·이번 달 27,000회(한국 시간 달력 월)입니다. 서비스 콘솔의 월 한도 30,000회를 기준으로 70% 를 넘으면 안내하고, 80% 를 넘으면 자동 새로고침을 멈추고(직접 시작한 분석만 한 번에 5회까지), 90% 를 넘으면 새 조회를 모두 멈춥니다. 하루 100회 안에서는 우선순위별로 남겨 두는 몫이 없습니다(구현 쪽 기본값 — 결정 거리는 `docs/DECISIONS.md` D-35 에 적었습니다). 사용량·시계·인증 상태를 확인할 수 없으면 새 조회를 하지 않고 'NAVER API HUB의 새로운 데이터 조회를 사용할 수 없습니다. 저장된 정보와 기본 주제 선정 규칙으로 후보 생성을 계속합니다.' 라고만 알립니다. `keys usage naver_apihub` 로 오늘·이번 달 시도/성공, 마지막 성공·오류, 멈춘 사유를 봅니다. 예전 버전이 만든 옛 항목(`naver_openapi`)이 남아 있으면 `keys list` 에 '옛 항목' 으로 보이고 새 항목은 받지 않습니다 — 새 키는 `naver_apihub` 에 넣고 옛 항목은 `keys remove` 로 지웁니다(키를 자동으로 지우지는 않습니다). 규칙은 결정 `docs/DECISIONS.md` D-35 에 있습니다.
- 키를 넣을 때는 터미널의 숨김 입력을 쓰세요. `--stdin`(JSON 한 줄)은 자동 시험용이고, 키를 명령줄에 직접 쳐서 넘기면 그 줄이 셸 기록에 남습니다.
- 네이버 프로필에는 글을 만들 때 쓰는 선택 항목이 있습니다 — `naver-profile set naver_a --intro-style … --subheading-min 3 --subheading-max 5 --difficulty … --ending-style … --excluded-topics 주식,코인 --topic-reuse-days 90 --post-type 정보형`(모두 기본값이 있어 비워 둬도 됩니다). 소제목 수가 범위를 벗어나거나 제외 주제가 제목·본문에 있으면 미리 보기와 복사용 글의 `[주의]` 에 경고만 나오고 막지 않으며, 같은 주제 재사용 기준은 후보를 고를 때 씁니다. 도입부 스타일·설명 난이도·마무리 방식·기본 글 유형은 아래 작성 기반(`draft plan`)이 읽습니다.
- **작성 기반**(글을 쓰기 전의 뼈대): 후보를 고르면 제목 후보 3개·권장 목차와 소제목·포함할 핵심 내용·주의사항·태그·확인 권장을 규칙으로 만들어 보여 줍니다(AI·네트워크 없이, **읽기만 하고 아무것도 저장하지 않습니다**). 초안 문장은 아직 만들지 않습니다.

```text
python -m chanceblog_desktop draft plan 3 --blog naver_a                  # 후보 3번의 네이버 A 용 작성 기반(선택 입력은 하나도 필요 없습니다)
python -m chanceblog_desktop draft plan 3 --blog naver_b --verbose        # 네이버 B 용 — 값이 어느 층에서 왔는지도 보입니다
python -m chanceblog_desktop draft plan 3 --blog naver_a --experience "지난달부터 써 왔고 만족합니다" --exclude 광고,가격 --length 2500+ --title-direction 질문형 --url https://example.com/guide --conclusion "필요한 것만 고르세요"
```

- **규칙 기반 초안 본문**(`draft body` — 네이버에 복사해 직접 고쳐 쓸 수 있는 정보형 초안을 **AI 없이** 만듭니다): 후보와 네이버 블로그(A·B)로 제목 후보 3개·선택 제목·도입부·소제목 4~6개와 문단·주의사항·마무리·핵심 키워드·보조 키워드·태그·추천 카테고리·한 줄 요약·확인 권장을 만들고 제목 + 본문을 복사하기 쉬운 평문으로 보여 줍니다(**읽기만 하고 아무것도 저장하지 않습니다**). 선택 입력은 위 작성 기반과 같은 11칸이고 입력한 경험·의견·가격·날짜는 그대로 먼저 쓰입니다. **입력하지 않은 개인 경험·후기·협찬·가격·사용 기간·수치·효능은 지어내지 않습니다** — 본문은 '무엇을 확인하고 어떻게 고를지' 만 말하는 일반적인 글이라 제품·장소의 실제 사양·가격·운영 정보는 공식 자료에서 확인해 직접 보태야 하며(확인 권장에 적힙니다) 글맛은 직접 고쳐 쓰는 것을 전제로 합니다. 분야는 후보의 낱말에서 확실히 읽을 때만 읽고(못 읽으면 일반 틀) 안전 판정에서 ‘자동 초안 중지’ 인 후보는 초안을 만들지 않으며(후보 보기에서 이유를 확인합니다), 단정·최상급·효과를 말하는 낱말이 후보에 있으면 확인 권장 맨 위에서 알립니다.

```text
python -m chanceblog_desktop draft body 3 --blog naver_a                  # 후보 3번의 네이버 A 용 초안 본문(선택 입력은 하나도 필요 없습니다)
python -m chanceblog_desktop draft body 3 --blog naver_b --json           # 복사용 글은 body.plain_text(제목만·본문만·태그만은 title_text·body_text·tags_text)
python -m chanceblog_desktop draft body 3 --blog naver_a --experience "지난달부터 써 왔고 만족합니다" --must-include "필터는 먼저 확인하세요"   # 입력한 글은 그대로 먼저 들어갑니다
```

- 선택 입력(모두 선택, 틀린 값만 `DRAFT_OPTION_INVALID` 로 알립니다 — 비밀번호·키·토큰처럼 보이는 글(한글에 바로 붙은 키도), 모양 없는 긴 무작위 영숫자(영문자와 숫자가 함께 든 24자 이상 덩어리 — 32·40자 해시·긴 주문번호를 적은 글도 걸리니 앞 몇 글자만 적습니다. 24자 미만의 짧은 키·나눠 적은 키는 알아보지 못하고 `--url` 주소 칸은 이 검사 밖입니다), 그리고 이름이 token·secret·password·passphrase·auth_code·code_verifier·rlkey·share_key·download_key 등을 품거나 sid·ticket·code·reset·magic·invite 와 같고 값이 16자 이상인 주소 인자(퍼센트로 쓴 것도 세 겹까지 풀어서 봅니다 — state·nonce·login_hint·client_id·pat 은 일부러 넣지 않았습니다)는 받지 않고 오류에는 입력한 글을 적지 않습니다. 안전을 먼저 해서 `password: required` 같은 ‘이름: 값’ 꼴의 일반 글도 비밀로 보여 받지 않으니 문장으로 바꿔 써 주세요): `--message`(전하고 싶은 내용)·`--experience`(실제 사용 경험)·`--opinion`·`--must-include`(여러 번)·`--exclude`(쉼표나 여러 번)·`--audience`·`--length`(`1500-2000` 또는 `2500+`)·`--title-direction`·`--url`(https 공개 주소, 여러 번 — **열어 보거나 가져오지 않고 글자 그대로 적습니다**)·`--price-date`·`--conclusion`, 글 유형은 `--type`. 적용 순서는 **사용자 입력 → 블로그 프로필 → 글 유형 틀 → 후보 → 공통 기본값**입니다(글 길이를 기본 1,500~2,000자 대신 `--length 2500+` 로 주면 2,500자 이상).
- '지어내지 않기' 검사(`check/claims.py`)는 한국어 낱말 규칙이라 **놓치거나 잘못 걸 수 있습니다.** 수치는 규칙을 고치는 데 쓰지 않은 새 예문으로 잰 것만 믿으세요. 독립 검증자가 c2 끝(기준선 → 개선)에서 잰 값: 경험을 지어낸 문장 놓침 41% → 14%(섞은 100개)·62% → 30%(자연스러운 블로그체·일기체 c2-fix 가 이 셋을 고쳤고 같은 예문으로 다시 재면 기준선이 막던 위반을 못 막는 것 122 → 0개, 새 오탐 112 → 11개, 진짜 후기 제목 문제 31 → 0개였습니다 — 단 그 예문 안에서만 맞은 값입니다. 독립 델타 검증이 서술 끝말을 바꾼 탐침에서 기준선이 걸던 288문장 중 180개를 다시 놓치는 구멍과 진짜 후기 제목 꼬리 30개 중 21개를 설명 글로 읽는 오독을 찾아, 2차로 끝말을 열거하지 않는 구조 규칙(꾸미는 낱말 뒤 ~ 부탁 앞의 길이·조사)으로 고쳤습니다. 그 뒤 후속(c2b)으로 글쓴이를 가리키는 1인칭('제가·저는·내가·저도·저희는·우리는·우리가')이 꾸미는 낱말 앞 12글자 안에 있고 부탁 꼬리가 '참고하세요·확인해 주세요·써 보세요' 같은 추천이면 서술 절이 짧아도 단정으로 보게 했습니다. 처음 판은 규칙 코드를 읽지 않은 작성자의 새 예문 각 100문장(기준선 → 새)에서 대명사 + 짧은 절 + 부탁 꼬리 걸림 65 → 70·독자 부탁·안내 오탐 6 → 6·대명사가 든 정상 문장 오탐 7 → 7 이었지만, 독립 검증이 이 규칙만 노린 예문으로 새 오탐을 찾았습니다 — 동사 '나는'('향이 나는 제품을 써 본 느낌을 …')·독자에게 경험을 청하는 부탁('…써 본 느낌을 댓글로 알려 주세요')·독자에게 거는 조건 안내('…따라 해 본 뒤 막히면 질문하세요'). 그래서 '나는' 을 빼고 꼬리를 추천류로 좁히고 이어 가는 낱말·'…면' 조건 검사 뒤로 옮겼습니다(c2bf). 이어 재확인(c2bf 2차)이 찾은 두 가지도 고쳤습니다 — 절이 '…을·…를' 로 끝나는 문장('…해 본 뒤 결과를 확인해 주세요')은 꼬리가 받는 목적어가 있는 독자 순서 안내라 걸지 않고(검증자 새 예문의 정상 문장 새 오탐 20 → 3, 걸려야 하는 90 → 90), 추천 낱말은 끊는 자리 뒤 24글자까지만 찾게 해 긴 한 문장에서 제곱 시간이 되는 문제를 막았습니다. 그 결과 검증자의 정상 문장 190개에서 새 오탐은 62 → 0 이지만(이 예문으로 고쳤으니 개발용 값입니다) 걸려야 하는 12,025문장 중 걸림은 기준선 7,288 → 11,086(처음 판 11,646)이고, 처음 판의 맹검 이득(65 → 70)은 최종 코드에서는 사라졌습니다(문장은 읽지 않고 개수만 다시 세면 65 → 65). 계획·다짐 꼬리('…알려 드릴게요')와 '저희 제품' 같은 소유 꼴은 처음부터 일부러 뺐습니다. 그래도 꾸미는 말이 낱말 사전에 없는 경험('묵어 본·걸어 본')과 '…라면·…다면' 가드·'직접' 만 있는 머리말·붙여 쓴 글·추천이 아닌 꼬리·'…면' 으로 끝나는 낱말('보면·화면')이 든 단정·절이 '…을·…를' 로 끝나는 짧은 단정은 여전히 놓치고(맹검에서 놓친 30문장 중 23개가 사전 밖), 독자에게 순서를 안내하는 문장에 '써 보세요' 꼬리가 붙으면 새로 걸릴 수 있습니다(독립 검증자의 새 예문 순서 안내 40개 중 2개, D-33 ⑬ ㉲). 고치기 전에 쓴 새 서술 끝 28종(336문장)은 기준선 336 → 수정 전 48 → 수정 후 336 걸림, 구조 규칙을 정한 뒤 처음 쓴 새 끝 42종(636문장)은 기준선이 걸던 것을 못 거는 수가 46개(7.4%)로 남았습니다(서술 절이 3글자 이하이거나 조사 붙은 머리말 뒤 7글자 이하면 부탁과 길이로 못 가립니다). 진짜 후기 제목 꼬리 24개 중 못 읽는 것은 19 → 0, 대가로 후기를 설명하는 정보 글을 후기로 오인하는 비율이 26% → 28% 입니다(D-33 ⑫). 규칙 코드를 읽지 않은 작성자가 쓴 새 예문 약 1,000개 기준(기준선 → 수정 전 → 수정 후): 경험 단정 놓침 44% → 26% → 25%, 평범한 문장 오탐 0 → 0 → 0, 해요체 정보 글·3인칭 기사·안내문·부정 문장 오탐 3% → 18% → 6%, 후기형 제목 문제 9% → 24% → 3%, 후기를 설명하는 정보 글을 후기로 오인 67% → 14% → 26%(이 예문은 처음 잰 뒤 실패한 모양을 보고 규칙을 고쳤으므로 완전히 독립이 아닙니다). 구현자 자신의 개발용 예문에서는 놓침·오탐이 0% 이지만 규칙을 그 예문에 맞춘 것이라 증거가 아닙니다(독립 예문 14~30% 와의 격차가 맞춘 정도). 목표(놓침 10% 이하·오탐 3% 이하)에는 못 미쳤습니다 — 현재형·진행형 단정 + 부탁 꼬리 중 기준선도 못 잡던 모양, 신호가 없는 '후기를 설명하는 글'(장소·제품 안내 글로 잘못 바뀝니다), '정말 많은 사람들이 …했어요'·'붐볐'·'…많지 않았다' 같은 남은 오탐(11개), 그리고 기사·정보 글에도 흔한 때·정도 낱말만 든 해요체 문장은 이제 겪은 일로 읽지 않는 부작용이 남았고 독립 검증자가 다시 잽니다. **이 검사는 발행을 막는 방벽이 아니라 '확인해 보세요' 라고 권하는 안내입니다** — `draft plan` 의 문장 거름·경고와 후보 제안의 위험 표시에만 쓰이고 승인·발행을 막지 않으므로, 이후 묶음이 이것을 발행 관문으로 쓰려면 아래 구멍을 먼저 닫아야 합니다. 마지막 독립 검증(3차 델타)이 새 예문으로 잰 값은 위반 놓침 기준선 43 → 2차 23(100문장 중)·정상 문장 오탐 기준선 17 → 2차 14(104문장 중)였고, 구조 규칙이 닫지 못한 곳이 남았습니다 — 서술 절이 짧거나(조사 없는 머리말 뒤 3글자·조사 낀 머리말 뒤 7글자 이하), 절 안에 '화면·반면·더라도·는지' 같은 낱말이 있거나, 낱말이 '서·다가·자마자' 로 끝나면 부탁 꼬리와 구분하지 못하고, 조사 목록 밖의 조사('랑·으로·하고·까지·부터·에게' 등)를 단 독자 부탁은 다시 걸립니다. 또 단정이 꾸미는 낱말 앞에 있는 문장과 글쓴이가 말을 잇는 '…면' 목록 밖의 낱말('비교하면·총평하면' 등)도 놓치고, 후기 낱말이 제목 맨 앞에 맨몸으로 오는 진짜 후기('후기 광안리 횟집 다시 갈 만할까')는 12개 중 9개를 후기로 읽지 못하며, '방문해 본 후 만족도를 별점으로 남겨 주세요' 같은 독자 부탁은 새로 걸립니다. 자세한 한계는 [`docs/DECISIONS.md`](docs/DECISIONS.md) D-26 ⑤·D-33 ⑫·⑬.
- 후기·방문·체험처럼 경험을 전제한 후보를 **경험 입력 없이** 만들면 경험담을 지어내지 않고 정보형 안내 글(방문 후기→위치·이용 정보와 방문 전 확인사항, 제품 체험 후기는 ‘공개된 제품 정보와 구매 전 확인사항’ 안내 글로, 직접 사용 후기→기능과 선택 기준 정리)로 바꾸고 그 사실을 '확인 권장' 에 적습니다. 경험을 입력하면 목차에 경험 단락이 더해집니다. '지어내지 않기' 검사(`check/claims.py`)는 한국어 낱말 규칙이라 놓치거나 잘못 걸 수 있습니다 — 낱말이 없는 체감 표현('배터리가 오래 갔습니다'), 한자를 섞거나 글자 사이에 숫자·자음을 끼운 문장, 영어('I tried' 같은 1인칭 기본 꼴만 잡습니다), '좋았던 점은 소음이 적다는 것입니다' 처럼 꾸밈꼴로 쓴 경험은 못 잡을 수 있고, 반대로 '써 보니 어떠셨나요?'·'알려 주시겠어요?' 같은 높임 질문이나 따옴표로 가리키기만 하는 말은 일부러 통과시킵니다(예문 목록이 시험으로 고정). 다만 끝에 물음표만 붙이거나 꼬리 질문을 단 서술('편했어요?'·'만족했습니다 아닌가요?')과 높임 없는 구어 질문('써 봤어요?')은 겪은 일을 말하는 것과 같은 모양이라 걸립니다('써 보셨나요?' 로 바꿔 쓰세요). 후보가 네이버 A·B 둘 다를 대상으로 하면 두 블로그용 계획이 서로 너무 비슷한지도 알려 줍니다(제목·소제목·도입 방향·태그가 블로그마다 다르게 만들어집니다).

python -m chanceblog_desktop topics hold cleanup               # 90일 뒤에도 변화가 없는 보류 후보의 상세 정리 미리 보기(미리 보기가 확인 번호를 보여 주고 `--yes --confirm 확인번호` 를 붙여야 정리하며 이력 13칸만 남깁니다 — 자동으로는 절대 정리하지 않습니다)

- 글·설정·백업은 PC 의 사용자 데이터 폴더(Windows: `%LOCALAPPDATA%\ChanceblogDesktop`)에만 두고 저장소 안에는 두지 않습니다(`--data-dir` 로 바꿀 수 있지만 저장소 폴더 안은 거절합니다). `backup`·`restore` 로 백업과 복구를 합니다(`restore` 는 지금 글 저장소를 그 백업의 내용으로 통째로 바꾸므로 `--yes` 가 있어야 합니다 — `restore --latest` 만 쓰면 `CONFIRMATION_REQUIRED` 와 함께 어느 백업인지 알려 주니 맞으면 같은 명령 끝에 `--yes` 를 붙입니다). 키·토큰은 읽지도 보이지도 않고, 화면에 나가는 모든 글은 비밀 모양(`sk-proj-…`·`sk-ant-api03-…`·`sk-or-v1-…` 포함)을 가립니다(영문·숫자에 바로 붙은 `abcAKIA…` 와 밑줄·하이픈 앞의 JWT 는 알아보지 못합니다 — 기준이 되는 가리기 규칙과 같은 한계입니다). 후보·글 번호 자리나 `restore` 파일 자리에 키를 잘못 쳐도 오류 문구는 친 글이 번호 모양(16진수 8자 이하·앱이 만든 백업 이름)일 때만 되풀이하고 아니면 `(입력한 번호)`·`(입력한 파일)` 로 보입니다.
- 모든 명령과 옵션은 `python -m chanceblog_desktop --help` 와 `명령 --help` 에 한국어로 설명되어 있습니다. 구현 범위와 한계는 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §5 `service/`, 오류 코드는 [`docs/TROUBLESHOOTING.md`](docs/TROUBLESHOOTING.md) 에 있습니다.

## 화면(GUI) 열어 보기 — 첫 기초(홈·상태 화면)

화면은 PySide6 로 만듭니다(선택 설치 — **없어도 위의 명령줄은 그대로 동작합니다**). 화면은 아직 일부뿐입니다: 홈(KPI 카드 넷·Naver A 추천·Naver B 추천·작성 중 초안·최근 발행·연결 상태 한 줄 — 점수 링과 구간 이름이 붙은 추천 줄을 누르면 상세 서랍이 열립니다)과 불러오는 중·빈 화면·오류·일부만·오프라인 상태, 주제 상세 서랍, 그리고 **설정 화면**(연결 관리 — 키를 쓰는 서비스를 데이터 Provider·이미지·AI 보조·발행·연결 네 묶음과 마지막 '정보'(버전·진단 정보)까지 다섯 묶음의 접이식으로 보여 주고, 서비스마다 '준비 중' 인지와 연결 상태·저장된 키의 이름·기간별 사용량(막대 — 읽지 못하면 막대 없이 '확인할 수 없어요')을 읽기만 합니다. 키 값은 끝 4자도 화면에 나오지 않습니다. **키는 이 화면에서 등록·삭제·별칭 바꾸기·사용/예비/끄기·우선순위·연결 시험을 단추를 눌렀을 때만 합니다** — 등록은 입력 → 확인 두 단계이고 입력한 키는 점으로만 보이며 Windows 자격 증명 관리자에만 저장됩니다. 지금은 어느 서비스도 연결 시험 기능이 없어 '준비 중' 으로 꺼져 있습니다). 그리고 **블로그 관리 화면**(내 블로그 다섯 슬롯 — GitHub Pages·Blogger 영문·한글·네이버 A·B — 의 이름·블로그 ID·언어·주제·우선·제외 키워드·글 유형·색 같은 프로필을 화면에서 넣고 고칩니다(우선·제외 키워드와 글 유형은 지금은 저장만 하고 주제 후보 만들기에는 아직 쓰이지 않습니다). **저장·복제·삭제를 누를 때만** 사용자 데이터 폴더의 `topic_engine/channel_profiles.json` 한 파일에 쓰고(낡은 판 거절·직전 사본·실패하면 쓰기 전 상태로 되돌리기), 키·자격 증명은 읽지도 쓰지도 않습니다). 그리고 **Seed 관리 화면**(주제 후보를 만드는 데 쓸 낱말(Seed)의 목록입니다. 제안 파일에서 불러온 Seed 는 모두 '승인 전' 으로 시작하고 **승인하기 전에는 후보 생성에 쓰이지 않습니다**. 항목마다 승인·쉬게 하기·다시 쓰기를 하거나 여러 개를 한꺼번에 바꾸고(확인창이 먼저입니다), 우선 표시·제외·우선 키워드·허용 채널·제안 이유를 고치고, 새 Seed 를 승인 전으로 등록합니다. **승인·바꾸기·저장·등록·불러오기를 누를 때만** 사용자 데이터 폴더의 `topic_engine/seeds.json` 한 파일에 쓰고(낡은 판 거절·직전 사본·실패하면 쓰기 전 상태로 되돌리기), 지우는 기능은 없으며, 키·자격 증명은 읽지도 쓰지도 않습니다). 그리고 **주제 후보 화면**(엔진이 만든 후보를 카드로 비교하고 고릅니다 — 채널·작업 상태로 거르고 제목·키워드로 찾고, 후보를 누르면 점수 링·점수 구성·추천 이유·최근 관심도(상대값)·Seed 출처·안전 표시가 오른쪽 상세 창(좁은 창에서는 서랍)에 열립니다. **열고 거르고 고르는 것은 읽기만 하고**(보관함이 없어도 만들지 않습니다), 머리의 `후보 만들기` 를 눌러 미리 본 뒤 확인창에서 `만들기` 를 골랐을 때만 사용자 데이터 폴더의 `topic_engine/topic_engine.db` 에 후보를 **더합니다**(있던 후보는 지워지거나 바뀌지 않고, 실패하면 쓰기 전 상태 그대로이며, 키·네트워크는 쓰지 않습니다). 후보 상태 바꾸기 단추는 아직 없고, 후보 상세 아래 고정 줄의 `이 주제로 만들기` 가 초안 작성 화면으로 이어집니다). 그리고 **초안 작성 화면**(고른 후보 하나로 **AI 없이** 규칙 기반 초안 — 제목 후보 셋·본문·키워드·태그·카테고리·한 줄 요약·확인 권장 — 을 만들어 보여 줍니다. 제목과 본문을 직접 고치고 `검사하기` 로 훑은 뒤 `제목 복사`·`본문 복사`·`전체 복사` 로 **클립보드에만** 복사하고, `네이버 글쓰기 열기` 는 글쓰기 주소만 엽니다(로그인·입력·발행은 하지 않습니다). **저장하지 않습니다** — 초안은 메모리에만 있고 화면을 떠나면 사라지며(고친 내용이 있으면 먼저 묻습니다) 후보 상태·파일·보관함은 바뀌지 않습니다. 키·토큰처럼 보이는 글과 건강 효과를 단정하는 문장은 복사되지 않고(걸린 부분은 앞부분만 알려 줍니다), 확인이 필요한 글은 복사하기 전에 확인창이 먼저 뜹니다. 새 초안을 만드는 동안에는 제목·본문을 고칠 수 없습니다). 그 밖의 화면(발행 기록)은 메뉴가 아니라 사이드바의 흐린 '다음 단계' 목록에 이름만 보이고 누를 수 없습니다(화면이 만들어지면 메뉴로 올라옵니다). **홈은 읽기만 하고, 설정 화면도 열고 다시 읽는 동안은 읽기만 합니다**(보관함을 만들거나 바꾸지 않고 네트워크·로그인을 쓰지 않습니다 — 키를 넣고 지우는 쓰기는 사용자가 단추를 눌렀을 때만 시작합니다).

```text
python -m pip install PySide6                          # 한 번만(저장소 밖 가상환경에 설치하는 것을 권장합니다)
python -m chanceblog_desktop gui                       # 내 후보를 읽어 화면을 엽니다(명령줄과 같은 사용자 데이터 폴더)
python -m chanceblog_desktop gui --sample              # 내 데이터 대신 '예시 데이터' 로 화면을 둘러봅니다
python -m chanceblog_desktop gui --data-dir C:\work\data   # 다른 데이터 폴더를 읽습니다
```

PySide6 가 없는 PC 에서 `gui` 를 실행하면 설치 방법을 쉬운 한국어로 안내하고 끝납니다(오류 창·긴 영문 오류 없음). `gui` 에 모르는 옵션을 주면 입력한 값은 되풀이하지 않고 `사용법 오류: gui 명령의 인자가 올바르지 않습니다(입력한 값은 보이지 않습니다).` 와 사용법 한 줄만 나오며(종료 코드 2), `--data-dir` 로 정한 폴더가 없거나 파일이면 빈 화면이 아니라 쉬운 안내가 나옵니다. 화면 구조·값·부품 규칙은 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §5.1 과 [`docs/UI_DESIGN_SPEC.md`](docs/UI_DESIGN_SPEC.md), 사진·배율 검수는 [`docs/UI_VISUAL_QA.md`](docs/UI_VISUAL_QA.md) 에 있습니다.

## 개발 방식

사람(운영자)은 비개발자이고, 코드는 AI 도구가 작성하고 다른 주체가 검증합니다. 모든 변경은 브랜치 `ai/<도구>/<주제>` → PR → **운영자 병합** 순서이고, 시험(`python -m unittest discover -s tests`)과 CI 가 통과해야 합니다. 승인이 필요한 일(시크릿·계정·서명 키·새 플랫폼·삭제·정책)은 번호 있는 요청으로 묻습니다. 키는 저장소에 두지 않습니다(`.env.example` 에는 변수 이름만 있습니다).
