# ocr_addon — 글자 읽기 추가 도구(작업자) 소스

사진 속 글자를 **이 PC 안에서만** 읽는 선택 기능의 작업자 프로세스 소스입니다. 앱 본체(`src/`)와 따로 설치하는 추가 도구이고, 앱 본체 묶음(`packaging/`)에는 들어가지 않습니다(이 폴더는 `src/` 밖입니다).

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `protocol.py` | 앱과 작업자가 표준 입출력으로 주고받는 약속. 표준 라이브러리만, 3.10 문법만 씁니다. 앱 쪽 사본(`src/chanceblog_desktop/ui/core/ocr_protocol.py`)과 같은 글자인지 시험이 두 쪽에서 가져와 견줍니다 |
| `netguard.py` | 작업자 안의 소켓 수준 네트워크 시도 가드. 작업자 진입 파일의 첫 줄에서 적재하고, 설치에 실패하면 작업자는 시작하지 않습니다 |
| `worker_main.py` | 작업자 진입 파일. 가드를 먼저 적재한 뒤에야 엔진을 가져옵니다 |
| `stubs/requests.py` | 아무것도 하지 않는 가짜 `requests`(진짜 `requests`·`urllib3`·`certifi` 를 묶음에서 빼려고) |
| `requirements-ocr.lock` | 작업자 가상환경 잠금 21개(해시 포함). 모든 핀은 PyPI 업로드 14일 이상, `numpy` 는 2.5.4 |
| `requirements-build.txt` | 빌드 도구 잠금(해시 포함). 앱 본체의 의존성이 아닙니다 |
| `build_ocr_addon.py` | 동결·점검·압축을 한 번에 하는 빌드 스크립트 |
| `call_worker.py` | 사람이 손으로 작업자를 불러 보는 도구(시험·평가용) |

## 처음 가져왔을 때의 상태(B1 — 지나간 일)

- 이 소스는 a 단계(추가 도구 시제품)에서 가져왔고, 소스만 담았습니다(빌드 산출·가상환경·시험 사진 없음).
- (지나간 일) 처음 가져왔을 때 `build_ocr_addon.py` 는 a 단계 폴더 배치를 전제로 한 경로 상수(`STAGEA`·`PHOTOLAB`·`ASSETS`)를 갖고 있었습니다. d 단계에서 저장소 배치에 맞췄고 이 빌드 스크립트에는 그 상수가 없습니다(아래 '지금 상태(d 단계 — 빌드 흐름)'). `call_worker.py` 는 손으로 불러 보는 도구라 a 단계 폴더 배치를 아직 전제로 합니다.
- 앱은 `LOCAL_OCR = False` 이므로 이 도구가 없거나 있어도 작업자를 띄우지 않습니다.

## 빌드 산출물의 고지(운영자 확인 030 ②)

- `build_ocr_addon.py` 의 `notices` 단계(점검 앞 — 점검이 이 파일들도 보고 정보 파일의 파일 목록에 들어갑니다)가 산출 폴더에 `licenses/`(묶음에 든 부품마다 설치된 패키지에서 읽은 라이선스 전문)와 `THIRD_PARTY_NOTICES.txt`(제3자 부품 표·GEOS(LGPL-2.1) 안내와 바꿔 끼운 뒤 주의·MPL-2.0 고지·뺀 것·모델 2개와 글자 사전의 이름·출처·라이선스 표기 [5] 절 — 값은 `models.lock.json` 과 사전 출처 기록에서 그대로 옮기고 못 옮기면 빌드가 멈춥니다)를 만들고, `OCR_INFO.json` 에 `geos` 칸(판·별도 파일·전문 위치)을 적습니다. GEOS 라이선스 전문(`LICENSE_GEOS`)을 못 찾으면 조용히 건너뛰지 않고 빌드가 실패합니다.
- 원본 소스 압축 파일은 넣지 않습니다(새 내려받기 없음). 같은 버전 소스를 공식 배포처에서 받으라는 안내만 고지문에 적습니다.
- 이 단계의 시험은 빌드 없이 도는 `tests/test_ocr_addon_notices.py`(만들기 함수)와 `tests/test_ocr_addon_merged_flow.py`(점검·정보 파일·압축·산출물 점검까지 한 줄기) 입니다.
- 운영자 확인 필요(열린 질문): LGPL-2.1 이 요구하는 '앱 약관이 디버깅용 리버스 엔지니어링을 막지 않기' 는 앱 약관 문구의 몫입니다. 이 앱에는 자체 약관·라이선스 문구가 없어 이번 범위 밖이고, 추가 도구를 켜기 전에 정해야 합니다(법률 자문이 아닙니다).

## 빌드 점검 관문과 텔레메트리 한계(검증 S 반영)

- `build_ocr_addon.py all` 은 점검(묶음 안 모든 exe·DLL·pyd 의 가져오기 표에서 네트워크 DLL — 허용 예외는 `_internal` 바로 아래의 `_socket.pyd`·`select.pyd`·`python312.dll` 셋뿐 — 금지 파일·모델 해시·동결본 자가 점검)이 하나라도 실패하면 거기서 멈추고 종료 코드 1 로 끝납니다(정보 파일·zip 을 만들지 않습니다).
- 텔레메트리: 작업자는 onnxruntime 의 텔레메트리를 끄는 호출과 환경 변수(`ORT_DISABLE_TELEMETRY=1`·`DO_NOT_TRACK=1`)까지 합니다. 운영체제 이벤트 추적(ETW)이 실제로 꺼졌는지는 증명하지 못합니다 — '텔레메트리 0' 은 이 한계 안에서의 말입니다.

## 시험

- `tests/ocr_worker_probe.py`(시험 전용 실행기 — 앱 묶음·동결 작업자에는 없다)가 이 폴더의 `worker_main.py`·`netguard.py`·`protocol.py` 를 **파이썬 소스 그대로** 띄우고 엔진 만들기·모델 파일 확인 이름만 가짜로 바꿔 끼운다. `tests/test_ocr_worker_guard.py` 가 그것으로 소켓 가드(바깥 시도는 막혀 `net_blocked`·루프백은 통과)·가드 적재 순서·실패하면 시작하지 않음·진짜 `serve` 의 약속 처리를 시험한다. 시험이 만드는 바깥 시도는 패킷이 나갈 수 없는 주소(`0.0.0.1`)뿐이다.
- 이 폴더의 소스를 고치면(특히 `protocol.py`) 앱 쪽 사본 `src/chanceblog_desktop/ui/core/ocr_protocol.py` 도 같은 글자로 고친다 — `tests/test_ocr_protocol_same.py` 가 견준다.

## 약속(요약)

- 요청(앱 -> 작업자): 머리 한 줄(JSON) + 픽셀 바이트. 사진 경로·파일 이름·사진 번호·종류·메모·`Exif` 는 한 글자도 넣지 않습니다.
- 응답(작업자 -> 앱): 한 줄에 JSON 하나. 앱은 모두 데이터로만 다루고, 알려진 칸·형식·한도·요청 번호를 검사합니다.
- 종료 코드: 0 정상, 2 약속 위반, 3 입력이 도중에 닫힘, 4 거절한 요청의 본문이 64MB 초과, 5 네트워크 시도 차단, 6 시작 실패, 70 소켓 가드 적재 실패.

## 지금 상태(d 단계 — 빌드 흐름)

위 '처음 가져왔을 때의 상태(B1)' 의 경로 상수 이야기는 지나간 일입니다. d 단계에서 빌드 쪽을 저장소 배치에 맞췄습니다(결정 D-527 에서 D-533). 만들고 받고 점검하는 방법은 `docs/PACKAGE_OCR.md` 에 있습니다.

| 파일 | 하는 일 |
| --- | --- |
| `build_rules.py` | 빌드 점검 규칙 R1에서 R4(가져오기 표·묶음 파일·부품·자가 점검)와 잠금 파일·모델 잠금 점검을 순수 함수로 둔 것. 표준 라이브러리만 씁니다 |
| `fetch_models.py` | 빌드 전용 모델 받기(커밋 고정·크기·SHA-256 대조). 앱은 이 파일을 가져오지 않습니다 |
| `verify_release.py` | 올리기 전 산출물 점검 — 압축 파일·`SHA256SUMS`·`PACKAGE_INFO.json` 을 파일 자체에서 다시 읽어 해시·크기·파일 목록·모델 잠금 값과 라이선스 고지 파일(`licenses/`·`THIRD_PARTY_NOTICES.txt`)이 압축 파일 안에 있는지 확인하고, FFmpeg DLL·인증서 파일·기본 모델·OpenSSL·진짜 `urllib3`·`certifi` 같은 있으면 안 되는 것과 정보 파일에 적힌 빌드 점검 결과도 압축 파일 쪽에서 다시 확인합니다 |
| `models.lock.json` | 모델 2개의 저장소·커밋·크기·SHA-256 과 사전의 크기·SHA-256 |
| `requirements-ocr.meta.json` | 21개 핀의 PyPI 업로드 날짜(모든 핀 14일 이상 규칙의 근거) |
| `data/` | 글자 사전과 정보 파일(줄바꿈 변환 금지 — `.gitattributes`) |

- `build_ocr_addon.py` 는 `--out-dir` 와 `--models-dir`(받은 모델 폴더)를 받고, 점검에 걸리면 정보 파일·압축 파일을 만들지 않습니다. 시각은 커밋 시각(또는 `SOURCE_DATE_EPOCH`)입니다. 점검을 끄는 옵션은 없습니다.
- 빌드 흐름 파일은 `.github/workflows/package-ocr.yml` 입니다(수동 실행만 — 운영자가 병합해 main 에 있고(M101) 실행도 운영자만 합니다).
