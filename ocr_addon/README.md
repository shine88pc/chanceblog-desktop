# ocr_addon — 글자 읽기 추가 도구(작업자) 소스

사진 속 글자를 **이 PC 안에서만** 읽는 선택 기능의 작업자 프로세스 소스입니다. 앱 본체(`src/`)와 따로 설치하는 추가 도구이고, 앱 본체 묶음(`packaging/`)에는 들어가지 않습니다(이 폴더는 `src/` 밖입니다).

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `protocol.py` | 앱과 작업자가 표준 입출력으로 주고받는 약속. 표준 라이브러리만, 3.10 문법만 씁니다. 앱 쪽 사본(`src/chanceblog_desktop/ui/core/ocr_protocol.py`)과 같은 글자인지 시험이 두 쪽에서 가져와 견줍니다 |
| `netguard.py` | 작업자 안의 소켓 수준 네트워크 시도 가드. 작업자 진입 파일의 첫 줄에서 적재하고, 설치에 실패하면 작업자는 시작하지 않습니다 |
| `worker_main.py` | 작업자 진입 파일. 가드를 먼저 적재한 뒤에야 엔진을 가져옵니다 |
| `stubs/requests.py` | 아무것도 하지 않는 가짜 `requests`(진짜 `requests`·`urllib3`·`certifi` 를 묶음에서 빼려고) |
| `requirements-ocr.lock` | 작업자 가상환경 잠금 21개(해시 포함). 모든 핀은 PyPI 업로드 14일 이상, `numpy` 는 2.5.4 |
| `requirements-build.txt` | 빌드 도구 잠금(해시 포함). 앱 본체의 의존성이 아닙니다 |
| `build_ocr_addon.py` | 동결·점검·압축을 한 번에 하는 빌드 스크립트 |
| `call_worker.py` | 사람이 손으로 작업자를 불러 보는 도구(시험·평가용) |

## 지금 상태(B1)

- 이 소스는 a 단계(추가 도구 시제품)에서 가져왔고, 소스만 담았습니다(빌드 산출·가상환경·시험 사진 없음).
- `build_ocr_addon.py` 는 a 단계 폴더 배치를 전제로 한 경로 상수(`STAGEA`·`PHOTOLAB`·`ASSETS`)가 그대로 있습니다. 저장소 배치에 맞추는 일은 빌드 흐름을 정하는 단계(B3)에서 합니다. B1 에서는 고치지 않았습니다.
- 앱은 `LOCAL_OCR = False` 이므로 이 도구가 없거나 있어도 작업자를 띄우지 않습니다.

## 시험

- `tests/ocr_worker_probe.py`(시험 전용 실행기 — 앱 묶음·동결 작업자에는 없다)가 이 폴더의 `worker_main.py`·`netguard.py`·`protocol.py` 를 **파이썬 소스 그대로** 띄우고 엔진 만들기·모델 파일 확인 이름만 가짜로 바꿔 끼운다. `tests/test_ocr_worker_guard.py` 가 그것으로 소켓 가드(바깥 시도는 막혀 `net_blocked`·루프백은 통과)·가드 적재 순서·실패하면 시작하지 않음·진짜 `serve` 의 약속 처리를 시험한다. 시험이 만드는 바깥 시도는 패킷이 나갈 수 없는 주소(`0.0.0.1`)뿐이다.
- 이 폴더의 소스를 고치면(특히 `protocol.py`) 앱 쪽 사본 `src/chanceblog_desktop/ui/core/ocr_protocol.py` 도 같은 글자로 고친다 — `tests/test_ocr_protocol_same.py` 가 견준다.

## 약속(요약)

- 요청(앱 -> 작업자): 머리 한 줄(JSON) + 픽셀 바이트. 사진 경로·파일 이름·사진 번호·종류·메모·`Exif` 는 한 글자도 넣지 않습니다.
- 응답(작업자 -> 앱): 한 줄에 JSON 하나. 앱은 모두 데이터로만 다루고, 알려진 칸·형식·한도·요청 번호를 검사합니다.
- 종료 코드: 0 정상, 2 약속 위반, 3 입력이 도중에 닫힘, 4 거절한 요청의 본문이 64MB 초과, 5 네트워크 시도 차단, 6 시작 실패, 70 소켓 가드 적재 실패.
